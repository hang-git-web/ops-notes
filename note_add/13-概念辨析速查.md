## 一、并发 vs 并行（★ 面经原题）

### Q1 面试官：并发和并行有什么区别？

> **考察点**：操作系统概念 · 单核能不能"并发"

```text
并发（Concurrency）：同一时间段内"交替"处理多个任务 —— 宏观上像同时，微观上是轮流。
并行（Parallelism）：同一时刻"真正同时"执行多个任务 —— 必须有多个 CPU 核。
```

> **★ 一句话答法**：**「并发是交替执行、看起来同时在处理；并行是真正同时执行，需要多核。并发是『结构』问题，并行是『执行』问题。」**

| | 并发 | 并行 |
| --- | --- | --- |
| 时间维度 | 一段时间内交替 | 同一时刻同时 |
| 需要多核吗 | **不需要**（单核也能并发） | **必须多核 / 多机** |
| 典型例子 | 单核 CPU 上多进程轮流跑；Nginx 事件循环处理海量连接 | 4 核跑 4 个计算线程 |
| 关注点 | 吞吐、响应、任务调度 | 计算速度 |
| 类比 | 一个客服同时接待 10 个客户（来回切换） | 10 个客服各接待 1 个客户 |

> **加分补充**：
> · **「高并发」不等于「高性能」**：Redis 用单线程也能扛十万级 QPS，靠的是 **IO 多路复用**（并发处理连接），不是并行计算。
> · Go 的 goroutine、Python 的 asyncio 都是"用并发模型在少量线程上支撑大量任务"。

## 二、MB 和 Mb（★ 面经原题，单位陷阱）

### Q2 面试官：MB 和 Mb 有什么区别？100M 带宽的下载速度是多少？

> **考察点**：单位换算 · 带宽与吞吐

```text
b = bit（位）      —— 网络带宽用
B = Byte（字节）   —— 文件大小、内存用
1 Byte = 8 bit
```

| 写法 | 含义 | 用在哪 |
| --- | --- | --- |
| **Mb / Mbps** | 兆**位**每秒 | **网络带宽、链路速率**（运营商说"100 兆宽带"） |
| **MB / MB/s** | 兆**字节**每秒 | **文件大小、下载速度、磁盘吞吐** |
| MiB / GiB | 2 的幂（1024 进制），严格说法 | 内存、`free -h` 的真实含义 |

**三个必会换算（面试爱考）**：

```text
1) 100 Mbps 的带宽 = 100 ÷ 8 = 12.5 MB/s   ← 下载速度的上限
2) 1 Gbps = 1000 Mbps = 125 MB/s
3) 100 MB 的文件，在 100 Mbps 链路上理论最快 100 / 12.5 = 8 秒
```

**1000 和 1024 的坑**：

```text
硬盘厂商用 10 进制：1 TB = 1000 GB = 1000^4 字节
操作系统用 2 进制：1 TiB = 1024 GiB
→ 所以买了 1TB 的盘，系统里显示 931 GiB（不是被坑了，是进制不同）
内存条是 2 进制：8 GiB 就显示 8 GiB
网络速率是 10 进制：1 Gbps = 1000 Mbps
```

**顺带记住三个性能单位**：

| 单位 | 含义 | 场景 |
| --- | --- | --- |
| **IOPS** | 每秒 IO 次数 | 数据库小随机读写（SSD 几万到几十万） |
| **吞吐（MB/s）** | 每秒传输字节数 | 大文件顺序读写、带宽 |
| **延迟（ms/us）** | 一次操作耗时 | 磁盘 `await`、网络 RTT |
| PPS | 每秒包数 | 小包场景（防火墙 / 网卡瓶颈） |

## 三、进程 / 线程 / 协程

### Q3 面试官：进程、线程、协程有什么区别？为什么线程切换比进程快？

> **考察点**：调度单位 · 地址空间与开销

| 维度 | 进程 | 线程 | 协程 |
| --- | --- | --- | --- |
| 资源 | **独立地址空间**、独立 fd 表 | 共享进程的地址空间、堆、fd；**独享栈和寄存器** | 用户态调度，栈更小（KB 级） |
| 切换开销 | 大（要切换页表、刷 TLB） | 中（同一地址空间，仍要陷入内核） | **极小（用户态切换，不陷入内核）** |
| 通信 | IPC（管道/共享内存/socket） | 直接读写共享变量（**要加锁**） | 共享变量 / 通道（channel） |
| 崩溃影响 | 只影响自己 | **一个线程崩了整个进程挂** | 同进程 |
| 数量级 | 几百~几千 | 几千~上万 | **几十万**（Go goroutine） |
| 谁调度 | 内核 | 内核 | 运行时 / 语言层 |

> **追问：为什么线程切换比进程快？**
> 因为线程**共享同一个地址空间**，切换时**不用换页表和刷 TLB**，只需保存 / 恢复寄存器和栈。
>
> **追问：线程越多越好吗？**
> **不是。** 线程多了上下文切换开销和锁竞争上升，`sy` 变高、性能反而下降（`vmstat` 的 `cs` 会飙升）。见 `09-Q6`。

## 四、buffer 和 cache

### Q4 面试官：buffer 和 cache 有什么区别？

> **考察点**：`free` 里的 `buff/cache` 到底是什么

| | buffer（缓冲） | cache（缓存） |
| --- | --- | --- |
| 目的 | **解决速度不匹配**：把零散的小写入攒起来 | **提高命中率**：把读过的数据留在内存 |
| 方向 | 偏"写" | 偏"读" |
| 例子 | 写磁盘前先在内存攒一批、管道缓冲、网卡发送缓冲 | 文件内容的 page cache、DNS 缓存、CPU cache |

> `free` 里显示成 `buff/cache`（合并一列），**它们都是可以回收的内存**，所以判断内存够不够要看 `available`（见 `07-Q1`）。

## 五、阻塞/非阻塞、同步/异步、五种 IO 模型

### Q5 面试官：阻塞和非阻塞、同步和异步有什么区别？有哪几种 IO 模型？

> **考察点**：IO 模型 · Nginx/Redis 为什么单线程能高并发

```text
阻塞 / 非阻塞：说的是"调用方要不要一直等"
同步 / 异步：  说的是"结果怎么通知你"（自己拿 vs 别人送上门）
```

| 模型 | 行为 | 现实例子 |
| --- | --- | --- |
| 阻塞 IO | `read()` 一直等到有数据 | 普通文件读写、简单 socket |
| 非阻塞 IO | 没数据立刻返回 `EAGAIN`，需要自己轮询 | 设置 `O_NONBLOCK` |
| **IO 多路复用** | 一个线程用 `select/poll/epoll` 同时盯上千个连接 | **Nginx、Redis、Netty** |
| 信号驱动 IO | 数据到了用信号通知 | 用得少 |
| **异步 IO** | 内核把活干完再通知你 | Linux `io_uring`、AIO |

> **★ 关键一句**：**前四种都算"同步 IO"**（数据拷贝阶段你还是要等），**只有最后一种是真正的异步 IO**。

**零拷贝（sendfile）**：

```text
普通读文件再发网络：磁盘 → 内核缓冲 → 用户缓冲 → socket 缓冲 → 网卡（4 次拷贝、4 次上下文切换）
sendfile：          磁盘 → 内核缓冲 → 网卡（省掉用户态那一趟）
→ Nginx 用 sendfile 传静态文件更快；类似的还有 mmap + write、splice
```

> **面试官爱问**：「Redis / Nginx 为什么单线程 / 少量线程就能高并发？」→ **用 IO 多路复用（epoll）+ 事件驱动，单线程就能同时管理大量连接；高并发靠的是"并发模型"，不是多线程并行计算。**

## 六、用户态与内核态

### Q6 面试官：用户态和内核态是什么？系统调用为什么有开销？

> **考察点**：特权级 · `sy` 的来源

```text
CPU 有两种特权级：用户态（ring3，权限受限）和内核态（ring0，能操作硬件和所有内存）
应用程序想读文件、发网络包、创建进程，必须通过"系统调用（syscall）"陷入内核态。
→ 每次切换都有开销，这就是 top 里 sy 的来源。
```

```bash
strace -c ./程序        # 统计系统调用次数和耗时
strace -p <PID>        # 跟踪运行中的进程
ltrace                  # 跟踪库函数调用
```

> **串起来理解**：`us` 高 = 你写的代码在算；`sy` 高 = 系统调用 / 切换太多；容器通过 **namespace 和 cgroup** 限制的也是这些系统资源（`12-Q5`）。

## 七、七种进程间通信方式（★ 面经①第 11 题）

### Q7 面试官：Linux 有哪几种进程间通信方式？

> **考察点**：IPC 全景 · **原稿写"没了解过"，这题必须补上**
> **七种背这句口诀**：**「管道、命名管道、信号、信号量、共享内存、消息队列、套接字」**

| # | 方式 | 一句话 | 传数据吗 | 能跨主机吗 | 速度 | 典型场景 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | **管道 pipe** | 匿名管道，只能父子/亲缘进程用 | 是 | 否 | 中 | `ps aux 管道符 grep nginx` 里的那根竖线 |
| 2 | **命名管道 FIFO** | 有文件名的管道，无亲缘也能用 | 是 | 否 | 中 | `mkfifo` 做日志收集、shell 里跨进程传数据 |
| 3 | **信号 signal** | 异步通知，**只告诉你有事，不搬数据** | **否** | 否 | 快 | `kill`、Ctrl+C、`nginx -s reload` |
| 4 | **信号量 semaphore** | 计数器，**管同步/互斥，不搬数据** | **否** | 否 | 快 | 多进程抢同一资源、保护共享内存 |
| 5 | **共享内存 shm** | 多进程映射同一块物理内存 | 是 | 否 | **最快** | 数据库 / 中间件的高频数据交换 |
| 6 | **消息队列 msg queue** | 内核维护的"消息链表"，可按类型收发 | 是 | 否 | 中 | 异步解耦、进程间排队传递结构化消息 |
| 7 | **套接字 socket** | 通信端点，**唯一能跨主机** | 是 | **是** | 中 | Nginx↔PHP-FPM（Unix socket）、Redis、一切网络服务 |

```text
速度排序（大概）：共享内存 > 信号/信号量 > 消息队列 ≈ 管道 ≈ socket（本机）> socket（跨网络）
原因：共享内存直接读写同一块物理内存，没有"用户态 ⇄ 内核态"的多次数据拷贝。
```

**追问一般是这三个**：

```text
1) 哪个最快？        → 共享内存（但要自己配信号量做同步）
2) 哪个不传数据？    → 信号（只带编号和少量信息）、信号量（只是个计数器）
3) 哪个能跨主机？    → 套接字 socket（唯一一个）
```

**每种方式的关键点（每个准备一句）**：

```text
管道 pipe    ：半双工、字节流、只能亲缘进程用（靠 fork 继承 fd）、进程结束就没了
命名管道 FIFO ：和匿名管道唯一的区别是"有名字"（存在于文件系统），任何进程都能打开
信号 signal  ：软中断式的异步通知；详见 05-Q1
信号量 sema  ：P/V 操作（减/加），值为 0 时申请者阻塞；经典组合是"共享内存 + 信号量"
共享内存 shm ：最快，但没有内置同步机制，进程崩溃可能留下残留
消息队列 msg ：有边界、可带优先级、异步；但比共享内存多一次拷贝
套接字 socket：唯一能跨主机；本机用 Unix domain socket 比 TCP 更快（不走协议栈）
```

**怎么看 / 清理 IPC 资源**：

```bash
ipcs -m              # 看共享内存段
ipcs -q              # 看消息队列
ipcs -s              # 看信号量
ipcs -l              # 看内核限制（最大队列数、单条消息大小）
ipcrm -m <id>        # 删除（进程异常退出常留下"僵尸"共享内存/信号量）
df -h /dev/shm       # 基于 tmpfs 的共享内存（默认是内存的一半）
```

**socket 的分类（追问会用）**：

| 类型 | 说明 | 例子 |
| --- | --- | --- |
| **AF_UNIX / Unix domain socket** | 本机不同进程之间，走文件系统路径，**比 TCP 更快**（不走协议栈） | `/run/docker.sock`、`/var/lib/mysql/mysql.sock`、Nginx ↔ PHP-FPM |
| AF_INET + TCP | 可靠、有连接、跨主机 | HTTP、MySQL 远程连接、Redis |
| AF_INET + UDP | 无连接、快、不保证可靠 | DNS、日志上报 |

> **★ 实战记忆**：**「MySQL 本地登录用 socket（快），远程用 TCP；Nginx 转发给 PHP-FPM 也用 Unix socket。」** 面试说出这个例子，比背定义有效得多。
>
> **注意别答混**：面试问的是"**Linux 的进程间通信机制**"（内核级）；如果是业务层的 MQ（Kafka、RabbitMQ），那是**分布式消息中间件** —— 可以补一句"业务上我们更多用消息中间件，内核级的消息队列用得少"。

## 九、本章追问链

```text
并发 / 并行   →  单核能并发吗？（能）
              →  Redis 单线程为什么能高并发？（IO 多路复用）
MB / Mb       →  100M 带宽下载多少？（12.5 MB/s）
              →  1TB 硬盘为什么显示 931G？（10 进制 vs 2 进制）
进程/线程/协程 →  为什么线程切换比进程快？（不换页表、不刷 TLB）
              →  线程越多越好吗？（不是，cs 飙升、sy 高）
buffer/cache  →  buff/cache 能回收吗？（能，所以看 available）
IO 模型       →  哪几种算同步？（前四种）
              →  零拷贝是什么？（sendfile 省掉用户态那一趟）
用户态/内核态  →  sy 高说明什么？（系统调用/切换多）
IPC           →  最快的是哪个？为什么？（共享内存，无拷贝）
              →  哪个不传数据？（信号、信号量）
              →  哪个能跨主机？（socket）
              →  共享内存为什么要配信号量？（本身没有同步机制）
```
