# 01 文件命令、重定向与链接

> **本章考什么**：你会不会用系统。
> **关键词**：`find` vs `grep`、`df` vs `du`、`>` vs `>>`、软链接 vs 硬链接、FHS 目录结构、前后台。
> **应届生范围**：会常用命令、能说清 rwx 之外的基本概念。
> **不需要**：特殊权限细节、ACL、inode 原理（在 `02` 和 `进阶版/`）。

## 一、常用命令（背分类，不背全集）

> **面试官会这么问**：你平时用得最多的 Linux 命令有哪些？
> **考察点**：基础命令熟练度 · 会不会按用途归类
> **答题技巧**：**别背词典，按用途分六类说**，说完主动补一个「最容易被问混的」（见 Q2）。

| 类别 | 命令 | 一句话 |
| --- | --- | --- |
| 看目录 | `ls -lh` / `ls -a` / `pwd` | 详情 / 含隐藏文件 / 当前路径 |
| 切目录 | `cd /etc` / `cd -` / `cd ~` | 进入 / 回上个目录 / 回家目录 |
| 建删 | `mkdir -p a/b` / `rm -f` / `rm -rf` | 递归建目录 / 删文件 / **删目录（不可恢复）** |
| 复制移动 | `cp -r dir1 dir2` / `mv a b` | 复制目录要加 `-r` / 移动或重命名 |
| 看内容 | `cat` / `less` / `head` / `tail -f` | 大文件用 less；**`tail -f` 实时跟日志** |
| 找文件 | `find /var/log -name "*.log"` | **按文件名 / 属性找** |
| 找内容 | `grep -rn "error" /var/log` | **在文件内容里找** |
| 打包 | `tar -czvf b.tar.gz /data` / `tar -xvf` | 打包压缩 / 解压 |
| 看空间 | `df -h` / `du -sh /var` | 分区容量 / 目录占用 |
| 看进程 | `ps aux` / `top` | 快照 / 实时 |
| 网络 | `ping` / `ss -tlnp` / `curl` | 连通 / 监听端口 / 测接口 |
| 编辑 | `vim` | `i` 插入、`Esc`、`:wq` 保存退出、`:q!` 强退 |

## 二、三道「最容易答错」的辨析题

### Q2 面试官：`find` 和 `grep` 有什么区别？

> **考察点**：命令用途区分 · 文件 vs 内容

**答**：`find` 在磁盘上**按文件名 / 属性找文件**；`grep` 在**文件内容里找文字**。两者常组合使用。

```bash
find /etc -name "*.conf"          # 找文件名
grep -rn "listen" /etc/nginx/     # 找内容（-r 递归、-n 显示行号）
find /etc -name "*.conf" | xargs grep listen   # 组合：在所有 conf 里搜 listen
```

**追问**：怎么找出 `/var/log` 下 7 天前的日志？
`find /var/log -name "*.log" -mtime +7`（`-mtime +7` = 修改时间在 7 天前）。

---

### Q3 面试官：`df` 和 `du` 有什么区别？

> **考察点**：磁盘排查的第一道分叉 · 高频题

**答**：

| 命令 | 看什么 |
| --- | --- |
| **`df -h`** | **分区 / 文件系统**的容量和使用率（还剩多少） |
| **`du -sh 目录`** | **目录 / 文件**实际占用了多少 |

> **标准答法**：「`df` 看的是**分区还剩多少空间**，`du` 看的是**目录占了多少空间**。排查磁盘满的时候先用 `df` 定位是哪个分区，再用 `du` 逐层找大目录。」

```bash
df -h                  # 看每个挂载点的 Use%
du -sh /var/log        # 看 /var/log 总共多大
du -sh /* | sort -h    # 找出哪个一级目录最大
```

**追问**：`df` 和 `du` 结果对不上，为什么？
① 文件被删但进程还持有句柄（`lsof | grep deleted`）；② 目录被新挂载覆盖了；③ ext4 默认给 root 预留 5%；④ inode 用尽（`df -i`）。详见 `08-Q2`。

---

### Q4 面试官：`tail -f` 和 `cat` 有什么区别？

> **考察点**：看日志的正确姿势

**答**：`cat` 是一次性把整个文件打出来（大文件会刷屏、卡终端）；**`tail -f` 是持续跟踪文件新写入的内容**，看实时日志用它。

```bash
tail -f /var/log/nginx/access.log     # 实时跟
tail -n 50 /var/log/messages          # 只最后 50 行
tail -F app.log                       # -F 比 -f 更强：文件被轮转后还能跟住新文件
```

> **加分**：`tail -F` 的 `F` 会在文件被**轮转（logrotate 改名）**后自动跟上新文件 —— 这也是排查「日志轮转后看不到新日志」的关键。详见 `11-Q4`。

## 三、重定向与管道（★★★ 必考基础）

### Q5 面试官：`>` 和 `>>` 有什么区别？`2>&1` 是什么意思？

> **考察点**：标准流 · 重定向 · 日志写入安全
> **来源**：面经②拓展，高频基础题

**先记住三个标准流**：

```text
0 = 标准输入（键盘）
1 = 标准输出（屏幕上的正常结果）
2 = 标准错误（屏幕上的报错信息）
```

**答**：`>` 是**覆盖**写入，`>>` 是**追加**写入。`2>&1` 表示「把标准错误也重定向到**标准输出当前所在的位置**」。

| 写法 | 含义 | 典型用法 |
| --- | --- | --- |
| **`>`** | **覆盖**输出到文件 | `echo hello > a.txt` |
| **`>>`** | **追加**输出到文件 | `echo hello >> a.txt` |
| `2>` | 只把**错误**输出到文件 | `命令 2> err.log` |
| `&>` | 正确 + 错误都到文件 | `命令 &> all.log` |
| **`> f 2>&1`** | 同上（老写法，兼容性好） | `命令 > f 2>&1` |
| `2>/dev/null` | **丢弃错误**（不显示报错） | `find / -name a 2>/dev/null` |
| **`管道符`** | 前一个命令的输出，当作后一个命令的输入 | `ps aux 管道符 grep nginx` |
| `tee` | 同时输出到屏幕**和**文件 | `命令 管道符 tee -a log.txt` |

> **★ 必须记住的一句话**：**`>` 是覆盖，`>>` 是追加 —— 写日志必须用 `>>`，用错 `>` 会把已有内容清空。**

**顺序有讲究**（高频追问）：`> f 2>&1` 里 `2>&1` 必须写在后面 —— 它表示「错误去**标准输出现在所在的地方**」，如果先 `2>&1` 再 `> f`，错误还是打到屏幕上。

**两个真实场景**：

```bash
# 1) 把命令的输出和错误都记到日志（cron 里最常用）
/shell/backup.sh >> /var/log/backup.log 2>&1

# 2) 屏蔽一堆无用的权限报错
find / -name "*.conf" 2>/dev/null
```

**管道的用处**：把多个命令串起来。

```bash
ps aux | grep nginx                     # 在进程列表里搜 nginx
cat app.log | grep "ERROR" | wc -l      # 统计错误行数
df -h | awk 'NR>1 {print $5, $6}'       # 只看使用率和挂载点
```

## 四、软链接与硬链接（★★★ 高频）

### Q6 面试官：硬链接和软链接有什么区别？

> **考察点**：inode · 文件系统 · 链接计数
> **来源**：面经①第 6 题（已会）· 面经②第 4 题（问的是软链接）

```bash
ln  a.txt  hard.txt      # 硬链接
ln -s a.txt soft.txt     # 软链接（-s = symbol）
ls -li a.txt hard.txt soft.txt    # -i 看 inode 编号
```

| 对比 | 硬链接 | 软链接 |
| --- | --- | --- |
| 本质 | **同一个文件的另一个名字** | **存放路径的快捷方式** |
| inode 编号 | **相同** | 不同 |
| **删除源文件后** | **还能用**（数据还在） | **失效**（指向的路径没了） |
| 能否跨分区 | **不能** | 能 |
| 能否指向目录 | **不能**（`.` `..` 除外） | **能** |
| 类比 | 同一个人有两个户口本 | 桌面上的快捷方式 |

**怎么判断是哪种链接**：

```bash
ls -l soft.txt
# lrwxrwxrwx ... soft.txt -> a.txt    ← 开头是 l，且有 -> 箭头，就是软链接
```

> **标准答法（背这一句）**：
> 「硬链接和源文件**指向同一个 inode**，相当于给文件起了个新名字，删掉源文件数据还在；软链接**存的是路径**，是一个快捷方式，删掉源文件就失效了。软链接可以跨分区、可以指向目录，硬链接不行。」

**底层的四个推论**（面试官追问时用）：

| 追问 | 怎么答 |
| --- | --- |
| 为什么硬链接不能跨文件系统 | **inode 编号只在单个文件系统内唯一**，跨分区找不到对应 inode |
| 怎么看出还有几个硬链接 | `ls -l` 的**第二列就是链接计数**，减到 0 数据才真正释放 |
| 目录能做硬链接吗 | 不能（`.` 和 `..` 除外），否则目录树会出现环路 |
| 软链接存的是什么 | 一段**路径字符串**，内核访问时重新解析 |

---

### Q7 面试官：什么是软链接？（面经②第 4 题）

> **考察点**：软链接的边界情况 · 断链 · 权限位
> **这题被追问的原因是**：只说「快捷方式」不够，要说出**断链、权限位、怎么覆盖**。

**被追问时补这 5 个细节**：

| 追问 | 怎么答 |
| --- | --- |
| 软链接的权限位有意义吗 | **没有**。软链接永远是 `lrwxrwxrwx`，能不能访问看**目标文件**的权限 |
| 写成相对路径会怎样 | 相对路径是相对**链接文件所在目录**解析的；把链接挪到别处就断了（跨目录一般写绝对路径） |
| 什么是断链（dangling link） | 目标被删或移走后：`ls -l` 一般显示成红色，`file` 报 `broken symbolic link`；此时 `test -L` 为真、`test -e` 为假 |
| 怎么覆盖已有的链接 | `ln -sf 目标 链接名`（`-f` = 覆盖）；不加 `-f` 会报 `File exists` |
| 怎么知道它指向哪 | `ls -l` 看 `->` 箭头；`readlink 链接`；`readlink -f 链接` 解析成最终绝对路径 |

> **实战场景（说出来比背定义有用）**：版本发布常用软链接切流 —— `/opt/app/current -> /opt/app/v1.2`，回滚就是把链接指向 v1.1；Nginx 的 `sites-enabled` 也是指向 `sites-available` 的软链接。

## 五、目录结构（FHS，了解）

### Q8 面试官：配置文件放在哪个目录？日志放在哪？`/proc` 是什么？

> **考察点**：FHS 目录规范 · 会不会最基本的「找东西」

Linux 只有一棵树，根是 `/`。**记住这几个就够**：

| 目录 | 放什么 |
| --- | --- |
| **`/etc`** | **配置文件**（nginx.conf、my.cnf 都在这） |
| **`/var`** | **可变数据**：日志（`/var/log`）、缓存、网站 |
| `/usr` | 系统软件和库 |
| `/home` | 普通用户的家目录 |
| `/root` | root 的家目录 |
| `/tmp` | 临时文件（**重启会清空**） |
| **`/proc`** | **虚拟文件系统**，反映内核实时状态（`cat /proc/cpuinfo`、`/proc/meminfo`、`/proc/<pid>/`） |
| `/dev` | 设备文件（如 `/dev/sda`） |
| `/boot` | 内核和引导文件（别乱动） |

> **面试可能问**：「配置文件一般放在哪？」→ `/etc`。「日志放在哪？」→ `/var/log`。「`/proc` 是什么？」→ **虚拟文件系统，不在硬盘上，读它就是读内核的实时状态**。

## 六、前后台任务

### Q9 面试官：怎么让程序在退出终端后继续跑？

> **考察点**：作业控制 · 终端与进程的关系

```bash
命令 &                  # 把命令丢到后台运行（但退出终端可能被挂断）
jobs                    # 查看当前终端的后台任务
fg %1                   # 把 1 号任务调回前台
bg %1                   # 把任务放到后台继续跑
Ctrl + Z                # 把正在跑的前台任务挂起（暂停）
Ctrl + C                # 结束正在跑的前台任务
nohup ./run.sh &        # 退出终端也不中断地跑
```

| 概念 | 说明 |
| --- | --- |
| `&` | 后台运行，**但退出终端可能被挂断** |
| **`nohup`** | **退出终端也不中断**（no hang up），配合 `&` 用 |
| `Ctrl+C` vs `Ctrl+Z` | 前者**结束**进程；后者只是**暂停**（挂到后台），可以 `fg` 恢复 |

> **答法**：「`nohup ./run.sh &`，或者 `disown`、`setsid`；**生产环境更推荐写成 systemd 服务** —— 由 PID 1 托管，和终端无关，还能开机自启。」
> 原理和更多脱离终端的方式见 `05-Q8`。
