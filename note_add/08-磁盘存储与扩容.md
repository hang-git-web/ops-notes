## 一、磁盘怎么看

### Q1 面试官：`df` 和 `du` 有什么区别？

> **考察点**：磁盘排查的第一道分叉 · 最高频的一题

| 命令 | 看什么 |
| --- | --- |
| **`df -h`** | **分区 / 文件系统**的容量和使用率（还剩多少） |
| **`du -sh 目录`** | **目录 / 文件**实际占用了多少 |

```bash
df -h                  # 看每个挂载点的 Use%（使用率）
du -sh /var/log        # 看 /var/log 总共多大
du -sh /* | sort -h    # 找出哪个一级目录最大
lsblk                  # 看有哪些磁盘和分区（硬件视角）
df -i                  # 看 inode 使用率（空间没满却写不进时查它）
```

> **标准答法**：**「`df` 看的是分区还剩多少空间，`du` 看的是目录占了多少空间。排查磁盘满的时候先用 `df` 定位是哪个分区，再用 `du` 逐层找大目录。」**

---

### Q2 面试官：磁盘满了怎么查？`df` 和 `du` 结果对不上怎么办？

> **考察点**：磁盘排查步骤 + 两个特例（inode / deleted file）
> **这是四道场景题的第 3 题，必背。**

**排查六步**：

```text
1) df -h                     先确认是哪个分区满了
2) du -sh /* | sort -h       在该分区里逐层往下找大目录
3) 找到大文件后判断：日志 / 备份 / 垃圾 → 清理或转移
4) 如果是日志：清理 + 配置 logrotate 自动轮转（治本，见 11-Q3）
5) 特例：df 显示有空间但写不进 → df -i 查 inode 是否用满（见 02-Q7）
6) 特例：删了文件空间没释放   → lsof | grep deleted，重启对应进程
```

**为什么 `df` 和 `du` 会对不上（★ 高频追问）**：

| 原因 | 说明 | 怎么确认 |
| --- | --- | --- |
| **文件被删但进程还持有句柄** | 目录里看不到，但 inode 和数据块还被占用 | `lsof 管道符 grep deleted`、`lsof +L1` |
| **目录被新挂载覆盖** | 挂载是覆盖行为，原数据还在但看不见 | `mount` 看挂载点、先 `umount` 再看 |
| **ext4 默认给 root 预留 5%** | 普通用户看到的可用空间比 df 少 | `tune2fs -l /dev/sda1`（看 Reserved block count） |
| **inode 用尽** | 空间还有，但创建不了新文件 | `df -i` |

**找大文件的组合拳**：

```bash
du -ah /data | sort -h | tail -10
find / -size +1G -mtime -7                    # 7 天内、大于 1G 的
find /data -type f -size +500M -exec ls -lh {} +   # 列出来看
```

> **加分点**：第 5、6 条能说出来，说明你**真踩过坑**，不是背的。

## 二、新盘怎么用（五步 / 七步）

### Q3 面试官：给服务器新装一块磁盘，会有哪些初始化步骤？

> **考察点**：**面经②第 2 题** · 这人被拷打的原因是**漏说了"分区"**
> **难度**：★★★ · **这题是清单题，面试官会逐项核对，漏一步等于没做过**

**核心顺序（★ 背这一句）**：
> **「识别新盘 → 分区 → 刷新分区表 → 格式化 → 挂载 → 写 fstab 开机自挂 → `mount -a` 验证。」**

**完整 7 步（每一步都带验证）**：

```bash
# 1) 先在虚拟机/云控制台添加一块磁盘（关机加最稳；热添加后需要重新扫描）
echo "- - -" > /sys/class/scsi_host/host0/scan      # 热添加后手动触发扫描

# 2) 确认系统识别到了新盘（关键：看清盘符，别搞错盘！）
lsblk                         # 树状列出所有盘和分区
fdisk -l                      # 更详细（容量、分区表类型）
dmesg | tail                  # 看内核有没有识别到新盘的日志

# 3) 分区（新盘 /dev/sdb，无分区）
fdisk /dev/sdb                # 交互式：n → p → 1 → 回车 → 回车 → w
partprobe /dev/sdb            # ★ 刷新分区表，让内核认到 /dev/sdb1（最容易漏的一步）
lsblk /dev/sdb                # 验证：能看到 sdb1 了

# 4) 格式化：在"分区"上建文件系统
mkfs.ext4 /dev/sdb1           # 或 mkfs.xfs /dev/sdb1（★ 格式化会清空数据）
blkid /dev/sdb1               # 看新分区的 UUID 和文件系统类型

# 5) 挂载（先建目录再挂）
mkdir -p /data
mount /dev/sdb1 /data
df -h /data                   # 验证：容量对不对、挂载点对不对

# 6) 开机自动挂载：写 /etc/fstab（用 UUID，不要用 /dev/sdb1）
cp /etc/fstab /etc/fstab.bak.$(date +%F)          # 改之前先备份
# 在 fstab 里加一行（内容如下），然后验证：
#   UUID=xxxx-xxxx  /data  ext4  defaults,nofail  0  2
mount -a                      # ★ 验证：不报错才算对

# 7) 按需给目录权限
chown -R app:app /data
chmod 750 /data
```

**这四个关键词说出来，可信度立刻不一样**：

| 关键词 | 为什么重要 |
| --- | --- |
| **`partprobe`** | 不做的话分区建好了但 `/dev/sdb1` 不出现，`mkfs` 会报找不到设备 |
| **`blkid` 取 UUID** | 盘符可能变（加盘、换控制器），UUID 不会 |
| **`nofail`** | 挂不上也不阻塞开机（数据盘强烈建议加） |
| **`mount -a`** | 改完 fstab 必须验证，否则重启起不来 |

**`fdisk` 交互键（别只会敲命令）**：

| 键 | 作用 |
| --- | --- |
| `m` | 帮助 |
| `n` | 新建分区（之后选 p/e、分区号、起止扇区） |
| `d` | 删除分区 |
| `p` | 打印当前分区表（**动手前先看一眼**） |
| `t` | 改分区类型（8e = LVM、82 = swap） |
| **`w`** | **保存并退出**（= 真正生效） |
| `q` | 不保存退出 |

> **`w` 才保存、`q` 不保存** —— 这个小细节能体现你真操作过。
> **大磁盘（> 2T）用 `parted` 或 `gdisk`**（GPT 分区表）：
> ```bash
> parted -s /dev/sdb mklabel gpt
> parted -s /dev/sdb mkpart primary xfs 0% 100%
> ```

### Q4 面试官：`/etc/fstab` 是什么？为什么用 UUID？

> **考察点**：开机自动挂载 · fstab 六字段 · 防御性习惯

**`/etc/fstab` = 开机自动挂载的配置文件**，每行六个字段：

```text
UUID=xxxx-xxxx   /data    ext4    defaults,nofail    0    2
      ↑            ↑        ↑            ↑           ↑    ↑
    设备       挂载点    文件系统      挂载选项      备份  fsck顺序
```

| 写法 | 说明 |
| --- | --- |
| `UUID=...` | **推荐**：盘符可能变（加盘、换控制器），UUID 不会 |
| `defaults` | 默认选项（rw、suid、exec、auto、nouser、async） |
| **`nofail`** | **挂不上也不阻塞开机**（数据盘强烈建议加） |
| 最后的 `2` | 开机 fsck 顺序：根分区是 1，其它是 2，不检查写 0 |

> **fstab 写错的后果**：系统进 emergency mode。救援方法见 `06-Q6`。
> **面试官爱问的连续追问**：「如果盘换了、UUID 变了怎么办？」→ `blkid` 查新 UUID，改 fstab（或进救援模式改）。

## 三、扩容

### Q5 面试官：虚拟机扩盘的详细步骤和指令？（面经①第 9 题）

> **考察点**：**面经原题** · 系统识别 → 分区 → 文件系统 全链路
> **注意区分两个场景**：**A 是加一块新盘；B 是原来那块盘变大了**。

#### 场景 A：新增一块盘

就是 Q3 的 7 步（识别 → 分区 → `partprobe` → `mkfs` → `mount` → fstab → `mount -a`）。

#### 场景 B：把已有分区「变大」（云盘扩容 / 虚拟机扩容量）

**普通分区（非 LVM）**：

```bash
# 1) 控制台把盘扩容（比如 40G → 100G）
lsblk                       # 确认盘变大了，但分区还没变

# 2) 扩分区（两条路）
growpart /dev/sda 3         # ★ cloud-utils 工具，最省事（推荐）
# 或 fdisk /dev/sda：d 删掉分区 → n 重建 → ★起始扇区必须和原来一致 → w
partprobe /dev/sda

# 3) 扩文件系统（★ 命令不同，必考）
resize2fs /dev/sda3         # ext4 —— 写【设备名】
xfs_growfs /data            # xfs  —— 写【挂载点】

df -h /data                 # 验证
```

> **XFS 只能扩、不能缩**（要缩容只能备份 → 重建 → 恢复）；ext4 可以缩，但**必须先卸载**。

**LVM 在线扩容（★ 生产最常见）**：

```bash
# 先看结构，确认 VG 里还有没有空闲空间
pvs ; vgs ; lvs

# 1) 如果是新加了一块盘要并进这个 VG
pvcreate /dev/sdc
vgextend vg_data /dev/sdc

# 2) 如果底层盘本身变大了，先扩 PV
pvresize /dev/sda3

# 3) 扩 LV（+10G 或 全部剩余空间）
lvextend -L +10G /dev/vg_data/lv_app
lvextend -l +100%FREE /dev/vg_data/lv_app

# 4) 扩文件系统（★ 两条命令不一样，少这一步 df 不会变）
resize2fs /dev/vg_data/lv_app     # ext4
xfs_growfs /app                   # xfs（写挂载点）
```

> **一句话总结 LVM 扩容：`pvresize` → `lvextend` → `resize2fs`/`xfs_growfs`，三步缺一不可。**

**LVM 是什么、有什么好处**：

| 概念 | 作用 |
| --- | --- |
| PV（物理卷） | 初始化过的硬盘 / 分区 |
| VG（卷组） | PV 组成的资源池 |
| **LV（逻辑卷）** | 从池子里划出来用的空间 |

> **好处一句话**：**普通分区建好就改不了大小，LVM 可以「在线扩容」**（还能做快照）。这也是为什么生产上数据库盘一般建在 LVM 上。

**扩 swap（顺带记）**：

```bash
swapon --show                  # 看当前 swap
# 方式一：加 swap 文件（不用分区，最方便）
fallocate -l 4G /swapfile && chmod 600 /swapfile
mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
# 方式二：新分区 → mkswap /dev/sdb2 → swapon /dev/sdb2 → 写 fstab
```

---

### Q6 面试官：ext4 和 XFS 有什么区别？扩容命令为什么不一样？

> **考察点**：文件系统差异 · 缩容的禁忌

| | ext4 | XFS |
| --- | --- | --- |
| 扩容命令 | `resize2fs`（写**设备名**） | `xfs_growfs`（写**挂载点**） |
| 缩容 | **可以**（必须先卸载） | **不支持**，只能备份重建 |
| 常见于 | CentOS 6/7、Ubuntu | CentOS 7+ 默认、RHEL 系 |

> **面试官爱问**：「扩完分区了，`df` 为什么没变？」→ **因为少了"扩文件系统"这一步**（`resize2fs` / `xfs_growfs`）。分区是"容器"，文件系统是"容器里的东西"，两个都要扩。

## 四、RAID

### Q7 面试官：RAID 0/1/5/10 有什么区别？为什么数据库用 RAID 10？

> **考察点**：RAID 级别 · 容量与容错计算 · 和备份的关系

| 级别 | 最少几块盘 | 可用容量 | 能坏几块盘 | 适合什么 |
| --- | --- | --- | --- | --- |
| **RAID 0** | 2 | 全部之和（N×单盘） | **0 块**（坏了全丢） | 临时数据、求速度 |
| **RAID 1** | 2 | 单盘容量 | N−1 块 | 系统盘 |
| **RAID 5** | 3 | **(N−1) × 单盘** | **1 块** | 一般存储 |
| **RAID 6** | 4 | (N−2) × 单盘 | **2 块** | 大容量存储 |
| **RAID 10** | 4 | N/2 × 单盘 | 每组坏 1 块 | **数据库** |

**常考的三个问题**：

> **Q：4 块 1T 的盘做 RAID 5，可用容量多少？**
> A：**(4−1) × 1T = 3T**（牺牲一块盘的容量存校验信息）。
>
> **Q：RAID 5 坏了两块盘会怎样？**
> A：**数据全部丢失**（RAID 5 只能容错 1 块）。
>
> **Q：数据库为什么用 RAID 10 而不是 RAID 5？**
> A：RAID 5 每次写要额外算校验（**写惩罚**），**写性能差**；RAID 10 是镜像 + 条带，**读写都快、容错也更好**（数据库写多）。

---

### Q8 面试官：RAID 能代替备份吗？

> **考察点**：高可用 vs 可恢复 · **这题几乎必问**

> **答：不能。**
> RAID 只能防「磁盘物理损坏」，**防不了误删、病毒、逻辑损坏** —— 因为这些操作会被**同步到所有盘**。

| | RAID | 备份 |
| --- | --- | --- |
| 解决什么 | **磁盘坏了服务不中断**（高可用） | **数据能恢复**（可恢复性） |
| 防误删吗 | **不防**（删除会被同步） | 防（能回滚到备份点） |

> **一句话（背这句）**：**「RAID 保的是『不中断』，备份保的是『能恢复』，两者解决的是不同问题。」**
> 备份的 3-2-1 原则和恢复演练见 `12-Q1`。

## 五、磁盘 IO 是不是瓶颈

### Q9 面试官：怎么判断磁盘 IO 是瓶颈？

> **考察点**：iostat 判读 · 和 `wa` 的联系

```bash
iostat -x 1 3        # 重点看 %util 和 await
iotop -o             # 看哪个进程在读写
pidstat -d 1         # 按进程看 IO
vmstat 1             # bi/bo 和 wa
```

| 指标 | 含义 | 判断 |
| --- | --- | --- |
| **`%util`** | 设备"忙着处理 IO"的时间占比 | **接近 100% 说明磁盘是瓶颈** |
| **`await`** | 平均每次 IO 的等待时间（含排队） | **明显变大说明排队严重** |
| `svctm` | 实际服务时间 | 现代内核不准，参考 `%util`+`await` |
| `r/s` `w/s` | 每秒读写次数（IOPS） | 和盘的能力比 |

> **和 CPU 串起来**：`top` 里 **`wa` 高 + `us` 不高** → **其实是在等磁盘，加 CPU 没用**，要去看 `iostat -x`。
> **加分**：**`iostat -x` 里 `%util` 100% 但 `await` 不大**，可能是 SSD/RAID 卡并行度高，"忙"不等于"慢"；**`await` 大才是真慢**。
