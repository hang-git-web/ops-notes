# 13 补充：磁盘扩容与挂载实操（面经第 9 题）

> **面经原题**：虚拟机扩盘的详细步骤和指令。
> 这题你答了七七八八，缺的是 **刷新分区表（`partprobe`）**、**用 UUID 而不是设备名**、**XFS 和 ext4 扩文件系统的命令不同**。
> **核心顺序（背这一句）**：
> **"识别新盘 → 分区 → 刷新分区表 → 格式化 → 挂载 → 写 fstab 开机自挂 → `mount -a` 验证。"**

---

## 一、场景 A：虚拟机上"新增一块盘"（面经原题，完整版）

### 步骤 ①~⑦（每一步都带验证）

```bash
# ① 先在虚拟机/云控制台添加一块磁盘（关机加最稳；热添加后需要重新扫描）
echo "- - -" > /sys/class/scsi_host/host0/scan      # 热添加后手动触发扫描

# ② 确认系统识别到了新盘（关键：看清盘符，别搞错盘！）
lsblk                         # 树状列出所有盘和分区
fdisk -l                      # 更详细（容量、分区表类型）
dmesg | tail                  # 看内核有没有识别到新盘的日志

# ③ 分区（新盘 /dev/sdb，无分区）
fdisk /dev/sdb                # 交互式：n → p → 1 → 回车 → 回车 → w
partprobe /dev/sdb            # ★ 刷新分区表，让内核认到 /dev/sdb1（最容易漏的一步）
lsblk /dev/sdb                # 验证：能看到 sdb1 了

# ④ 格式化：在"分区"上建文件系统
mkfs.ext4 /dev/sdb1           # 或 mkfs.xfs /dev/sdb1（★ 格式化会清空数据）
blkid /dev/sdb1               # 看新分区的 UUID 和文件系统类型

# ⑤ 挂载（先建目录再挂）
mkdir -p /data
mount /dev/sdb1 /data
df -h /data                   # 验证：容量对不对、挂载点对不对

# ⑥ 开机自动挂载：写 /etc/fstab（用 UUID，不要用 /dev/sdb1）
cp /etc/fstab /etc/fstab.bak.$(date +%F)          # 改之前先备份
# 在 fstab 里加一行（内容如下），然后验证：
#   UUID=xxxx-xxxx  /data  ext4  defaults,nofail  0  2
mount -a                      # ★ 验证：不报错才算对

# ⑦ 按需给目录权限
chown -R app:app /data
chmod 750 /data
```

### `/etc/fstab` 六个字段（必背）

```text
UUID=xxxx-xxxx   /data    ext4    defaults,nofail    0    2
      ↑            ↑        ↑            ↑           ↑    ↑
    设备       挂载点    文件系统      挂载选项      备份  fsck顺序
```

| 写法 | 说明 |
| --- | --- |
| `UUID=...` | **推荐**：盘符可能变（加盘、换控制器），UUID 不会 |
| `defaults` | 默认选项（rw、suid、exec、auto、nouser、async）|
| **`nofail`** | **挂不上也不阻塞开机**（数据盘强烈建议加）|
| 最后的 `2` | 开机 fsck 顺序：根分区是 1，其它是 2，不检查写 0 |

> ⚠️ **fstab 写错的后果**：系统进 emergency mode。救援方法见 `09-补充-Linux启动流程.md` 第四节。

### `fdisk` 交互键（别只会敲命令）

| 键 | 作用 |
| --- | --- |
| `m` | 帮助 |
| `n` | 新建分区（之后选 p/e、分区号、起止扇区）|
| `d` | 删除分区 |
| `p` | 打印当前分区表（**动手前先看一眼**）|
| `t` | 改分区类型（8e = LVM、82 = swap）|
| **`w`** | **保存并退出**（= 真正生效）|
| `q` | 不保存退出 |

> **大磁盘（> 2T）用 `parted` 或 `gdisk`**（GPT 分区表）：
> ```bash
> parted -s /dev/sdb mklabel gpt
> parted -s /dev/sdb mkpart primary xfs 0% 100%
> ```

## 二、场景 B：把已有分区"变大"（云盘扩容 / 虚拟机扩容量）

> 注意区别：**场景 A 是加一块新盘；场景 B 是原来那块盘变大了，要把多出来的空间"吃进去"。**

### 2.1 普通分区（非 LVM）

```bash
# ① 控制台把盘扩容（比如 40G → 100G）
lsblk                       # 确认盘变大了，但分区还没变

# ② 扩分区（两条路）
growpart /dev/sda 3         # ★ cloud-utils 工具，最省事（推荐）
# 或 fdisk /dev/sda：d 删掉分区 → n 重建 → ★ 起始扇区必须和原来一致 → w
partprobe /dev/sda

# ③ 扩文件系统（★ 命令不同，必考）
resize2fs /dev/sda3         # ext4
xfs_growfs /data            # xfs（注意：写挂载点，不是设备名）

df -h /data                 # 验证
```

> **XFS 只能扩、不能缩**（要缩容只能备份 → 重建 → 恢复）；ext4 可以缩，但必须先卸载。

### 2.2 LVM 在线扩容（★ 生产最常见，你笔记 `03` 提过，这里补齐）

```bash
# 先看结构，确认 VG 里还有没有空闲空间
pvs ; vgs ; lvs

# ① 如果是新加了一块盘要并进这个 VG
pvcreate /dev/sdc
vgextend vg_data /dev/sdc

# ② 如果底层盘本身变大了，先扩 PV
pvresize /dev/sda3

# ③ 扩 LV（+10G 或 全部剩余空间）
lvextend -L +10G /dev/vg_data/lv_app
lvextend -l +100%FREE /dev/vg_data/lv_app

# ④ 扩文件系统（★ 两条命令不一样，少这一步 df 不会变）
resize2fs /dev/vg_data/lv_app     # ext4
xfs_growfs /app                   # xfs（写挂载点）
```

> **一句话总结 LVM 扩容：`pvresize` → `lvextend` → `resize2fs`/`xfs_growfs`，三步缺一不可。**

### 2.3 扩 swap（顺带记）

```bash
swapon --show                  # 看当前 swap
# 方式一：加 swap 文件（不用分区，最方便）
fallocate -l 4G /swapfile && chmod 600 /swapfile
mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
# 方式二：新分区 → mkswap /dev/sdb2 → swapon /dev/sdb2 → 写 fstab
```

## 三、实操里最容易踩的 6 个坑（说得出就是"真做过"）

| 坑 | 表现 | 原因 / 处理 |
| --- | --- | --- |
| **没跑 `partprobe`** | 分区建好了但 `/dev/sdb1` 不存在 | 内核还没重读分区表；`partprobe` 或 `partx -a` |
| **fstab 用 `/dev/sdb1`** | 重启后盘符变了 → 起不来 | 改用 **UUID**（`blkid` 查），并加 `nofail` |
| **盘符搞混** | `mkfs` 把有数据的盘格式化了 | 动手前 `lsblk -f` + `df -h` 核对；**mkfs 不可逆** |
| **`df` 没变化** | 扩完分区 df 还是老容量 | 少了"扩文件系统"那一步（`resize2fs`/`xfs_growfs`）|
| **挂载后原有数据"消失"** | 挂到非空目录上，原内容被遮住 | 挂载是覆盖行为；应先换空目录或先迁移数据 |
| **XFS 想缩容** | `xfs_growfs` 不支持缩小 | XFS 设计上不支持缩容，只能重建 |

## 四、面试怎么答这题（照着这个顺序说）

```text
① 先确认：在控制台加盘/扩容 → lsblk、fdisk -l 确认系统识别到新盘（新盘是 /dev/sdb，无分区）
② 分区：fdisk /dev/sdb，n 建主分区，w 保存；然后 partprobe 刷新分区表
③ 格式化：mkfs.ext4 /dev/sdb1（或 mkfs.xfs）
④ 挂载：mkdir /data → mount /dev/sdb1 /data → df -h 确认
⑤ 持久化：blkid 取 UUID，写进 /etc/fstab（UUID + nofail），mount -a 验证
⑥ 如果是"扩容"而不是新盘：扩分区（growpart）→ 扩文件系统（resize2fs / xfs_growfs）
   如果是 LVM：pvresize → lvextend → resize2fs / xfs_growfs
⑦ 补一句安全意识："动手前先 lsblk 核对盘符，fstab 改前备份、改后 mount -a 验证，避免重启起不来。"
```

> **面试官想听的其实是"你到底做没做过"**：`w` 才保存、`partprobe` 刷新、UUID 优于设备名、XFS 不能缩——随便说出一两个，可信度立刻不一样。
