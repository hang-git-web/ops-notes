# 12 补充：文件类型、inode 与文件系统（面经第 7 题）

> **面经原题**：如何看文件类型？（你只答了半句）
> **完整答法**：**"两种方式：`file 文件名` 直接看类型，它读文件头判断、不受扩展名影响；或者 `ls -l` 看第一个字符——`-` 普通文件、`d` 目录、`l` 软链接、`b` 块设备、`c` 字符设备、`s` socket、`p` 命名管道。"**
> 这题还会牵出 **inode**（因为硬链接、磁盘写不进去都跟它有关），所以本篇一起补。

## 一、看文件类型的三种方式

```bash
file /etc/passwd          # ASCII text
file /bin/ls              # ELF 64-bit LSB executable...
file -i 图片.png          # image/png（MIME 类型）
file -b /dev/sda          # block special（不显示文件名，脚本里好用）

ls -l /etc/passwd         # 看第一个字符
stat /etc/passwd          # 文件系统层面的详细信息（含 inode 号、三个时间）
```

### 1.1 `ls -l` 第一个字符的 7 种类型（★ 背下来）

| 字符 | 类型 | 例子 | 说明 |
| --- | --- | --- | --- |
| `-` | **普通文件** | 文本、二进制、配置 | 最常见 |
| `d` | **目录** | `/etc` | 目录本质也是文件（存的是"名字 → inode"的映射）|
| `l` | **符号链接** | `ls -l` 里带 `->` | 软链接 |
| `b` | **块设备** | `/dev/sda`、`/dev/sdb1` | 按块随机读写，可挂载 |
| `c` | **字符设备** | `/dev/tty`、`/dev/null` | 按字符流读写，不可挂载 |
| `s` | **套接字 socket** | `/run/docker.sock` | 进程间通信的端点 |
| `p` | **命名管道 FIFO** | `mkfifo /tmp/pipe` | 管道文件 |

> **小技巧**：`ls -lF` 会在名字后面加标记：目录 `/`、可执行 `*`、软链 `@`、socket `=`、FIFO `|` —— 一眼就能看出来。

### 1.2 为什么 `file` 不看扩展名

```text
Linux 不靠扩展名判断文件类型，靠的是文件内容（头部 magic number）和权限位。
所以把 a.jpg 改名成 a.txt，file 依然会说它是 JPEG 图片。
（这也解释了：为什么在没有 x 权限时，即使是二进制也不能"直接执行"）
```

## 二、inode 是什么（★ 硬链接题的底层）

### 2.1 一句话

```text
inode（索引节点）= 文件的"元数据 + 数据块地址表"，不包含文件名。
存放：权限、属主/属组、大小、三个时间、指向数据块的指针、链接计数。

文件名和 inode 的关系：
   目录项（文件名） → inode 号 → 数据块
   所以"文件名"只是目录里的一条记录，删掉文件名不等于删掉 inode。
```

```bash
ls -li a.txt hard.txt soft.txt
#  1234567 -rw-r--r-- 2 root root ... a.txt      ← 链接计数 2
#  1234567 -rw-r--r-- 2 root root ... hard.txt   ← ★ inode 相同 = 硬链接
#  1234570 lrwxrwxrwx 1 root root ... soft.txt -> a.txt  ← inode 不同 = 软链接
stat a.txt        # 直接看 inode 号、链接计数、三个时间
```

### 2.2 四个必记推论

| 推论 | 原因 |
| --- | --- |
| **硬链接的 inode 相同** | 它们是同一个文件的不同名字 |
| **删除一个硬链接，文件还在** | 只看**链接计数**减到 0 才真正释放数据 |
| **硬链接不能跨文件系统** | **inode 编号只在单个文件系统内唯一**，跨分区找不到对应 inode |
| **软链接可以跨分区、可以指向目录** | 它只存路径字符串，靠内核重新解析 |

### 2.3 inode 用尽：空间没满却写不进（★ 高频故障）

```bash
df -h /            # 空间看起来还有
df -i /            # ★ inode 已经 100% → 创建新文件报 "No space left on device"
```

> **原因**：inode 数量在 `mkfs` 时就固定了（每个文件至少占一个 inode）。
> **场景**：`/var/spool/postfix` 堆积大量小邮件、session 文件、缓存小文件。
> **处理**：找出小文件多的目录清掉；长期方案是重建文件系统时调大 inode 数或换 xfs（动态分配 inode）。

## 三、文件系统与时间戳（顺带补，面试常混）

### 3.1 常见文件系统

| 文件系统 | 特点 | 常见于 |
| --- | --- | --- |
| **ext4** | 稳定、经典，可缩容 | CentOS 6/7、Ubuntu |
| **xfs** | 大文件、高并发强，**只能扩不能缩** | CentOS 7+ 默认、RHEL 系 |
| tmpfs | 内存里的文件系统，重启即失 | `/dev/shm`、`/run` |
| overlayfs | 分层联合挂载 | **Docker 镜像层** |
| nfs / cifs | 网络文件系统 | 共享存储 |

```bash
df -T              # 显示文件系统类型
mount | column -t  # 看当前挂载和类型
```

### 3.2 三个时间（`find` 按时间找文件就靠它们）

| 时间 | 含义 | 什么时候变 |
| --- | --- | --- |
| **mtime** | 内容修改时间 | 改内容时（**最常用**）|
| **ctime** | 元数据变更时间（权限、属主、链接数） | `chmod`/`chown` 时 |
| **atime** | 访问时间 | 读文件时（现代系统常用 `relatime` 减少写入）|

```bash
find /var/log -name "*.log" -mtime +7      # 7 天前修改过的
find /data -size +100M -mtime -1           # 一天内、大于 100M 的文件
```

### 3.3 磁盘和分区的命名规律（扩盘那题的基础）

| 名字 | 含义 |
| --- | --- |
| `/dev/sda` / `/dev/sdb` | 第一块 / 第二块 SCSI/SATA 盘（虚拟机的虚拟盘也常这样命名）|
| `/dev/sda1`、`/dev/sdb1` | 磁盘上的分区 |
| `/dev/vda` | KVM/QEMU 的 virtio 盘 |
| `/dev/nvme0n1`、`/dev/nvme0n1p1` | NVMe 盘及其分区 |
| `/dev/sr0` | 光驱 |

> **记住**：**盘是 `/dev/sdb`，分区是 `/dev/sdb1`**；`mkfs` 要作用在**分区**上，`fdisk -l` / `lsblk` 用来确认到底识别到了什么。

## 四、面试可能这么问

**Q：怎么查看一个文件的类型？**
A：`file 文件名`，它读文件头判断类型，不受扩展名影响；也可以 `ls -l` 看第一个字符——普通文件 `-`、目录 `d`、软链接 `l`、块设备 `b`、字符设备 `c`、socket `s`、命名管道 `p`。

**Q：inode 是什么？**
A：文件的元数据和数据块索引，包含权限、属主、大小、时间、数据块指针和链接计数，**但不包含文件名**。文件名只是目录里"名字 → inode 号"的映射。

**Q：为什么硬链接不能跨文件系统？**
A：inode 编号只在单个文件系统内部唯一，跨分区就没有对应的 inode 了。软链接存的是路径，所以可以跨分区、也可以指向目录。

**Q：磁盘没满但写不进文件，可能是什么原因？**
A：三种常见原因——① **inode 用尽**（`df -i` 看）；② 分区满了但你写的是另一个挂载点（`df -h 目录`）；③ 删了文件但进程还持有句柄，空间没释放（`lsof | grep deleted`）。

**Q：块设备和字符设备有什么区别？**
A：块设备（`b`，如 `/dev/sda`）以固定大小的块随机读写、可以挂载文件系统；字符设备（`c`，如 `/dev/tty`、`/dev/null`）按字节流顺序读写、不经过缓冲、不能挂载。
