## 一、内存怎么看（**先破除一个误区**）

```bash
free -h
              total        used        free      shared  buff/cache   available
Mem:           15Gi       6.2Gi       1.1Gi       412Mi       8.4Gi       8.9Gi
Swap:         4.0Gi          0B       4.0Gi
```

### 三个关键认知（★ 面试常考）

| 认知 | 说明 |
| --- | --- |
| **① `buff/cache` 大 ≠ 内存不足** | 这是**缓存**（Linux 拿空闲内存缓存数据加速），应用需要时会自动回收 |
| **② 判断内存够不够看 `available`** | 不是看 `free`，也不是看 `used` |
| **③ 真正缺内存的信号是 `si/so`** | `vmstat 1` 里持续非 0（说明在换页）才说明内存压力大 |

> **标准答法**：**"`free` 里 buff/cache 占了很多是正常的，那是缓存；判断内存是否充足要看 `available`——它才是应用真正还能拿到的内存。如果 `vmstat` 里 si/so 持续不为 0，才说明内存真的紧张。"**

### 附：内存不够会有什么现象

```text
· 系统变慢（频繁换页到 swap）
· 进程被 OOM Killer 杀掉 → dmesg | grep -i oom 能查到
· 容器里的进程被杀 → 状态显示 OOMKilled
```

## 二、常用性能工具（**只需知道"看什么"**）

| 工具 | 看什么 | 关键指标 |
| --- | --- | --- |
| **`top`** | 实时总览 | CPU 各字段、哪个进程最占资源 |
| **`free -h`** | 内存 | **`available`** |
| **`vmstat 1`** | CPU + 内存 + IO 综合 | `r`（CPU 队列）、`b`+`wa`（磁盘）、**`si/so`（内存换页）** |
| **`iostat -x 1`** | 磁盘 IO | **`%util`（接近 100% 说明盘忙）**、`await`（响应时间）|
| **`ss -tlnp`** | 端口与连接 | 监听地址、连接状态 |
| `ps aux --sort=-%cpu` | 按 CPU 排进程 | 找 CPU 最高的 |
| `ps aux --sort=-%mem` | 按内存排进程 | 找内存最高的 |

### CPU 使用率含义（top 第一行，**记住 3 个**）

```text
%Cpu(s):  3.2 us,  1.5 sy,  0.0 ni, 94.0 id,  1.2 wa,  0.0 hi,  0.1 si,  0.0 st
             ↑          ↑                     ↑
        用户态(应用在算) 内核态(系统调用)    IO等待(等磁盘)
```

| 字段 | 高说明什么 |
| --- | --- |
| **`us`** | 应用在算（代码问题）|
| **`sy`** | 系统调用/上下文切换太多 |
| **`wa`** | **在等磁盘 IO，不是 CPU 的问题（加 CPU 没用）** |

## 三、四道场景题（★ 必须背下来）

### 场景题 1：服务器 CPU 使用率 100%，你怎么查？

```text
① top 找出是哪个进程（按 P 键按 CPU 排序），记住 PID
② 判断是什么原因：
   · us 高 → 应用自己在算（死循环、正则、频繁 GC）
   · sy 高 → 系统调用/上下文切换太多
   · wa 高 → 其实是在等磁盘 IO，不是 CPU 问题
③ 深入到进程内部：
   · Java：jstack <pid> 看线程栈
   · 通用：top -H -p <pid> 看是哪个线程
④ 处理：
   · 业务高峰 → 扩容
   · 代码 bug → 修代码
   · 异常进程 → kill 掉
```

### 场景题 2：内存不够（内存快满了）怎么查？

```text
① free -h              重点看 available（不是 free，也不是 used）
② buff/cache 大是正常的，那是缓存，不是内存不足
③ vmstat 1             看 si/so，持续非 0 才是真的缺内存
④ ps aux --sort=-%mem | head   找出占内存最大的进程
⑤ dmesg | grep -i oom  看有没有进程被 OOM 杀掉过
```

### 场景题 3：磁盘满了怎么查？

```text
① df -h                先确认哪个分区满了
② du -sh /* | sort -h  在该分区里逐层找大目录
③ 找到后判断是日志、备份还是垃圾 → 清理或转移
④ 是日志的话 → 清理并配置 logrotate 自动轮转（治本）
⑤ 特例：df 有空间但写不进 → df -i 查 inode
⑥ 特例：删了文件空间没释放 → lsof | grep deleted，重启对应进程
```

### 场景题 4：服务起不来 / 端口不通怎么查？

```text
① systemctl status 服务          看状态和错误提示
② journalctl -u 服务 -n 50       看详细日志
③ ss -tlnp | grep 端口           端口是否被占用、服务是否在监听
④ 检查配置文件语法（如 nginx -t）
⑤ 检查目录权限和属主（数据目录、日志目录）
⑥ 检查磁盘是否满（df -h）        最容易忽略的一条
⑦ 如果是"本机能访问、外部不能"：
   · 先看监听地址是 0.0.0.0 还是 127.0.0.1
   · 再看防火墙（firewall-cmd --list-all / ufw status）
   · 再看 SELinux（getenforce）
```

## 四、答题技巧（比答案本身更重要）

**面试官问场景题，想听的是"你的排查思路"，不是"你会几个命令"。**

所以答题时用这个结构：

```text
① 先说方向：我要先定位是"哪一类资源"的问题（CPU / 内存 / 磁盘 / 网络）
② 再说顺序：先看整体（top/free/df），再定位到具体进程
③ 再说工具：具体用什么命令、看什么指标
④ 最后说处理：找到原因怎么解决
```

**反面例子**（不要这样答）：

> "就 top 看一下，然后看看日志……"（没有结构、没有术语）

**正面例子**：

> "我会先**分层定位**：先 `top` 看整体是哪类资源紧张——如果 `wa` 高说明是磁盘 IO 问题，如果 `us` 高说明是应用 CPU 问题；然后按 CPU 排序找到具体进程，再看进程内部是哪个线程在消耗，Java 应用可以用 `jstack` 看线程栈；最后根据原因处理——业务高峰扩容、代码问题修代码。"
