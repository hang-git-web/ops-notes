## 一、信号是什么

```text
信号（signal）= 内核或进程发给另一个进程的"异步通知"，本质是软件中断。
进程对信号有三种处理方式：
  ① 默认动作（终止 / 暂停 / 继续 / 忽略 / core dump）
  ② 捕获（自己写 handler 处理，比如"收到 TERM 先把缓存落盘再退出"）
  ③ 忽略（显式忽略；但 SIGKILL、SIGSTOP 无法被捕获或忽略）
```

```bash
kill -l            # 列出所有信号编号和名字（面试前扫一眼）
kill -l 15         # 15 → TERM
```

## 二、常用信号表（背 ★ 的）

| 编号 | 名字 | 触发方式 | 默认动作 | 能捕获吗 | 典型场景 |
| --- | --- | --- | --- | --- | --- |
| ★ 1 | **SIGHUP** | 终端断开 / `kill -1` | 终止 | ✅ | **约定俗成用来"重载配置"**（nginx reload）；`nohup` 就是让它免疫 HUP |
| ★ 2 | **SIGINT** | **Ctrl+C** | 终止 | ✅ | 中断前台程序 |
| 3 | SIGQUIT | Ctrl+\ | 终止 + core | ✅ | 退出并生成 core dump |
| 9 | **SIGKILL** | `kill -9` | **强制终止** | ❌ **不可捕获、不可忽略** | 内核直接杀，最后手段 |
| ★ 15 | **SIGTERM** | `kill`（默认） | 终止 | ✅ | **优雅退出**：先清理资源再停 |
| 17 | SIGCHLD | 子进程结束/暂停时 | 忽略 | ✅ | 父进程靠它回收子进程，处理不当就是**僵尸进程** |
| 18 | SIGCONT | `fg`/`bg`/`kill -18` | 继续 | ✅ | 恢复被暂停的进程 |
| 19 | SIGSTOP | `kill -19` | 暂停 | ❌ **不可捕获** | 强制冻结进程 |
| ★ 20 | **SIGTSTP** | **Ctrl+Z** | 暂停 | ✅ | 挂起前台程序（可 `fg` 恢复）|
| 10 / 12 | SIGUSR1 / SIGUSR2 | 程序自定义 | 终止 | ✅ | nginx：`USR1` 重开日志、`USR2` 平滑升级 |
| 11 | SIGSEGV | 非法内存访问 | 终止 + core | ✅ | 段错误，写代码的常见崩溃 |
| 13 | SIGPIPE | 写一个已关闭的管道 | 终止 | ✅ | `yes \| head -1` 后面那个进程收到的 |

> **选择题记忆法**：**只有 9（KILL）和 19（STOP）不能被捕获/忽略**，其余都可以。

## 三、Ctrl 组合键（★ 答题要一次答全）

| 按键 | 发信号吗 | 信号 / 效果 | 进程状态变化 | 能恢复吗 |
| --- | --- | --- | --- | --- |
| **Ctrl+C** | ✅ | **SIGINT（2）** | 前台进程**终止**（可被捕获改写行为）| ❌ |
| **Ctrl+Z** | ✅ | **SIGTSTP（20）** | 前台进程**暂停**并放到后台 | ✅ `fg`/`bg` 恢复 |
| **Ctrl+D** | ❌ **不是信号** | 表示**输入结束（EOF）**：`read()` 返回 0 | 不影响进程本身 | — |
| Ctrl+\ | ✅ | SIGQUIT（3） | 终止 + core dump | ❌ |
| Ctrl+S / Ctrl+Q | ❌ | 终端流控 | 暂停 / 恢复**屏幕输出**（程序还在跑）| ✅ |

### 3.1 Ctrl+D 要说清楚的三层

```text
① 它不是信号！它是终端把"输入结束"告诉程序（read() 返回 0，即 EOF）。
② 在空行按 Ctrl+D → shell 读到 EOF → shell 退出（logout）。
③ 有输入时按 Ctrl+D → 把这行内容先交给程序（不结束输入），再按一次才结束。
   例：cat 里按 Ctrl+D 结束输入；python 交互里按 Ctrl+D 退出解释器。
```

> **对比记忆**：**Ctrl+C 是"我不想让你跑了"，Ctrl+Z 是"你先歇会儿"，Ctrl+D 是"我说完了"。**

## 四、kill 的用法（不止 kill -9）

```bash
kill 1234                # 默认发 15（SIGTERM）—— 优雅退出
kill -15 1234            # 同上，显式写出来更清楚
kill -2 1234             # 等同 Ctrl+C，中断
kill -9 1234             # 强制杀死，不可捕获
kill -1 1234             # SIGHUP，很多服务约定用它 reload
kill -0 1234             # 不真发信号，只判断进程是否存在（有权限）

kill -l                  # 列出所有信号

# 批量操作
pkill -f "python app.py" # 按命令行匹配杀
killall nginx            # 按进程名杀（名字全匹配）
kill -- -1234            # 给"进程组"发信号（负数 = 进程组 ID）
```

> **标准答法（面经第 4 题）**：
> **"`kill` 默认发 15（SIGTERM），是可捕获的优雅退出，进程可以落盘、关连接；`kill -2` 是 SIGINT，等同 Ctrl+C，也是优雅中断；`kill -9` 是 SIGKILL，不可捕获不可忽略，内核直接杀，进程没有任何清理机会。所以顺序是先 15、等几秒不退出，再上 9。"**

## 五、进程状态（★ 一定会被追问）

```bash
ps aux            # STAT 列
ps -eo pid,stat,comm | grep -E '^ *[0-9]+ (D|Z|T)'
```

| 状态 | 含义 | 常见原因 |
| --- | --- | --- |
| **R** | Running / Runnable（在跑或在等 CPU）| 正常 |
| **S** | Interruptible sleep（可中断睡眠）| **绝大多数进程常态**：等 IO、等事件 |
| **D** | **Uninterruptible sleep（不可中断睡眠）** | 卡在磁盘/NFS/驱动的 IO 上，**不响应信号** |
| **T** | Stopped（暂停）| **收到 SIGSTOP / Ctrl+Z**；被调试器停住 |
| **Z** | Zombie（僵尸）| 子进程已退出，父进程没 `wait` 回收 |
| I | Idle 内核线程 | 基本不用管 |

```text
STAT 里的后缀字母：s = 会话首进程，l = 多线程，+ = 前台进程组，< = 高优先级，N = 低优先级
```

## 六、为什么 `kill -9` 也有杀不掉的时候（★ 高分点）

| 情况 | 原因 | 怎么处理 |
| --- | --- | --- |
| 进程处于 **D 状态** | 卡在内核的 IO 等待里，**信号要等系统调用返回才能处理**，而 -9 也不能打断已经启动的不可中断等待 | 等 IO 超时恢复；查是哪块盘/NFS 慢（`cat /proc/<pid>/stack`、`dmesg`），严重时只能重启 |
| 进程已经是**僵尸 Z** | 它已经死了，只剩进程表项，信号无处可发 | **杀父进程**，让它被 init/PID 1 收养并回收 |
| 是**内核线程** | 不是用户态进程，信号不适用 | 别动 |
| **权限不足** | 非 root 杀别人的进程 → `Operation not permitted` | 用 root 或 sudo |
| 容器里的 **PID 1** | 容器内 1 号进程对未注册的信号会忽略（内核为此有特殊处理）| 用 `docker stop`（先 TERM 后 KILL）或修容器入口 |

## 七、优雅停止与"退出终端程序就死"

### 7.1 服务是怎么被优雅停掉的

```text
systemctl stop nginx
  → systemd 给主进程发 SIGTERM（默认 KillSignal）
  → 等 TimeoutStopSec（默认 90 秒）让进程自己退
  → 还没退就补一个 SIGKILL
```

> 所以"为什么推荐 15 而不是 9"在这里得到闭环：**15 给应用时间做收尾，9 是最后的兜底。**

### 7.2 为什么退出终端程序就没了

```text
关闭终端 → 内核给该终端的前台进程组发 SIGHUP → 程序默认被终止
免疫方式：
  nohup ./run.sh &         # 忽略 SIGHUP，输出重定向到 nohup.out
  ./run.sh &  + disown     # 先后台，再从 shell 的任务表里摘掉
  setsid ./run.sh          # 新会话，彻底脱离终端
  systemd 服务（生产推荐）  # 由 PID 1 托管，和终端无关，还能开机自启
```

## 八、面试可能这么问

**Q：kill -15 和 kill -9 有什么区别？**
A：15 是 SIGTERM，可捕获，属于"请你优雅退出"，进程能保存数据、关闭连接；9 是 SIGKILL，不可捕获不可忽略，内核直接终止进程，没有清理机会，可能丢数据。**实操上先 15，等几秒不退再 9。**

**Q：Ctrl+C、Ctrl+Z、Ctrl+D 有什么区别？**
A：Ctrl+C 发 SIGINT 终止前台进程；Ctrl+Z 发 SIGTSTP 把前台进程暂停并放进后台，可以 `fg` 恢复；**Ctrl+D 不是信号**，它是输入结束（EOF），shell 读到 EOF 会退出，`cat` 之类的程序会结束读取。

**Q：进程挂起后是什么状态？怎么恢复？**
A：状态是 `T`（stopped）。`jobs` 看任务号，`fg %1` 调回前台、`bg %1` 放后台继续跑，也可以直接 `kill -CONT <pid>`。

**Q：`kill -9` 都杀不掉的进程怎么办？**
A：先看状态。如果是 D 状态，说明卡在不可中断的 IO 上，信号要等系统调用返回才能处理，得先解决底层 IO（磁盘/NFS）；如果是 Z 状态，它已经死了，要杀它的父进程；如果是别人的进程，那就是权限问题。

**Q：为什么 nginx 重载用 `kill -HUP` 也可以？**
A：SIGHUP 只是"终端挂断"信号，但它的语义由程序自己定义，nginx、sshd 等约定用 HUP 表示"重读配置"，所以 `nginx -s reload` 本质上也是给 master 进程发 HUP。
