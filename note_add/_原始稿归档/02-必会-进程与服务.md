# 02 必会：进程、服务与文件描述符

> **应届生级别的范围**：会看进程、会用 kill、分清 start/enable 和 reload/restart、知道服务起不来怎么查。
> **不需要**：进程调度算法、CFS、context switch 细节（在 `进阶版/05`）。

---

## 一、进程基础

### 1.1 程序和进程的区别（可能被问）

```text
程序 = 硬盘上的静态文件（比如 nginx 这个文件）
进程 = 程序跑起来之后的实例（在内存里，有 PID）
```

一个程序可以对应多个进程。

### 1.2 怎么查看进程

| 命令 | 用途 | 关键点 |
| --- | --- | --- |
| `ps aux` | **一次性快照** | 找特定进程：`ps aux \| grep nginx` |
| `top` | **实时排行** | **`P` 按 CPU 排序、`M` 按内存排序、`q` 退出** |
| `ps -ef` | 快照，能看到父进程 | 看父子关系 |
| `free -h` | 内存 | 看 `available` |

**`ps aux` 重点看三列**：

```text
USER   PID  %CPU %MEM   ...  COMMAND
       ↑    ↑    ↑
      进程号  CPU占用 内存占用
```

### 1.3 结束进程：kill 和 kill -9（★ 高频）

| 命令 | 信号 | 行为 |
| --- | --- | --- |
| **`kill PID`** | 15（SIGTERM）| **请进程自己体面退出**（可以保存数据、清理临时文件）|
| **`kill -9 PID`** | 9（SIGKILL）| **强制杀死**，进程没机会清理 |

> **标准答法**：**"先 `kill`（15）让进程正常退出，如果不响应再用 `kill -9` 强杀。上来就 -9 可能导致数据没落盘。"**

### 1.4 僵尸进程（出现率很高）

| 问题 | 答案 |
| --- | --- |
| 什么是僵尸进程 | 子进程已经结束，但**父进程没有回收它**，进程表项还留着 |
| 怎么处理 | **杀它的父进程**（僵尸本身已经死了，`kill` 它没用）|
| 怎么找出来 | `ps aux \| grep Z` 或 `ps -eo stat,pid,comm \| grep '^Z'` |

### 1.5 让程序后台运行

```bash
nohup ./run.sh > app.log 2>&1 &     # 退出终端也不中断
jobs                                 # 看后台任务
```

> **面试点**：`&` 只是丢到后台，**退出终端可能会被挂断**；`nohup`（no hang up）才能真正不受终端影响。

## 二、服务管理（systemd）

### 2.1 最常用的一组命令

| 命令 | 作用 |
| --- | --- |
| `systemctl status 服务` | **看状态（最常用）** |
| `systemctl start / stop 服务` | 启动 / 停止 |
| `systemctl restart 服务` | 重启 |
| `systemctl reload 服务` | **重载配置（不中断）** |
| `systemctl enable / disable 服务` | 设置 / 取消**开机自启** |
| `journalctl -u 服务 -n 50` | 看该服务的日志 |

### 2.2 两个必考的区别（★ 高频）

#### ① start vs enable

| 命令 | 管什么 |
| --- | --- |
| `systemctl start nginx` | **现在启动**（重启机器就没了）|
| `systemctl enable nginx` | **开机自启**（现在不一定启动）|

> **标准答法**：**"这是两件独立的事：start 管'现在跑不跑'，enable 管'开机自不自动起'。部署完服务标准做法是两个都执行 `systemctl enable --now nginx`。"**

#### ② restart vs reload

| 命令 | 行为 | 影响 |
| --- | --- | --- |
| `systemctl restart` | 把进程关掉重开 | **会短暂中断服务** |
| `systemctl reload` | 让运行中的进程**重读配置** | **不中断服务** |

> **标准答法**：**"改完 Nginx 配置我会先 `nginx -t` 检查语法，再 `systemctl reload nginx`——reload 只让进程重读配置、不断连接；restart 会重启进程导致短暂断服。生产上能用 reload 就用 reload。"**

### 2.3 看 status 输出

```text
Loaded: loaded (...; enabled; ...)     ← enabled = 开机自启
Active: active (running) since ...     ← active = 正在运行
```

**最健康的状态 = `enabled` + `active (running)`。**

### 2.4 服务起不来怎么查（★ 必背，见 `05` 场景题 4）

```text
① systemctl status 服务        —— 看状态和报错
② journalctl -u 服务 -n 50     —— 看详细日志
③ ss -tlnp | grep 端口         —— 端口是否被占用
④ 检查配置语法（nginx -t）
⑤ 检查目录权限和属主
⑥ 检查磁盘是否满（df -h）      —— 最容易忽略
```

## 三、文件描述符与 ulimit（**知道结论即可**）

### 3.1 什么是文件描述符

```text
文件描述符（fd）= 进程打开文件/连接的"编号"
· 每个进程打开一个文件、一条网络连接，都会占用一个 fd
· Linux 规定：fd 0 是标准输入、1 是标准输出、2 是标准错误
```

### 3.2 报错 `Too many open files` 怎么查（★ 会这个就够）

```bash
# ① 看进程当前用了多少 fd
ls /proc/<PID>/fd | wc -l

# ② 看这个进程的限制是多少
cat /proc/<PID>/limits | grep -i "open files"

# ③ 看具体打开的是什么（是不是连接泄漏）
lsof -p <PID> | head -20

# ④ 处理方式
#    · 如果数量正常但限制太小 → 调大限制
#    · 如果数量持续增长不回落 → 是应用没关连接（代码问题）
```

### 3.3 怎么调大限制（**记住这个坑**）

| 方式 | 说明 |
| --- | --- |
| 临时 | `ulimit -n 65535`（只对当前会话生效）|
| 对登录用户永久 | 改 `/etc/security/limits.conf` |
| **对 systemd 服务** | ⚠️ **不读 limits.conf**！要改 unit 文件的 `LimitNOFILE=65535`，然后 `systemctl daemon-reload && systemctl restart 服务` |

> **面试加分点**：**"改完 `limits.conf` 发现服务还是报 `Too many open files`，是因为 systemd 服务不读 limits.conf，要在 unit 里设 `LimitNOFILE`。"**
