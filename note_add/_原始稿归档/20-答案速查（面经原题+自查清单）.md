## 一、两份面经原题答案（21 题）

### 1.1 第一套：服务器运维 AI 面（15 题）

1. **五阶段**：固件（BIOS/UEFI）上电自检并找启动设备 → GRUB 加载内核和 `initramfs` → 内核初始化并挂载根文件系统 → systemd（PID 1）按 `default.target` 并行拉起服务 → 登录。核心是"控制权交接"：固件 → GRUB → 内核 → systemd。
2. `export` 把 shell 局部变量变成**环境变量**，让子进程能继承；`source` 在当前 shell 进程内解释执行（**PID 不变**、只需读权限、`cd`/`export` 会影响当前 shell）；`bash mod.sh` 是 fork 子进程执行（**PID 变**、只需读权限、不影响当前 shell）；`./mod.sh` 也是新进程，但需要**执行权限**、依赖 shebang；`exec ./mod.sh` 是**替换当前进程映像**（PID 不变，跑完回不到原 shell）。
3. `Ctrl+C` 发 **SIGINT(2)** 终止前台进程；`Ctrl+Z` 发 **SIGTSTP(20)** 暂停前台进程并放入后台（`fg`/`bg` 可恢复）；`Ctrl+D` **不是信号**，表示输入结束（EOF，`read()` 返回 0），空行按它是 shell 退出。
4. `kill -15` = SIGTERM 可捕获，**优雅退出**（能落盘、关连接）；`kill -2` = SIGINT，等同 Ctrl+C，可捕获；`kill -9` = SIGKILL **不可捕获不可忽略**，内核直接杀。所以顺序是：先 15，等几秒不退再 9。
5. `us` 用户态（应用在算）、`sy` 内核态（系统调用/上下文切换）、`ni` 低优先级进程、`id` 空闲、`wa` 等 IO（磁盘瓶颈，不是 CPU 忙）、`hi` 硬中断（网卡收包）、`si` 软中断（协议栈处理）、`st` 被宿主机偷走的时间（超卖）。`100 - id ≈ 总使用率`。
6. **硬链接**=同一个 inode 的另一个名字（删源文件数据还在；不能跨文件系统、不能指向目录）；**软链接**=存放路径的快捷方式（inode 不同；目标删了就断链；可跨分区、可指向目录）。
7. 用 `file 文件名`（读文件头，**不受扩展名影响**）；或看 `ls -l` 第一个字符：`-` 普通文件、`d` 目录、`l` 软链接、`b` 块设备、`c` 字符设备、`s` socket、`p` 命名管道。块设备按块随机读写、可挂载（`/dev/sda`）；字符设备按字节流、不可挂载（`/dev/tty`）。
8. 符号法 `chmod u+x a.sh`、`chmod o-r a.txt`；数字法 r=4/w=2/x=1，三位分别是属主/组/其他人：**755** 目录与脚本、**644** 普通文件、**600** 私钥、777 生产禁用。补充：**能不能删文件看它所在目录的 w 权限**。
9. 控制台加盘 → `lsblk`/`fdisk -l` 确认识别到 `/dev/sdb` → **`fdisk /dev/sdb` 分区**（n→p→1→w）、`partprobe` 刷新分区表 → `mkfs.ext4 /dev/sdb1`（或 xfs）→ `mkdir /data && mount /dev/sdb1 /data` → `blkid` 取 UUID 写 `/etc/fstab` → **`mount -a` 验证**。扩容场景还要扩文件系统（`resize2fs` / `xfs_growfs`）。
10. **OOM**：物理内存和 swap 都回收不出空间时，内核的 OOM Killer 按 `oom_score` 杀进程保住系统。常见原因：内存泄漏、并发/流量激增、堆参数（`-Xmx`）超配、`overcommit` 允许超量分配、swap 太小、容器/cgroup 限制太小、不可回收的内核页/共享内存。**swap** 是磁盘上的内存后备：内存紧张时内核先回收文件页、再换出匿名页，访问时通过 major fault 换回，压力大不大看 `vmstat` 的 `si/so`。
11. **七种**：管道、命名管道、信号、信号量、共享内存、消息队列、套接字。其中**信号和信号量不传数据**（通知/同步）；**共享内存最快**（无拷贝，但要配信号量同步）；**只有 socket 能跨主机**（本机用 Unix socket 更快，如 Nginx↔PHP-FPM、MySQL 本地登录）。
12. 按题目要求写管道 + 重定向就行：注意用绝对路径、变量加引号、必要时 `set -euo pipefail`，先小范围试跑再上定时任务。
13. **并发**=同一时间段内交替处理多个任务（单核也能，如 Nginx 事件循环处理上千连接）；**并行**=同一时刻真正同时执行（必须多核）。**MB vs Mb**：B 是字节、b 是位，1 Byte = 8 bit，所以 100 Mbps = 12.5 MB/s；另外硬盘厂商按 10 进制（1TB ≈ 931GiB）。
14. 访问的页不在物理内存 → CPU 触发**缺页异常** → 内核分配新页/建立映射/从 swap 或文件读入 → 更新页表 → 重新执行刚才的指令；**minor** 代价小（页已在内存），**major** 要读磁盘（代价大）。**mmap** 把文件或匿名内存映射进地址空间，读写内存就等于读写文件，用于动态库加载、大文件读写、共享内存。**内存泄漏排查**：RSS 只涨不落 → `pmap -x`/`smaps_rollup` 看哪类内存涨 → jmap/valgrind/pprof 定位 → 监控 + 内存上限 + 保留现场再重启。
15. 四核 CPU 从 20% 飙到 100%：① `uptime` 看 1/5/15 分钟负载趋势、`top` 看 8 个字段；② `ps aux --sort=-%cpu`/`top -b -n 1` 定位进程；③ `top -H -p PID` 定位线程；④ 按字段判断类型（us 应用算、sy 系统调用、wa 等磁盘、hi/si 网络、st 超卖）；⑤ 深挖（`jstack`/`perf`/`strace`/`iostat -x`）；⑥ 处理（扩容/回滚/杀异常进程）并**前后各留一份现场**。

### 1.2 第二套：秋招 AI 面（6 题）

1. `bash mod.sh`：**父 shell 的 PATH 和当前目录都不变**（子进程改不了父进程环境）；`source mod.sh`：**两个都变**（在当前 shell 内执行）；`exec ./mod.sh`：**PID 不变，但当前 shell 的进程映像被脚本替换**，脚本一结束这个会话就结束，**回不到原来的 shell**。
2. 识别（`lsblk`/`fdisk -l`）→ **分区**（`fdisk` n/p/1/w，或 `parted`）→ `partprobe` **刷新分区表** → 格式化（`mkfs.ext4`/`mkfs.xfs`）→ 建目录并挂载 → `blkid` 取 UUID 写 `/etc/fstab`（加 `nofail`）→ `mount -a` 验证 → 按需 `chown/chmod`。**最容易漏的是"分区"这一步。**
3. `file 文件名`；或 `ls -l` 首字符 7 种：`-` 普通文件、`d` 目录、`l` 软链接、`b` 块设备、`c` 字符设备、`s` socket、`p` 命名管道。被追问时补：块设备按块随机读写、可以挂载、有内核缓冲（`/dev/sda`）；字符设备按字节流读写、一般不缓冲、不能挂载（`/dev/tty`）。
4. 软链接是**存目标路径的"快捷方式"文件**，和目标文件是两个不同的 inode；能跨文件系统、能指向目录；目标被删就变成**断链**（`ls -l` 显红、`file` 报 broken symbolic link）；**权限位没意义**（永远 `lrwxrwxrwx`，看目标文件权限）；覆盖要用 `ln -sf`；发布切版本（`/opt/app/current -> v1.2`）就靠它。
5. `ss -lntp`：**l**=listening 只看监听状态、**n**=numeric 不做名称解析（直接显示 IP 和端口数字）、**t**=tcp 协议（u=udp、x=unix、a=所有状态）、**p**=processes 显示占用端口的进程（需 root 才看得全）。查看连接用 `ss -antp`，过滤用 `ss -tn '( dport = :80 )'`，老写法 `netstat -lntp` 参数含义相同。
6. 三种理解：① **谁在监听**：`ss -lntp | grep :80`、`lsof -i :80`（重点看是 `0.0.0.0:80` 还是 `127.0.0.1:80`）；② **有哪些连接**：`ss -tn '( dport = :80 )'`、按来源统计 `ss -tn | awk '{print $5}' | sort | uniq -c | sort -rn`；③ **怎么让程序监听**：服务配置 `listen 80`，1024 以下端口需要 root 或 `CAP_NET_BIND_SERVICE` 能力，临时测试可用 `nc -l 80`。连不上按"监听 → 监听地址 → 防火墙 → 客户端实测 → 抓包"排查。

## 二、各章自查清单答案要点（135 项）

### 01b 重定向、软硬链接、环境变量、目录结构（7 项）

1. `>` 是覆盖写入，`>>` 是追加（**写日志必须用 `>>`**）；`2>&1` 是把标准错误重定向到"标准输出当前所在的位置"，所以要写在重定向**后面**：`命令 > f 2>&1`。
2. 硬链接=同一 inode 的另一个名字，删掉源文件数据还在，不能跨分区、不能指向目录；软链接=存路径的快捷方式，删掉源文件就失效，可跨分区、可指向目录。
3. 软链接权限位没意义（永远是 `lrwxrwxrwx`，看目标文件权限）；目标被删/移走后 `ls -l` 一般显红、`file` 报 broken symbolic link（`test -L` 真、`test -e` 假）；覆盖已有链接用 `ln -sf`。
4. "command not found" 通常是**软件安装目录不在 PATH 里**：把目录加进 PATH（写 `~/.bashrc` 或 `/etc/profile` 后 `source`），或直接用绝对路径调用。
5. `/etc` 放配置文件（nginx.conf、my.cnf），`/var` 放可变数据：日志在 `/var/log`、还有缓存和网站数据。
6. Ctrl+C 发 SIGINT 结束前台进程；Ctrl+Z 发 SIGTSTP 把前台进程**暂停**并放入后台，可 `fg`/`bg` 恢复。
7. 退出终端继续跑：`nohup ./run.sh > app.log 2>&1 &`；也可以 `disown`、`setsid`；生产推荐写成 systemd 服务。

### 01 必会：常用命令、权限与用户（7 项）

1. `find` 在磁盘上按文件名/属性找文件，`grep` 在文件内容里找文字；常组合使用：`find /etc -name "*.conf" | xargs grep listen`。
2. `df -h` 看分区剩余容量与使用率，`du -sh 目录` 看目录实际占用；排查磁盘满要先用 df 定位分区、再用 du 逐层找。
3. 对目录：`r` 能列出文件名（ls）、`w` 能在目录里创建/删除/改名文件、`x` 能进入目录（cd）；只有 r 没有 x 能看名字但进不去。
4. 755 用于目录和可执行脚本；644 用于普通文件和配置；600 用于私钥、口令文件；777 生产禁用。
5. 能不能删一个文件看的是**它所在目录的 w 权限**，不是文件自己的权限（删除本质是"从目录里移除这个名字"）。
6. SUID：执行时临时以文件属主身份运行，典型例子 `/usr/bin/passwd`（让普通用户能改 `/etc/shadow`）；SGID 用在目录上则新建文件继承目录的组；Sticky 让目录内文件只有属主能删（`/tmp`）。
7. `usermod -aG wheel 用户名`（CentOS；Ubuntu 是 sudo 组），`id 用户名` 验证；注意少写 `-a` 会覆盖用户原有组。

### 02 必会：进程、服务与文件描述符（7 项）

1. `ps aux` 是一次性快照（适合 grep 定位），`top` 是实时排行（P 按 CPU、M 按内存、q 退出）。
2. `kill`（15 SIGTERM）可被捕获，给进程清理资源后优雅退出的机会；`kill -9`（SIGKILL）不可捕获，内核直接杀。先 15 等几秒不退再 9，避免数据没落盘。
3. 僵尸进程=子进程已退出但父进程没有 `wait()` 回收，进程表项残留；它本身已经死了、杀不掉，要**杀它的父进程**。
4. `start` 管"现在启动"，`enable` 管"开机自启"，是两件独立的事，都要做：`systemctl enable --now 服务`。
5. `reload` 让运行中的进程重读配置、**不中断连接**；`restart` 会重启进程导致短暂断服；改配置优先 reload（Nginx 先 `nginx -t` 再 reload）。
6. 顺序：`systemctl status` 看状态 → `journalctl -u 服务 -n 50` 看日志 → `ss -tlnp` 看端口是否被占用 → 检查配置语法 → 检查目录权限和属主 → `df -h` 看磁盘是否满。
7. `ls /proc/PID/fd | wc -l` 看当前 fd 数，`cat /proc/PID/limits` 看限制，`lsof -p PID` 看具体打开了什么；**systemd 服务不读 `limits.conf`**，要在 unit 里设 `LimitNOFILE` 再 `daemon-reload`。

### 03 必会：磁盘、挂载与 RAID（8 项）

1. `df` 看分区还剩多少（`df -h` 看使用率），`du` 看目录/文件实际占了多少；排查磁盘满先 `df -h` 定位分区，再 `du -sh /* | sort -h` 逐层找。
2. ① `df -h` 定位分区；② `du -sh /* | sort -h` 逐层找大目录；③ 判断是日志/备份/垃圾后清理或转移；④ 日志类配置 logrotate 治本；⑤ 特例 `df -i` 查 inode；⑥ 特例 `lsof | grep deleted` 看被删除但仍被占用的文件。
3. "df 有空间却写不进"通常是两种：**inode 用满**（`df -i`）或**文件被删除但仍被进程占用**（`lsof | grep deleted`）。
4. 新硬盘五步：`lsblk` 认盘 → `fdisk` 分区（n/p/1/w，之后 `partprobe` 刷新）→ `mkfs.ext4` 格式化 → `mkdir` + `mount` 挂载 → 写 `/etc/fstab` 并 `mount -a` 验证。
5. fstab 写错（UUID/设备名或选项不对）会导致开机进 emergency mode；改完必须 `mount -a` 验证，改前先备份，用 **UUID** 并加 **`nofail`** 更稳。
6. RAID 0 容量=全部之和、可坏 0 块；RAID 1 容量=单盘、可坏 N−1；RAID 5 容量=(N−1)×单盘、可坏 1 块；RAID 10 容量=N/2×单盘、每组可坏 1 块（性能与容错兼顾）。
7. 4 块 1T 做 RAID 5：**(4−1)×1T = 3T** 可用（牺牲一块盘的容量存校验）。
8. RAID 只能防"磁盘物理损坏"，**防不了误删、病毒、逻辑损坏**（这些会被同步到所有盘）；RAID 保"服务不中断"，备份保"数据能恢复"，所以 RAID 不能代替备份。

### 04 必会：网络基础、子网计算与 TCP（10 项）

1. IP 是设备在网络里的地址；掩码区分网络位和主机位（判断是否同网段）；网关是出网出口；DNS 把域名解析成 IP。
2. `192.168.1.100/26`：块大小 256−192=64，100 落在 64~127 → **网络地址 192.168.1.64、广播 192.168.1.127、可用 65~126、主机数 2^6−2=62**。
3. /24=255.255.255.0、/25=128、/26=192、/27=224、/28=240、/29=248、/30=252（可用主机数依次 254/126/62/30/14/6/2）。
4. ping 只测**网络层连通**（ICMP），telnet/nc 测**端口是否可连**；服务检测要用端口测试，因为 ping 通不代表服务在监听或应用正常。
5. 本机通、外部不通：① 看监听地址是 `0.0.0.0` 还是 `127.0.0.1`；② 看防火墙是否放行；③ 看 SELinux；④ 从客户端 `telnet IP 端口` 确认；⑤ 还不行就抓包。
6. 三次握手：SYN → SYN+ACK → ACK；三次是为了让**双方都确认**"我发得出、你收得到，你发得出、我收得到"——两次的话服务端无法确认客户端收到了它的 SYN+ACK。
7. TIME_WAIT 是**主动关闭方**的正常状态（等 2MSL 保证最后的 ACK 能到达），多了会占本地端口，靠长连接/连接池减少短连接；CLOSE_WAIT 是**被动方应用没调 `close()`**，属代码问题，调内核参数没用。
8. `ss -s` 看总体统计（estab/timewait 各多少）；按状态统计用 `ss -ant | awk '{print $1}' | sort | uniq -c`。
9. `ss -lntp`：**l**=listen 只看监听、**n**=numeric 不解析名称直接显示数字、**t**=tcp 只看 TCP、**p**=process 显示进程（需 root）。
10. 三种理解：① 谁在监听 `ss -lntp | grep :80` / `lsof -i :80`；② 有哪些连接 `ss -tn '( dport = :80 )'` / 按来源 `ss -tn | awk` 统计；③ 让程序监听：配置 `listen 80`，1024 以下端口需要 root 或 `CAP_NET_BIND_SERVICE`。

### 05 必会：内存与故障排查（7 项）

1. `buff/cache` 大**不是**内存不足：Linux 用空闲内存缓存文件数据来加速，应用需要时会自动回收；判断内存够不够要看 `available`。
2. 判断内存是否充足看 **`available`**（不是 free、也不是 used）；真正紧张信号是 `vmstat` 里 **`si/so` 持续非 0**（在换页）。
3. `us` 高=应用自己在算（死循环、正则、GC）；`sy` 高=系统调用/上下文切换太多；`wa` 高=在等磁盘 IO，**不是 CPU 的问题**（加 CPU 没用）。
4. 四道场景题都按"**先定位是哪类资源 → 再用工具看指标 → 定位到进程/线程 → 最后处理**"来说，别一上来就报命令。
5. `vmstat`：`r`=运行队列长度（CPU 排队）、`b`=阻塞进程数（多是 D 状态、等 IO）、`si/so`=换入换出速率（内存压力）。
6. `iostat -x` 的 `%util` 是设备"忙着处理 IO"的时间占比，接近 100% 说明磁盘是瓶颈；配合 `await`（平均等待时间）一起看。
7. 答题结构：**先说方向（先定位资源类型）→ 再说具体命令和指标 → 最后说判断标准和怎么处理**。

### 06 必会：日志、定时任务与系统信息（7 项）

1. 日志在 `/var/log`：`messages`（系统通用，RHEL 系）、`syslog`（Debian 系）、`secure`（登录/安全）、`cron`（定时任务）、`dmesg` 或 `journalctl -k`（内核/硬件），应用日志在自己目录。
2. `tail -f` 实时跟踪新写入的内容（`-F` 还能跟住轮转后的新文件）；`grep -C 3 "ERROR" app.log` 显示匹配行前后各 3 行。
3. logrotate 自动**切割、压缩、删除**旧日志，并可在轮转后给服务发信号重新打开日志文件，防止单个日志把磁盘写满。
4. 轮转后应用还持有**原来的文件句柄**，会继续往已改名的文件里写、空间不释放；发信号（如 `USR1`/`HUP`）是让它重新打开新的日志文件。
5. 每天凌晨 3 点：`0 3 * * *`（顺序是 分 时 日 月 周）。
6. `*/5 * * * *` 是**每 5 分钟**执行一次；`5 * * * *` 是**每小时的第 5 分钟**执行一次。
7. 排查：`systemctl status crond` → `/var/log/cron` 有没有执行记录 → 脚本有没有执行权限和 `#!/bin/bash` → **PATH/环境变量**（cron 环境很干净，要用绝对路径）→ `%` 要转义 → 手动 `bash -x` 跑一遍。

### 07 了解级：安全、容器、备份与监控（8 项）

1. `firewall-cmd --permanent --add-port=80/tcp && firewall-cmd --reload`（临时测试可以不加 `--permanent`）。
2. firewalld 是管理前端，底层最终还是 nftables/iptables 规则（`iptables -L -n` 能看到）；"放行了还是不通"要查：监听地址、SELinux、云安全组/上层防火墙、服务是否真的在监听。
3. SELinux 三种模式：`enforcing`（强制拦截）、`permissive`（只记录不拦）、`disabled`（关闭）。
4. 判断是不是 SELinux 拦的：`getenforce` 看模式 → `setenforce 0` 临时关闭验证是否立刻恢复 → `ausearch -m avc -ts recent` 看拒绝日志 → 用 `restorecon`/`semanage` 修正上下文或加策略。
5. 容器 vs 虚拟机：容器共享宿主机内核（靠 namespace 隔离 + cgroup 限制）、体积 MB 级、秒级启动；虚拟机有独立 Guest OS、体积 GB 级、分钟级启动，隔离性更强。
6. **namespace 管隔离**（PID/NET/MNT/UTS/IPC/USER），**cgroup 管资源限制**（CPU/内存/IO/进程数）。
7. 3-2-1：**3 份数据、2 种介质、1 份异地**；备份必须做恢复演练，没验证过的备份不算备份。
8. RAID 只防磁盘物理损坏，误删/病毒/逻辑损坏会被同步到所有盘，所以不能替代备份：RAID 保"不中断"，备份保"能恢复"。

### 09 补充：Linux 启动流程（7 项）

1. 五阶段：固件（BIOS/UEFI）上电自检并找启动盘 → GRUB 加载内核与 initramfs → 内核初始化并挂载根文件系统 → systemd（PID 1）按 target 并行拉起服务 → 登录。每阶段"谁在干活"：固件 / GRUB / 内核 / systemd / getty 与 sshd。
2. initramfs 是**临时的内存文件系统**，解决"要用驱动才能挂根分区，但驱动又存放在根分区上"的鸡生蛋问题。
3. PID 1 就是 systemd：负责按依赖启动服务、**收养孤儿进程（收尸）**、响应 `systemctl`；容器里的 1 号进程也是这个角色（所以入口脚本常用 `exec`）。
4. `rescue.target` 对应单用户/救援模式，`multi-user.target` 对应旧 runlevel 3（多用户命令行），`graphical.target` 对应 5。
5. `systemd-analyze blame` 找最慢的服务，`journalctl -b` 看本次开机日志（`-b -1` 看上次），再配合 `systemctl --failed` 看失败的服务。
6. `rd.break` 步骤：GRUB 菜单按 `e`，在 linux 行尾加 `rd.break` → Ctrl+X 启动 → `mount -o remount,rw /sysroot` → `chroot /sysroot` → `passwd root` → `touch /.autorelabel` → `exit` → `reboot`。
7. fstab 写错的救援：进 emergency mode 或 `rd.break` → `mount -o remount,rw /`（或 `/sysroot`）→ 注释/改回正确的 UUID → `mount -a` 验证 → `reboot`；预防用 UUID、加 `nofail`、改前备份、改后验证。

### 10 补充：export、source、子 shell（9 项）

1. shell 局部变量只有当前 shell 能用；`export` 后成为**环境变量**，子进程才能继承（典型用途是把安装目录加进 PATH）。
2. `source` 在当前 shell 进程内执行（PID 不变、只需读权限、`cd`/`export` 会影响当前 shell）；`bash a.sh`/`./a.sh` 另起进程（PID 变、不影响当前 shell；`./` 还需要 x 权限并依赖 shebang）。
3. `exec` 不新建进程，而是**用新程序覆盖当前 shell 的进程映像**（PID 不变）；脚本跑完进程就结束，**回不到原来的 shell**；而 `source` 会把 `cd`/`export` 留在当前 shell，`bash` 什么都留不下。
4. `exec >> /var/log/x.log 2>&1` 把整段脚本的输出重定向；容器入口脚本用 `exec "$@"` 让应用成为 PID 1，才能正确接收 `docker stop` 发的 SIGTERM。
5. `bash a.sh` 只是把文件当输入读，**有读权限就行**；`./a.sh` 要内核直接执行文件，**必须有执行权限 x**。
6. 另起一个 bash 进程执行脚本时 `$$` 是新进程 PID；但在 bash 的**子 shell**（括号、管道、命令替换）里 `$$` 仍是外层 shell 的 PID，要看真实 PID 用 `$BASHPID`。
7. cron 的 PATH 很干净、也不读 `~/.bashrc`，所以脚本里要用绝对路径，或在开头显式 `source /etc/profile` / 自己设置 PATH。
8. `su tom` 只切用户、环境基本不变；`su - tom` 是完整登录，会读 profile 并重置 HOME/PATH 等环境。
9. 管道两侧各自是**子 shell**，子 shell 里的变量不会回到父 shell；改成 `while ... done < file`（输入重定向）或用 `{ ... }` 在当前 shell 执行就好了。

### 11 补充：信号、Ctrl 组合键与进程状态（8 项）

1. 1=SIGHUP（挂断，常约定为重载配置）、2=SIGINT（Ctrl+C）、9=SIGKILL（强杀）、15=SIGTERM（优雅退出）、18=SIGCONT（继续）、19=SIGSTOP（暂停）、20=SIGTSTP（Ctrl+Z）。
2. 只有 **9（SIGKILL）和 19（SIGSTOP）** 不可被捕获或忽略，其余信号都可以写 handler 或忽略。
3. Ctrl+C=SIGINT 终止前台进程；Ctrl+Z=SIGTSTP 暂停并放入后台（`fg` 恢复）；**Ctrl+D 不是信号**，是输入结束（EOF），shell 读到就退出。
4. 15 可捕获，进程能先落盘、关连接再退出；9 由内核直接终止，没有清理机会、可能丢数据，所以先 15 等几秒不退再 9。
5. R=运行/就绪、S=可中断睡眠（绝大多数进程的常态）、D=不可中断睡眠（卡在 IO，不响应信号）、T=暂停（SIGSTOP/TSTP）、Z=僵尸。
6. `kill -9` 也杀不掉的几种：D 状态（等 IO 恢复）、Z 僵尸（杀父进程）、权限不足（用 root）、容器里的 PID 1（用 `docker stop`）。
7. `systemctl stop` 先发 **SIGTERM**，等 `TimeoutStopSec`（默认 90 秒）让进程自己退，超时才补 **SIGKILL**。
8. `nohup` 让进程忽略 SIGHUP 并配合 `&` 后台跑；`disown` 把任务从 shell 任务表摘掉；`setsid` 新建会话彻底脱离终端；systemd 托管最稳（还能开机自启）。

### 12 补充：文件类型、inode 与文件系统（8 项）

1. `file 文件名` 读文件头判断真实类型，**不受扩展名影响**（jpg 改名成 txt 仍识别为图片）；`file -i` 还能看 MIME 类型。
2. `ls -l` 首字符 7 种：`-` 普通文件、`d` 目录、`l` 符号链接、`b` 块设备、`c` 字符设备、`s` socket、`p` 命名管道（FIFO）。
3. inode 存文件元数据（权限、属主/组、大小、三个时间、数据块指针、链接计数），**不含文件名**；目录里存的是"文件名 → inode 号"的映射。
4. 删掉一个硬链接只是**链接计数减 1**，inode 还被其他名字引用，所以数据还在；链接计数就是 `ls -l` 的第二列，减到 0 才真正释放数据块。
5. inode 编号只在**单个文件系统内唯一**，跨分区找不到对应 inode，所以硬链接不能跨文件系统；软链接存的是路径，所以可以跨。
6. `df -i` 看 inode 使用率；inode 用尽的表现是"`df -h` 看还有空间，但创建新文件报 `No space left on device`"。
7. **mtime** 是内容修改时间（`find -mtime` 用它）；**ctime** 是元数据（权限/属主/链接数）变更时间；**atime** 是访问时间（现代系统多用 relatime 减少写）。
8. `/dev/sdb` 是**整块磁盘**，`/dev/sdb1` 是它上面的**一个分区**；分区表操作、`mkfs`、`mount` 都作用在分区上。

### 13 补充：磁盘扩容与挂载实操（8 项）

1. 七步：识别（`lsblk`/`fdisk -l`）→ 分区（`fdisk` n/p/1/w）→ 刷新分区表（`partprobe`）→ 格式化（`mkfs.ext4`/`mkfs.xfs`）→ 挂载（`mkdir` + `mount`）→ 写 fstab（UUID + `nofail`）→ `mount -a` 验证。
2. `fdisk` 里 `n` 新建分区、`d` 删除分区、`p` 打印当前分区表、`w` 保存并生效、`q` 不保存退出（`m` 是帮助）。
3. `partprobe` 让内核重新读取分区表；不做的话分区建好了但 `/dev/sdb1` 设备节点不出现，后面 `mkfs` 会报找不到设备。
4. fstab 六字段：**设备（UUID）、挂载点、文件系统类型、挂载选项、备份标记、fsck 顺序**；用 UUID 是因为盘符可能变；加 `nofail` 是为了挂不上也不阻塞开机。
5. ext4 扩文件系统用 `resize2fs /dev/sda3`（写**设备名**），xfs 用 `xfs_growfs /data`（写**挂载点**）；XFS 设计上**不支持缩容**，只能备份重建。
6. LVM 扩容三步：`pvresize`（底层盘变大时）→ `lvextend -l +100%FREE /dev/vg/lv` → `resize2fs`（ext4）或 `xfs_growfs`（xfs）。
7. 扩完容量 `df` 没变：① 只扩了分区、没扩文件系统；② `df` 看的挂载点不是这个分区（或挂载被覆盖）；③ 其实扩的是另一个设备。
8. 同第 09 章：进 emergency/`rd.break` → `mount -o remount,rw /` → 改回正确的 UUID → `mount -a` 验证 → `reboot`。

### 14 补充：虚拟内存、缺页中断、mmap、OOM 与内存泄漏（9 项）

1. 每个进程有**独立的虚拟地址空间**，按页（通常 4KB）通过**页表**映射到物理内存，TLB 缓存映射关系；好处是隔离、地址连续、可换出到 swap、可共享。
2. **RSS** 是真正驻留在物理内存里的量（排查内存看它）；**VSZ/VIRT** 是虚拟地址空间总量（含未分配和映射文件，参考价值低）；**SHR** 是其中可共享的部分。
3. 缺页中断：访问的页不在内存 → CPU 触发缺页异常 → 内核判断是分配新页、建立映射还是从 swap/文件读入 → 更新页表（刷新 TLB）→ 返回后**重新执行刚才的指令**。
4. **minor** 缺页是页已在物理内存、只是还没建立映射（代价小，如首次访问堆、写时复制）；**major** 缺页必须读磁盘（swap 或文件），代价大，多了系统会明显变卡。
5. mmap 把文件或匿名内存**映射进进程地址空间**，读写内存就等于读写文件；用途：动态库加载、大文件随机读写、进程间共享内存；查看用 `/proc/PID/maps`、`pmap -x`。
6. swap 是磁盘上的内存后备：内存压力大时先回收文件页、再换出匿名页，访问时通过 major fault 换回；`swappiness` 控制换出匿名页的倾向（默认 60，数据库常调到 1~10）。
7. OOM 原因分三类：**应用层**（内存泄漏、并发激增、一次加载大文件、堆参数超配）、**内核参数**（overcommit 允许超额分配、回收参数不当）、**资源规划**（swap 太小、容器 limit 太小、共享内存/锁定内存不可回收）。
8. OOM Killer 按 `oom_score`（主要是 RSS，结合 `oom_score_adj`）挑进程；查用 `dmesg -T | grep -i oom`、`journalctl -k`、容器看 OOMKilled；防就是限制内存（MemoryMax/容器 limit/`-Xmx`）+ 加内存或 swap + 监控告警。
9. 排查内存泄漏：`top`/`ps` 找到进程 → 采样 RSS 看是否**只涨不落** → `pmap -x`/`smaps_rollup` 看哪类内存涨 → Java 用 `jmap`、C 用 `valgrind`、Go 用 `pprof` → 运维侧监控 + 内存上限 + 保留现场（`gcore`）后再重启。

### 15 补充：Linux 七种进程间通信方式（8 项）

1. 七种：**管道、命名管道、信号、信号量、共享内存、消息队列、套接字（socket）**。
2. 不传数据的是**信号**（异步通知，只带编号和少量信息）和**信号量**（计数器，用于同步互斥）。
3. **共享内存最快**：多个进程映射同一块物理内存，读写不需要在用户态和内核态之间拷贝；代价是没有内置同步，要自己配信号量/锁。
4. 只有 **socket 能跨主机**；Unix domain socket 走文件系统路径、用于本机进程间通信（比 TCP 少走协议栈、更快）；TCP/UDP socket 用于跨主机。
5. 管道是匿名的、只能用于有亲缘关系的进程（靠继承 fd）；命名管道在文件系统里有名字（`mkfifo`），任意进程都能打开；两者都是半双工字节流。
6. `ipcs -m` 看共享内存、`ipcs -q` 看消息队列、`ipcs -s` 看信号量；`ipcrm -m/-q/-s <id>` 清理残留；`/dev/shm` 是 POSIX 共享内存常见位置。
7. 例：Nginx 转发 PHP-FPM 用 Unix socket（如 `/run/php-fpm.sock`）；MySQL 本地登录走 `mysql.sock`，远程连接走 TCP。
8. 共享内存本身没有同步机制，多进程并发读写会产生竞态，所以要配信号量/互斥锁来保证互斥和顺序。

### 16 补充：top 字段详解与高 CPU 实战排查（8 项）

1. `us` 用户态、`sy` 内核态、`ni` 低优先级、`id` 空闲、`wa` 等 IO、`hi` 硬中断、`si` 软中断、`st` 被宿主机偷走；`100 - id` 约等于总使用率。
2. 网卡收到包先触发**硬中断（hi）**，内核把它标记为待处理的**软中断（si）**由协议栈处理，所以大流量/大量小包会让 hi 和 si 一起升高。
3. top 里 `1` 展开每个核、`P` 按 CPU 排序、`M` 按内存排序、`H` 显示线程、`c` 显示完整命令行（`q` 退出、`k` 杀进程、`W` 保存配置）。
4. 用 `nproc` 看核数，load 接近核数算跑满、超过 2 倍要处理；注意 load 还包含 D 状态进程，**不等于 CPU 使用率**。
5. load 高 CPU 低：磁盘/NFS IO 卡住（`b` 大、`wa` 高）、内存换页（`si/so` 非 0）、被 cgroup 限流、云主机被超卖（`st` 高）。
6. `vmstat`：`r`=运行队列长度、`b`=阻塞进程数（多为 D 状态）、`cs`=上下文切换次数、`si/so`=换入换出速率。
7. 六步：确认现象（`uptime`/`top`）→ 定位进程（`ps aux --sort=-%cpu`）→ 定位线程（`top -H -p`）→ 按字段判类型（us/sy/wa/hi-si/st）→ 深挖（`jstack`/`perf`/`strace`/`iostat`）→ 处理并验证。常见真凶：死循环、频繁 GC、定时任务撞车、被压测/挖矿、慢 SQL。
8. 四核上单线程死循环最多只能吃 25%（一个核），所以必须用 `top -H -p`（或 `ps -L`）看到线程级占用，才能定位到具体线程。

### 17 补充：概念辨析（9 项）

1. **并发**是同一时间段内交替处理多个任务（单核也能做，如 Nginx 事件循环处理上千连接）；**并行**是同一时刻真正同时执行（必须多核，如 4 核跑 4 个计算线程）。
2. `b` 是位、`B` 是字节，1 Byte = 8 bit，所以 **100 Mbps ÷ 8 = 12.5 MB/s**。
3. 硬盘厂商按 10 进制（1TB = 1000⁴ 字节），系统按 2 进制（1TiB = 1024⁴），1000⁴ ÷ 1024³ ≈ 931，所以 1TB 盘显示 931GiB。
4. 进程=独立地址空间、切换要换页表刷 TLB、崩溃互不影响；线程=共享进程地址空间、只独享栈和寄存器、切换更轻、通信方便但要加锁、一个线程崩整个进程挂；协程=用户态调度、栈极小、数量可达几十万（goroutine）。
5. 线程共享同一个地址空间，切换时**不用切换页表和刷新 TLB**，只要保存/恢复寄存器和栈，所以比进程切换快。
6. buffer 是为解决速度不匹配的**写缓冲**（如写盘前攒批），cache 是为提高命中率的**读缓存**（如 page cache）；`free` 里合并显示成 `buff/cache`，都属于**可回收**内存。
7. 阻塞/非阻塞说的是**调用方要不要一直等**，同步/异步说的是**结果怎么通知**；五种 IO 模型：阻塞 IO、非阻塞 IO、IO 多路复用（select/poll/epoll）、信号驱动 IO、异步 IO（io_uring），前四种都算同步 IO。
8. `sendfile` 让数据从磁盘经内核缓冲**直接送到网卡**，省掉了经过用户态的那一趟拷贝（普通方式要 4 次拷贝、4 次上下文切换），所以 Nginx 传静态文件更快。
9. 用户态权限受限，访问硬件和内核资源必须通过**系统调用**陷入内核态（每次切换都有开销）；`top` 里的 `sy` 就是执行内核代码（含系统调用）的时间。
