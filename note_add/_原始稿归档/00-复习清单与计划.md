## 二、必会 12 条（逐条打勾）

### 【命令类】

- [ ] **1. 常用文件命令**
  `ls` `cd` `cp` `mv` `rm` `mkdir` `find` `grep` `tar` `vim`
  **要会说**：`find` 按名字找文件，`grep` 在文件内容里找；`cp -r` 复制目录；`rm -rf` 不可恢复

- [ ] **1.5 重定向、软硬链接、环境变量**（★ 同样是必考基础）
  **重定向**：`>` 覆盖、`>>` 追加（**写日志必须用 `>>`**）、`2>&1` 把错误也写进去、`|` 管道
  **软硬链接**：硬链接 = 同一 inode 的另一个名字（删源文件仍可用）；软链接 = 路径快捷方式（删源文件就失效）
  **环境变量**：`echo $PATH`；"命令找不到"通常是 PATH 没包含安装目录
  **目录结构**：`/etc` 放配置、`/var/log` 放日志、`/proc` 是内核状态
  → 详见 `01b-补充-重定向、链接与目录结构.md`

- [ ] **2. 权限模型**
  `rwx` 对**文件**：读内容 / 改内容 / 执行
  `rwx` 对**目录**：列文件名 / 增删改名 / **进入目录（cd）**
  `chmod 755`（目录、脚本）、`chmod 644`（普通文件）、`chown 用户:组 文件`
  `umask` 概念：新建文件权限 = 最大权限 − umask（目录 777−022=755，文件 666−022=644）

- [ ] **3. 用户与组**
  `useradd` / `usermod -aG` / `passwd` / `id`
  `wheel` 组（CentOS）→ 加入后才能用 `sudo`

### 【概念类】

- [ ] **4. 进程**
  `ps aux` 看快照、`top` 看实时排行（**P 按 CPU、M 按内存、q 退出**）
  **`kill`（信号 15，请进程退出）vs `kill -9`（强杀）—— 先 15 后 9**
  僵尸进程：子进程结束了但父进程没回收；**杀父进程才能清掉**

- [ ] **5. 服务管理**
  **`systemctl start`（现在启动）vs `systemctl enable`（开机自启）—— 两件事，都要做**
  **`reload`（重读配置不断服务）vs `restart`（重启会短暂中断）—— 改配置优先 reload**
  `systemctl status` 看状态、`journalctl -u 服务` 看日志

- [ ] **6. 磁盘**
  **`df -h`（看分区容量）vs `du -sh`（看目录占用）—— 高频题，别说混**
  **磁盘满了怎么查**（见下面场景题 3）

- [ ] **7. 网络基础**
  IP（地址）、掩码（分网段）、网关（出口）、DNS（域名转 IP）
  **子网计算**（一定会考，见 `04-必会-网络与TCP.md`）
  `ping`（连通）、`telnet IP 端口`（端口通不通）、`ss -tlnp`（看监听端口和进程）

- [ ] **8. 日志**
  日志在 `/var/log/`：`messages`（系统）、`secure`（登录/安全）、`cron`（定时任务）
  `tail -f` 实时看日志
  **logrotate = 日志轮转**：自动切割、压缩、删除旧日志，**防止日志把磁盘写满**

- [ ] **9. 定时任务**
  `crontab -e` 编辑、`crontab -l` 查看
  **五颗星**：`分 时 日 月 周`
  **`*/5 * * * *` 是每 5 分钟；`5 * * * *` 是每小时第 5 分钟 —— 高频坑**

### 【项目类】

- [ ] **10. 讲清楚你做过的项目**（★ 这是你最大的优势）


## 三、四道场景题：标准答法（★ 今天必须背）

> **答题通用结构**：先给结论/方向 → 再说具体命令 → 最后说判断标准

### 场景题 1：服务器 CPU 使用率 100%，你怎么查？

```text
① 先用 top 找出是哪个进程（按 P 键按 CPU 排序），记下 PID
② 再看是什么原因导致的：
   · us 高 → 应用自己在算（死循环、正则、频繁 GC）
   · sy 高 → 系统调用/上下文切换太多
   · wa 高 → 其实是在等磁盘 IO，不是 CPU 的问题
③ 深入到进程内部：
   · Java 应用 → jstack <pid> 看线程栈
   · 通用 → top -H -p <pid> 看是哪个线程在占 CPU
④ 最后处理：业务高峰就扩容；代码 bug 就修；不该跑的进程就杀掉
```

### 场景题 2：内存不够（或内存快满了）怎么查？

```text
① free -h —— 重点看 available（不是看 free，也不是看 used）
② 如果 buff/cache 很大 —— 那是缓存，不是内存不足（可回收）
③ vmstat 1 —— 看 si/so（换入换出），持续非 0 才说明真的缺内存
④ ps aux --sort=-%mem | head —— 找出占内存最大的进程
⑤ dmesg | grep -i oom —— 看有没有进程被 OOM 杀掉过
```

### 场景题 3：磁盘满了怎么查？

```text
① df -h —— 先确认是哪个分区满了
② du -sh /* | sort -h —— 在该分区里逐层找大目录
③ 找到大文件后判断是日志、备份还是垃圾，再清理或转移
④ 如果是日志 → 清理并配置 logrotate 自动轮转（治本）
⑤ 特例：df 显示有空间但写不进 → df -i 查 inode 是否用满
⑥ 特例：删了文件空间没释放 → lsof | grep deleted，重启对应进程
```

### 场景题 4：服务起不来 / 端口访问不通，怎么查？

```text
① systemctl status 服务 —— 看状态和错误提示
② journalctl -u 服务 -n 50 —— 看完整日志
③ ss -tlnp | grep 端口 —— 端口有没有被占用、服务有没有监听
④ 检查配置文件语法（如 nginx -t）
⑤ 检查目录权限和属主（数据目录、日志目录）
⑥ 检查磁盘是否满（df -h）—— 最容易忽略的一条
⑦ 如果是"本机能访问、外部不能"：
   · 先看监听地址是 0.0.0.0 还是 127.0.0.1
   · 再看防火墙（firewall-cmd --list-all）
```
