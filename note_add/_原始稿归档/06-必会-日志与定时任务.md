## 一、日志

### 1.1 日志放在哪

**系统日志统一放在 `/var/log/` 下**：

| 文件 | 内容 |
| --- | --- |
| `/var/log/messages` | **系统主日志**（服务运行、系统消息）|
| `/var/log/secure` | **安全日志**（登录、sudo）★ CentOS |
| `/var/log/auth.log` | 同上（Ubuntu 是这个）|
| `/var/log/cron` | **定时任务执行记录** |
| `/var/log/dmesg` | 内核/硬件日志 |
| `/var/log/nginx/access.log` | 应用日志 |

### 1.2 怎么看日志（**四个命令**）

```bash
cat /var/log/messages            # 小文件直接看
less /var/log/messages           # 大文件用 less（可上下翻、/ 搜索、q 退出）
tail -n 50 /var/log/messages     # 看最后 50 行
tail -f /var/log/nginx/access.log    # ★ 实时跟踪（最常用）
```

**过滤日志**：

```bash
grep -n "ERROR" app.log              # 找错误，带行号
grep -C 3 "ERROR" app.log            # 显示错误前后各 3 行（排障很有用）
tail -f app.log | grep "ERROR"       # 实时只看错误
grep "Failed password" /var/log/secure | wc -l   # 统计登录失败次数
```

**看服务自己的日志**：

```bash
journalctl -u nginx -n 50            # 看 nginx 服务最近 50 行
journalctl -u nginx -f               # 实时跟踪
```

### 1.3 logrotate：防止日志把磁盘写满（★ 会被问）

**问题**：日志会一直增长，不管它，迟早把磁盘写满，**业务就挂了**。

**logrotate 就是解决这个的**：自动完成 **切割 → 压缩 → 删除旧日志 → 通知服务重开日志**。

```bash
# 配置文件放这里（每个服务一个文件）
/etc/logrotate.d/nginx

# 一个典型配置
/var/log/nginx/*.log {
    daily                  # 每天轮转
    rotate 7               # 保留 7 份，更旧的自动删除
    compress               # 压缩旧日志
    missingok              # 文件不存在也不报错
    notifempty             # 空文件不轮转
    create 644 nginx adm   # 轮转后重建日志文件并设权限
    postrotate
        kill -USR1 $(cat /var/run/nginx.pid)   # 通知 nginx 重新打开日志文件
    endscript
}
```

**测试命令**：

```bash
logrotate -d /etc/logrotate.d/nginx    # 只检查不执行（debug）
logrotate -f /etc/logrotate.d/nginx    # 强制立刻轮转一次
```

> **面试可能问**：
> **Q：日志文件太大怎么办？**
> A："配置 **logrotate** 做日志轮转——按天或按大小切割、压缩旧日志、只保留最近 N 份。另外要加 `postrotate` 通知服务重新打开日志文件，否则服务会继续往改名后的旧文件里写。"
> **Q：为什么轮转后要发信号？**
> A："因为进程还开着原来那个文件句柄，不发信号的话它会继续写旧文件，新日志文件是空的。"

## 二、定时任务（cron）

### 2.1 基本用法

```bash
crontab -e      # 编辑当前用户的定时任务
crontab -l      # 查看
crontab -r      # 删除所有（★ 没有确认，慎用）
```

### 2.2 语法：五颗星

```text
分   时   日   月   周    命令
*    *    *    *    *    /path/to/script.sh

取值范围：
分 0-59   时 0-23   日 1-31   月 1-12   周 0-7（0 和 7 都是周日）
```

**常用示例**：

```bash
0 3 * * *      /shell/backup.sh      # 每天凌晨 3 点
*/5 * * * *    /shell/check.sh       # 每 5 分钟
0 9 * * 1-5    /shell/work.sh        # 周一到周五 9 点
@reboot        /shell/start.sh       # 开机执行
```

### 2.3 ★ 最高频的坑：`*/5` 和 `5` 的区别

```text
*/5 * * * *   每 5 分钟执行一次（一天 288 次）  ✅ 想要"每5分钟"用这个
5 * * * *     每小时的第 5 分钟执行（一天 24 次） ❌ 容易写错
```

### 2.4 cron 不执行怎么排查（★ 会被问）

```text
① systemctl status crond        服务有没有在跑
② crontab -l                    表达式对不对（★ 重点看 */5 还是 5）
③ tail -f /var/log/cron         有没有执行记录
④ 脚本里用绝对路径                cron 的环境变量极简，找不到命令
⑤ 脚本有执行权限                 chmod +x
```

> **加分点**：**"cron 不执行，90% 是三个原因：表达式写错、脚本里用了非绝对路径、脚本没有执行权限。"**

## 三、系统信息命令（面试可能随口问）

| 命令 | 作用 |
| --- | --- |
| `uname -r` | 内核版本 |
| `cat /etc/redhat-release` | 系统发行版 |
| `hostname` / `hostnamectl` | 主机名 |
| `uptime` | 运行时长 + 负载 |
| `free -h` | 内存 |
| `df -h` | 磁盘 |
| `nproc` / `lscpu` | CPU 核数 |
| `who` / `last` | 当前在线用户 / 登录历史 |
