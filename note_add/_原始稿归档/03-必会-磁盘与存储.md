## 一、`df` 和 `du` 的区别（★ 最高频的一题）

| 命令 | 看什么 |
| --- | --- |
| **`df -h`** | **分区/文件系统**的容量和使用率（还剩多少）|
| **`du -sh 目录`** | **目录/文件**实际占用了多少 |

```bash
df -h                  # 看每个挂载点的 Use%（使用率）
du -sh /var/log        # 看 /var/log 总共多大
du -sh /* | sort -h    # 找出哪个一级目录最大
```

> **标准答法**：**"`df` 看的是分区还剩多少空间，`du` 看的是目录占了多少空间。排查磁盘满的时候先用 `df` 定位是哪个分区，再用 `du` 逐层找大目录。"**

### 相关命令

```bash
lsblk                  # 看有哪些磁盘和分区（硬件视角）
df -i                  # 看 inode 使用率（空间没满却写不进时查它）
```

## 二、磁盘满了怎么查（★ 必背）

```text
① df -h                     先确认是哪个分区满了
② du -sh /* | sort -h       在该分区里逐层找大目录
③ 找到大文件后判断：日志 / 备份 / 垃圾 → 清理或转移
④ 如果是日志：清理 + 配置 logrotate 自动轮转（治本）
⑤ 特例：df 显示有空间但写不进 → df -i 查 inode 是否用满
⑥ 特例：删了文件空间没释放   → lsof | grep deleted，重启对应进程
```

> **第 ⑤⑥ 条是加分项**，能说出来说明你踩过坑。

## 三、磁盘分区与挂载（**知道流程即可**）

### 3.1 一块新硬盘怎么用起来（五步）

```text
① lsblk                      看新盘叫什么（比如 /dev/sdb）
② fdisk /dev/sdb             分区：n 新建 → p 主分区 → 1 → 回车 → 回车 → w 保存
③ mkfs.ext4 /dev/sdb1        格式化（创建文件系统）
④ mkdir /mnt/data && mount /dev/sdb1 /mnt/data    挂载
⑤ 写 /etc/fstab 并 mount -a  开机自动挂载
```

> **面试问"新加的硬盘怎么用"，按这五步答就行。**
> **`w` 才保存**（`q` 是不保存退出）——这个小细节能体现你真操作过。

### 3.2 /etc/fstab 是什么

**开机自动挂载的配置文件**，每行六个字段：

```text
UUID=xxx   /mnt/data   ext4   defaults   0   0
   ↑            ↑         ↑       ↑      ↑   ↑
 设备        挂载点    文件系统  挂载选项  备份 fsck
```

> ⚠️ **改 fstab 前先备份，改完必须 `mount -a` 验证** —— 写错会导致系统起不来。

### 3.3 LVM（了解即可）

| 概念 | 作用 |
| --- | --- |
| PV（物理卷）| 初始化过的硬盘/分区 |
| VG（卷组）| PV 组成的资源池 |
| **LV（逻辑卷）** | 从池子里划出来用的空间 |

**LVM 的好处**：**可以在线扩容**（分区建好就改不了，LVM 可以）。

```bash
# 扩容两步（记住是两步！）
lvextend -L +5G /dev/vg_data/lv_app     # 扩逻辑卷
resize2fs /dev/vg_data/lv_app           # 扩文件系统（ext4）；xfs 用 xfs_growfs
```

## 四、RAID（★ 会被问，记住这张表就够）

### 4.1 五种级别对比（**背下来**）

| 级别 | 最少几块盘 | 可用容量 | 能坏几块盘 | 适合什么 |
| --- | --- | --- | --- | --- |
| **RAID 0** | 2 | 全部之和（N×单盘）| **0 块**（坏了全丢）| 临时数据、求速度 |
| **RAID 1** | 2 | 单盘容量 | N−1 块 | 系统盘 |
| **RAID 5** | 3 | **(N−1) × 单盘** | **1 块** | 一般存储 |
| **RAID 6** | 4 | (N−2) × 单盘 | **2 块** | 大容量存储 |
| **RAID 10** | 4 | N/2 × 单盘 | 每组坏 1 块 | **数据库** |

### 4.2 常考的两个问题

**Q：4 块 1T 的盘做 RAID 5，可用容量多少？**
A：**(4−1) × 1T = 3T**（牺牲一块盘的容量存校验信息）。

**Q：RAID 5 坏了两块盘会怎样？**
A：**数据全部丢失**（RAID 5 只能容错 1 块）。

**Q：数据库为什么用 RAID 10 而不是 RAID 5？**
A：RAID 5 每次写要额外算校验，**写性能差**；RAID 10 是镜像 + 条带，**读写都快且容错更好**。

### 4.3 RAID 和备份的关系（★ 常考）

> **RAID 不是备份。**
> RAID 只能防"磁盘物理损坏"，**防不了误删、病毒、逻辑损坏**——因为这些操作会被同步到所有盘。

| | RAID | 备份 |
| --- | --- | --- |
| 解决什么 | **磁盘坏了服务不中断**（高可用）| **数据能恢复**（可恢复性）|
