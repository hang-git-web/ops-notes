## 一、防火墙（了解）

### 1.1 要会的一件事：放行端口

```bash
# CentOS（firewalld）
firewall-cmd --list-all                                   # 查看当前规则
firewall-cmd --add-port=80/tcp --permanent                # 永久放行 80
firewall-cmd --reload                                     # 重载生效

# Ubuntu（ufw）
ufw status
ufw allow 80

# 直接看 iptables 规则
iptables -L -n
```

### 1.2 两个概念（面试可能问）

| 问题 | 答案 |
| --- | --- |
| firewalld 和 iptables 什么关系 | **firewalld 是管理工具（前端），底层还是用 iptables/nftables**。两者**不能同时用** |
| 放行了端口但还是不通 | ① 看**监听地址**（`ss -tlnp`，是 `0.0.0.0` 还是 `127.0.0.1`）② 看云平台**安全组** ③ 看 SELinux |

> **加分点**：云服务器上"端口放了还是不通"，很可能是**云平台安全组**没放行——这是云环境特有的坑。

## 二、SELinux（了解）

### 2.1 一句话理解

> SELinux 是 Linux 的**强制访问控制**机制：除了传统的 rwx 权限，它还检查"**这个进程能不能访问这个文件**"，**即使你是 root 也可能被拦。**

### 2.2 三种模式（**记住这三个词**）

| 模式 | 行为 |
| --- | --- |
| **enforcing** | 强制（拒绝违规访问并记录）← **生产应该是这个** |
| **permissive** | 宽容（不拒绝，但记录）← **排障用** |
| **disabled** | 关闭 |

```bash
getenforce            # 查看当前模式
setenforce 0          # 临时切到 permissive（重启失效）
setenforce 1          # 切回 enforcing
```

### 2.3 被 SELinux 拦了怎么查（**记住这个流程**）

```text
① getenforce                   确认 SELinux 是否开启
② setenforce 0                 临时切成 permissive，再试一次
                               → 如果成功了，就说明是 SELinux 的问题
③ ausearch -m avc -ts recent   查看具体的拒绝记录（AVC 日志）
④ 修复：
   · 用 restorecon -Rv 目录      恢复文件默认的标签
   · 用 setsebool -P 开关 on     开启对应的策略开关
     （典型场景：Nginx 做反向代理时报 502，就是 httpd_can_network_connect 没开）
⑤ setenforce 1                 记得切回去
```

> **标准答法**：**"如果改了权限还是 Permission denied，我会怀疑 SELinux。判断方法很简单：`setenforce 0` 临时关掉再试一次，如果通过了就是 SELinux 的问题；然后用 `ausearch -m avc` 看具体的拒绝记录，用 `restorecon` 或 `setsebool` 精确放行，而不是直接关掉 SELinux。"**

## 三、容器与虚拟机（★ 这个要会，会被问）

| 对比 | 虚拟机 | 容器 |
| --- | --- | --- |
| **是否包含完整的操作系统** | 是（每个虚机一套内核）| **否（共享宿主内核）** |
| 启动速度 | 慢（几十秒）| **快（秒级）** |
| 资源占用 | 大（几百 MB 起）| **小** |
| 隔离强度 | **强**（硬件级隔离）| 相对弱（进程级隔离）|
| 代表技术 | KVM、VMware | Docker |

**一句话总结**：

> **虚拟机是"虚拟出一台完整的机器"；容器是"把进程关进一个有边界的盒子"，本质是被隔离 + 被限制的普通进程。**

**两个可能被追问的点**：

| 问题 | 答案 |
| --- | --- |
| 容器怎么实现隔离 | **namespace 负责隔离（让进程看不见别的东西），cgroup 负责限制资源（让进程用不了太多）** |
| 容器里 `free` 看到的是宿主机内存，为什么 | 因为容器**共享宿主内核**，`/proc/meminfo` 是全局的；容器真正的内存限制要在 cgroup 里看 |

**容器相关常用命令**（知道就行）：

```bash
docker ps -a                 # 查看所有容器（含已停止）
docker images                # 查看镜像
docker logs 容器              # 看容器日志
docker exec -it 容器 bash     # 进入容器
docker stats 容器             # 看容器的资源占用
```

## 四、备份（了解）

### 4.1 一句话原则

> **3-2-1 原则**：**3** 份数据、**2** 种介质、**1** 份异地。

**为什么**：因为不同的灾难需要不同的防线——

| 场景 | 本地备份能救吗 | 异地备份能救吗 |
| --- | --- | --- |
| 误删文件 | ✅ | ✅ |
| 硬盘损坏 | ✅ | ✅ |
| 服务器被盗 / 火灾 | ❌ | ✅ |
| 勒索病毒 | ❌ | ✅ |

### 4.2 两个必答的点

| 问题 | 答案 |
| --- | --- |
| **备份怎么验证可用** | **定期做恢复演练**——"备份成功 ≠ 备份可用，必须真的恢复一次验证过" |
| **RAID 能代替备份吗** | **不能**。RAID 只防磁盘物理损坏，防不了误删、病毒 |

### 4.3 备份的命令（你会用的）

```bash
# 文件备份
tar -czvf /backup/www_$(date +%F).tar.gz /data/www

# 数据库备份
mysqldump -uroot -p --single-transaction --all-databases > /backup/db_$(date +%F).sql

# 同步到远端
rsync -avz /backup/ backup@192.168.1.100::backup/
```

## 五、监控（了解）

### 5.1 你用过什么

**Zabbix**（你在笔记里做过完整的实验）：采集指标 → 触发器判断 → 触发告警 → 发邮件。

如果被问"你做过什么监控"，可以答：

> "我用 Zabbix 做过主机监控，配置了监控项采集 CPU、内存、磁盘和自定义指标，用触发器设置阈值，再通过动作把告警发到邮箱。"

### 5.2 两个概念（了解）

| 概念 | 一句话 |
| --- | --- |
| **监控什么** | 硬件 → 系统（CPU/内存/磁盘/网络）→ 中间件 → 应用 → **业务指标** |
| **告警为什么要分级** | 避免"所有告警都发同一个人"，按严重程度分 P0（立即处理）/ P1 / P2 / P3，不同级别用不同的通知方式（电话 / 短信 / 群消息）|

### 5.3 加分的一句

> "告警的目的是让人采取行动——**不能行动的告警就是噪音**，所以要定期清理无效告警。"
