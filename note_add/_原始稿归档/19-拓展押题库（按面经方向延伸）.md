# 19 拓展押题库：按两份面经的考察方向延伸（89 题）

> **这份题的来历**：不是你给的那两份面经里的题，而是**按它们的方向押的**。
> 两份面经透露的方向是：
> ```text
> ① 内核机制（启动流程、信号、缺页中断、mmap、IPC、OOM）
> ② 命令/参数的细节（ss -lntp 逐字母、source/bash/exec、ls -l 首字符）
> ③ 步骤题要一步不漏（磁盘初始化、扩容、救援）
> ④ 概念辨析（并发 vs 并行、MB vs Mb）
> ⑤ 场景排查（CPU 100%、磁盘满、服务起不来：先定位→再看指标→最后处理）
> ```
> 所以下面按**同样的考法**往外扩了一圈：内核/进程/内存/磁盘/网络/性能/Shell/日志/安全/备份监控/容器/中间件/项目行为。
> **标记说明**：★★★ = 这个方向必问；★★ = 很可能问；★ = 了解即可。
> **答案尽量一句话**，详细原理指到对应笔记。

## 一、系统与启动（★★★）

**Q：systemd 的服务文件放在哪几个目录？自己写的服务放哪？（★★）**
A：`/usr/lib/systemd/system/`（软件包安装）、**`/etc/systemd/system/`（管理员自建，优先级最高）**、`/run/systemd/system/`（运行时）。自建放 `/etc/systemd/system/xxx.service`，写完 `systemctl daemon-reload`。

**Q：自己写一个 systemd 服务，关键字段有哪些？（★★）**
A：`[Unit]` 里写 `Description`、`After=network.target`；`[Service]` 里写 `Type=simple`、`ExecStart`、`Restart=on-failure`、`User`、`LimitNOFILE`；`[Install]` 里写 `WantedBy=multi-user.target`。最后 `daemon-reload` + `enable --now`。

**Q：服务器时间不对会有什么影响？怎么同步时间？（★★）**
A：日志时间错乱、证书校验失败、集群/主从数据不一致、定时任务跑错时间。用 `chronyd`（或 ntpd）同步：`timedatectl` 看状态，`chronyc sources -v` 看时间源，`chronyc tracking` 看偏差。

**Q：内核参数怎么改？临时和永久有什么区别？（★★）**
A：临时 `sysctl -w vm.swappiness=10`（重启失效）；永久写 `/etc/sysctl.d/99-xxx.conf` 再 `sysctl -p`。常改的有 `net.ipv4.ip_forward`、`net.core.somaxconn`、`fs.file-max`、`vm.swappiness`、`vm.overcommit_memory`。

**Q：怎么查看系统版本、内核版本、CPU 核数、内存大小？（★★）**
A：`cat /etc/os-release`（RHEL 系也可 `cat /etc/redhat-release`）、`uname -r`、`nproc` 或 `lscpu`、`free -h`；硬件层面用 `dmidecode`。

**Q：uptime 里的三个数字是什么？怎么判断机器忙不忙？（★★★）**
A：1/5/15 分钟的平均负载，要和核数（`nproc`）比：接近核数算跑满，超过 2 倍要处理。注意它不只是 CPU，还包含 D 状态（等 IO）的进程。详见 `16-补充-性能-top字段与高CPU排查.md`。

**Q：服务器重启后服务没起来，你怎么查？（★★）**
A：`systemctl status 服务` → 看是不是 `enable` 过 → `journalctl -u 服务 -b` 看日志 → 检查依赖（网络、挂载、数据库）→ 再查磁盘是否满、权限对不对。

**Q：让服务开机自启有哪几种做法？（★）**
A：正规做法是 `systemctl enable 服务`；临时任务可以 `crontab -e` 里写 `@reboot`；老系统用 `/etc/rc.local`（要有执行权限）。

## 二、进程与作业控制（★★★）

**Q：进程有哪几种状态？D 状态是什么意思？（★★★）**
A：R 运行/就绪、S 可中断睡眠、**D 不可中断睡眠（卡在 IO 上，不响应信号）**、T 暂停、Z 僵尸。`ps aux` 的 STAT 列。

**Q：僵尸进程是什么？为什么杀不死？怎么处理？（★★★）**
A：子进程已退出，但父进程没有 `wait()` 回收，进程表项还在。僵尸本身已经没有可杀的了，**要杀它的父进程**；如果父进程也异常，等它退出后由 PID 1 收养回收。

**Q：nice 和 renice 是干什么的？（★★）**
A：调整进程优先级，范围 -20（最高）~ 19（最低）。`nice -n 10 命令` 启动时设置，`renice -n 5 -p PID` 改运行中的进程；实时优先级用 `chrt`。

**Q：怎么把一个正在跑的前台进程放到后台，再调回来？（★★）**
A：`Ctrl+Z` 挂起 → `bg` 放到后台继续跑；`jobs` 看任务号，`fg %1` 调回前台；启动时直接后台用 `命令 &`。

**Q：nohup、disown、setsid、systemd 有什么区别？（★★）**
A：`nohup` 让进程忽略 SIGHUP（关终端不死）；`disown` 把任务从 shell 的任务表里摘掉；`setsid` 新建会话彻底脱离终端；**生产推荐写成 systemd 服务**，由 PID 1 托管、能开机自启。

**Q：什么是孤儿进程？谁负责回收？（★★）**
A：父进程先退出、子进程还在跑，就叫孤儿进程，会被 **PID 1 收养**并在退出时回收。这也是容器里 1 号进程很重要的原因。

**Q：怎么查看一个进程打开了哪些文件、端口、线程？（★★）**
A：`lsof -p PID`（文件与端口）、`ls /proc/PID/fd | wc -l`（fd 数量）、`ss -tanp | grep PID`（网络连接）、`ps -L -p PID` 或 `top -H -p PID`（线程）。

**Q：`kill -9` 都杀不掉的进程怎么处理？（★★★）**
A：先看状态——**D 状态**是卡在不可中断 IO 上，只能等 IO 恢复（查磁盘/NFS）；**Z 状态**要杀父进程；**权限不足**要用 root；**容器里的 PID 1** 只认注册过的信号，用 `docker stop`。详见 `11-补充-信号与终端控制.md`。

## 三、内存（★★★）

**Q：free 里的 free 和 available 有什么区别？（★★★）**
A：`free` 是完全没用的空闲内存；**`available` 才是应用真正还能拿到的内存**（把可回收的 buff/cache 也算进去了）。判断内存够不够看 available。详见 `05-必会-内存与故障排查.md`。

**Q：buff/cache 占了很多，能不能手动释放？（★★）**
A：能但**生产慎用**：`echo 3 > /proc/sys/vm/drop_caches`。它是缓存，不是内存泄漏；释放后系统还要重新读盘，性能反而变差。

**Q：生产环境要不要开 swap？（★★）**
A：普通服务器建议留一点（内存的 1~2 倍或按需，比如 4~8G）当缓冲；但**数据库/中间件**（MySQL、Redis）和 K8s 一般要求关掉或把 `vm.swappiness` 调到 1~10，避免换页导致延迟抖动。

**Q：OOM Killer 按什么挑进程？怎么保护关键进程？（★★★）**
A：主要看进程占用的内存（RSS）并按 `oom_score_adj` 调整。查看 `/proc/PID/oom_score`；保护关键进程可以 `echo -1000 > /proc/PID/oom_score_adj`，或用 systemd 的 `MemoryMax`/`OOMPolicy`、容器 memory limit。

**Q：怎么判断是不是内存泄漏？用哪些工具？（★★★）**
A：看 RSS 是否**只涨不落、重启才回落**。`top`/`ps aux --sort=-%mem` 找进程 → 采样 RSS 看趋势 → `pmap -x`/`/proc/PID/smaps_rollup` 看是哪类内存涨 → Java 用 `jmap`、C 用 `valgrind`。运维侧先加监控和内存上限、保留现场再重启。详见 `14-补充-内存进阶.md`。

**Q：page cache 是什么？为什么它把内存吃满了？（★★）**
A：内核把读过的文件页缓存在内存里加速后续读取。它属于可回收内存（`free` 里算在 buff/cache），应用需要时会自动释放，所以"内存快满了"通常是假象。

**Q：内存占用高但没 OOM，要不要处理？（★）**
A：先看 `available`、`vmstat` 的 `si/so`、RSS 趋势，再结合业务延迟判断。稳定在高位且 available 充足就不用动；持续上涨或开始换页才要处理。

## 四、磁盘与文件系统（★★★）

**Q：df 和 du 显示的结果不一致，可能是什么原因？（★★★）**
A：① 文件被删除但进程还持着句柄（`lsof | grep deleted`，空间没释放）；② 目录被新挂载覆盖（原数据还在，但看不到）；③ ext4 默认预留 5% 给 root；④ inode 用尽。详见 `03-必会-磁盘与存储.md`。

**Q：磁盘满了但找不到大文件，怎么查？（★★★）**
A：`df -h` 定位分区 → `du -sh /path/* | sort -h` 逐层找 → `find / -size +1G -mtime -7` 按大小和时间找 → `lsof +L1` 查已删除但被占用的文件 → 别忘了 `df -i` 看 inode。

**Q：inode 用尽怎么处理？（★★）**
A：`df -i` 确认后，找小文件特别多的目录（如 `/var/spool`、session、缓存目录）清理；长期方案是重建文件系统时调大 inode 数，或改用 xfs（动态分配 inode）。

**Q：怎么判断磁盘 IO 是不是瓶颈？（★★★）**
A：`iostat -x 1` 看 **`%util` 接近 100%** 和 **`await` 明显变大**；配合 `vmstat` 的 `wa`、`iotop`、`pidstat -d 1` 找到具体进程。

**Q：fstab 写错导致系统起不来，怎么救？（★★）**
A：进 emergency mode 或在 GRUB 里加 `rd.break` → `mount -o remount,rw /`（或 `/sysroot`）→ 注释掉写错的行 → `mount -a` 验证 → `reboot`。预防：改前备份、用 UUID、加 `nofail`。

**Q：LVM 有什么好处？扩容怎么做？（★★★）**
A：好处是**可以在线扩容**（普通分区建好就难改）。扩容三步：`pvresize`（底层盘变大时）→ `lvextend -l +100%FREE /dev/vg/lv` → `resize2fs`（ext4）或 `xfs_growfs`（xfs）。详见 `13-补充-磁盘扩容实操.md`。

**Q：RAID 0/1/5/10 的区别？为什么数据库用 RAID 10？（★★★）**
A：0 是纯条带（快、不冗余）；1 是镜像（容错一半）；5 是条带+1 份校验（坏 1 块，写有惩罚）；10 是镜像+条带（性能与容错都好）。数据库写多，RAID 5 每次写要算校验、写性能差，所以用 RAID 10。

**Q：怎么统计某个目录下的大文件 Top10？（★★）**
A：`du -ah /data | sort -h | tail -10`；只找大文件用 `find /data -type f -size +500M -exec ls -lh {} +`。

## 五、网络（★★★）

**Q：TCP 为什么是三次握手？TIME_WAIT 为什么要等 2MSL？（★★★）**
A：三次是为了让双方都确认"对方收发正常"，两次的话服务端无法确认客户端收到了自己的 SYN+ACK。2MSL 是为了**保证最后一个 ACK 能到达**（丢了好重发），并让本次连接的残留报文在网络中消散。

**Q：TIME_WAIT 和 CLOSE_WAIT 分别说明什么？怎么处理？（★★★）**
A：TIME_WAIT 是**主动关闭方**的正常状态，多了会占端口，解法是减少短连接（长连接/连接池）；CLOSE_WAIT 是**被动方应用没调 close()**，是代码问题，调内核参数没用。详见 `04-必会-网络与TCP.md`。

**Q：服务本机能访问、外部访问不了，怎么查？（★★★）**
A：① `ss -lntp` 看监听地址是 `0.0.0.0` 还是 `127.0.0.1`；② 防火墙（firewall-cmd --list-all / iptables -L -n）；③ SELinux（getenforce）；④ 从客户端 `telnet IP 端口` 实测；⑤ 还不行就 `tcpdump` 抓包看包有没有到网卡。

**Q：怎么测试端口通不通？ping 通代表服务可用吗？（★★）**
A：用 `telnet IP 端口`、`nc -vz IP 端口`、`curl -I http://IP:端口`。**ping 通只代表网络层可达**，服务可能没监听、被防火墙拦或应用报错。

**Q：怎么抓包确认请求到底有没有到？（★★）**
A：`tcpdump -i any -nn port 80 -c 20`（抓 20 个包）、`-A` 看内容、`-w a.pcap` 存下来用 Wireshark 分析；看是哪一方的包没走通。

**Q：DNS 解析慢或不生效怎么排查？（★★）**
A：`cat /etc/resolv.conf` 看 DNS 地址，`dig 域名` / `nslookup 域名` 测试，`dig @8.8.8.8 域名` 换解析器对比，`time dig` 看耗时；还要看 `/etc/nsswitch.conf` 的解析顺序和 hosts 文件。

**Q：一台服务器为什么能同时跑多个服务？它们怎么区分？（★★）**
A：**靠端口区分**：IP+端口唯一标识一个服务，各服务监听不同端口（80/443/3306/6379…）；同一个端口默认只能被一个进程监听，除非用 `SO_REUSEPORT`（Nginx 多 worker）或绑不同 IP。

**Q：HTTP 502 和 504 有什么区别？常见原因？（★★）**
A：**502 Bad Gateway** = 网关从上游收到了无效响应（上游进程挂了、端口不对、SELinux/防火墙拦了）；**504 Gateway Timeout** = 上游响应超时（慢 SQL、后端卡住、超时配置太短）。

**Q：curl 常用参数？（★）**
A：`-I` 只看响应头、`-v` 看详细过程、`-x` 走代理、`-o` 保存文件、`-w` 自定义输出（如状态码/耗时）、`--resolve` 指定解析的 IP、`-k` 忽略证书、`-L` 跟随跳转。

## 六、性能排查（★★★）

**Q：CPU 使用率 100%，你的排查步骤？（★★★）**
A：`uptime` 看负载趋势 → `top` 看 8 个字段和排行的进程 → `ps aux --sort=-%cpu` 定位进程 → `top -H -p PID` 定位线程 → 按字段判断类型（us 应用算、sy 系统调用、wa 等 IO、hi/si 网络、st 被宿主机偷走）→ Java 用 `jstack`、通用用 `perf`/`strace` → 处理并留现场。详见 `16-补充-性能-top字段与高CPU排查.md`。

**Q：load 很高但 CPU 使用率很低，为什么？（★★★）**
A：load 里包含 **D 状态进程**，所以典型原因是磁盘/NFS IO 卡住、内存换页（`si/so`）、被 cgroup 限流，或云主机被超卖（`st` 高）。用 `vmstat` 的 `r/b/wa/si/so` 区分。

**Q：CPU、内存、磁盘、网络四类问题怎么快速区分？（★★★）**
A：`top` 看 `us/sy/wa/st` 和 load、`free` 看 `available`、`vmstat` 看 `r/b/si/so/cs`、`iostat -x` 看 `%util/await`、`ss -s`/`sar -n DEV` 看连接与流量。**先分层定位资源类型，再定位到进程，最后看进程内部。**

**Q：常用的性能工具和它们的用途？（★★）**
A：`top`/`vmstat`/`mpstat` 看 CPU、`free`/`smem` 看内存、`iostat`/`iotop` 看磁盘、`ss`/`sar -n DEV` 看网络、`pidstat` 按进程/线程看、`perf`/`火焰图` 找热点、`strace` 看系统调用。

**Q："服务变慢但资源都不高"，你怎么排查？（★★）**
A：往上下游看——上游依赖（数据库慢查询、Redis 慢命令、第三方接口超时）、应用内部（锁竞争、GC、线程池满）、DNS 解析、连接池耗尽、日志级别太详细导致 IO 抖动。用 `strace -p`、慢日志、APM/链路追踪定位。

## 七、Shell 与文本处理（★★）

**Q：怎么统计日志里访问次数最多的 IP / 状态码？（★★）**
A：`awk '{print $1}' access.log | sort | uniq -c | sort -rn | head`；状态码同理换成对应字段。

**Q：awk 和 sed 分别适合做什么？各举一个例子。（★★）**
A：`awk` 按列处理、做统计和格式化：`df -h | awk 'NR>1 {print $5, $6}'`；`sed` 做替换和按行编辑：`sed -i 's/old/new/g' a.conf`。

**Q：怎么批量替换一批文件里的内容？怎么在大目录里快速搜关键字？（★★）**
A：替换 `grep -rl 'old' dir --include='*.conf' | xargs sed -i 's/old/new/g'`；搜索 `grep -rn --include='*.log' 'ERROR' /var/log`，或更快的 `ripgrep`（`rg`）。

**Q：写 shell 脚本有哪些必须注意的点？（★★）**
A：首行写 `#!/bin/bash`，开头加 `set -euo pipefail`（出错就退出、用未定义变量报错），变量加双引号，命令用绝对路径（cron 里尤其重要），重要操作先做检查再执行。

**Q：`$$`、`$?`、`$0`、`$#`、`$@` 分别是什么？（★★）**
A：当前 shell 的 PID、上一条命令的退出码（0 成功）、脚本名、参数个数、全部参数列表；注意 bash 的子 shell 里 `$$` 不变，要看真实 PID 用 `$BASHPID`。详见 `10-补充-Shell与环境变量.md`。

## 八、日志与定时任务（★★★）

**Q：Linux 的主要日志文件有哪些？分别记什么？（★★★）**
A：`/var/log/messages`（系统通用，RHEL 系）、`/var/log/syslog`（Debian 系）、`/var/log/secure`（认证/登录）、`/var/log/cron`（定时任务）、`/var/log/dmesg` 或 `journalctl -k`（内核/硬件）、应用自己的日志目录。

**Q：logrotate 是怎么配的？关键参数有哪些？（★★）**
A：配置在 `/etc/logrotate.d/xxx`：`daily/weekly` 轮转周期、`rotate 7` 保留份数、`compress` 压缩、`missingok` 文件不存在不报错、`notifempty` 空文件不轮转、`create` 新建文件权限、`postrotate ... endscript` 里给服务发信号重新打开日志文件。

**Q：journalctl 常用参数？（★★）**
A：`-u 服务` 按服务过滤、`-f` 实时跟踪、`--since "1 hour ago"` 时间范围、`-p err` 只看错误级别、`-b` 本次开机、`-b -1` 上次开机、`-k` 只看内核、`--disk-usage` 看占用。

**Q：cron 任务不执行，你怎么排查？（★★★）**
A：① `systemctl status crond` 服务在不在；② `/var/log/cron` 有没有执行记录；③ **环境变量**：cron 的 PATH 很干净，脚本里要用绝对路径；④ 脚本有没有执行权限、有没有写 `#!/bin/bash`；⑤ `%` 要转义成 `\%`；⑥ 手动用 `bash -x` 跑一遍脚本。

**Q：crontab 里最容易踩的两个坑？（★★）**
A：**环境变量**（不读 `.bashrc`，PATH 极简）和 **特殊字符**（`%` 在 cron 里表示换行，必须转义）；另外输出默认发邮件，日志要自己重定向。

**Q：写一个"每天备份 + 每周清理旧备份"的脚本，你的思路？（★★）**
A：`tar -czf /backup/db_$(date +%F).tar.gz /data` 归档 → 校验大小/`tar -tzf` 验证 → `find /backup -name "*.tar.gz" -mtime +30 -delete` 清理 → 写日志重定向 `>> /var/log/backup.log 2>&1` → 挂到 `crontab`，最好再加个告警。

## 九、权限与安全（★★★）

**Q：rwx 对文件和目录分别代表什么？能不能删文件看谁的权限？（★★★）**
A：文件：读内容/改内容/执行；目录：列文件名/增删改名/进入目录。**能不能删一个文件取决于它所在目录的 w 权限**，不是文件自己的权限。

**Q：SUID、SGID、Sticky 分别是什么？举例子。（★★）**
A：SUID：执行时临时获得文件属主权限（`/usr/bin/passwd`）；SGID：获得属组权限，用在目录上则新建文件继承目录的组；Sticky：目录里的文件只有属主能删（`/tmp`，权限位是 `1777`）。

**Q：怎么给用户加 sudo？怎么做最小权限？（★★）**
A：`usermod -aG wheel 用户`（Debian 系是 sudo 组）。更规范的做法是用 `visudo` 编辑 `/etc/sudoers.d/xxx`，只放开需要的具体命令，而不是给 `ALL=(ALL) NOPASSWD: ALL`。

**Q：SSH 你会做哪些安全加固？（★★）**
A：禁用 root 直接登录（`PermitRootLogin no`）、只用密钥认证（`PasswordAuthentication no`）、改默认端口、限制来源 IP（防火墙/`AllowUsers`）、失败次数限制（fail2ban）、保持版本更新。

**Q：怎么放行一个端口？firewalld 和 iptables 是什么关系？（★★）**
A：`firewall-cmd --permanent --add-port=8080/tcp && firewall-cmd --reload`（CentOS 7+）；firewalld 是管理前端，底层调用的是 nftables/iptables 规则，`iptables -L -n` 能看到最终规则。

**Q：SELinux 三种模式是什么？被它拦了怎么查？（★★）**
A：enforcing（强制）、permissive（只记录不拦）、disabled（关闭）。排查：`getenforce` 看模式、`ls -Z` 看安全上下文、`ausearch -m avc -ts recent` 看拒绝日志、临时 `setenforce 0` 验证、长期用 `restorecon`/`semanage` 修正上下文或加策略。

**Q：怎么查找最近被改过的文件？怎么排查可疑的 SUID 文件？（★★）**
A：`find / -mtime -1 -type f`、`find / -perm -4000 -type f`、`rpm -Vf /usr/bin/xxx` 校验包文件是否被改。

## 十、备份、监控与运维规范（★★）

**Q：备份的 3-2-1 原则是什么？怎么验证备份可用？（★★★）**
A：3 份数据、2 种介质、1 份异地。**没验证过的备份不算备份**：定期做恢复演练、校验文件大小/校验和、抽查恢复到测试环境。

**Q：全量、增量、差异备份有什么区别？（★★）**
A：全量=每次都完整备份（恢复快、占空间）；增量=只备份上次备份后的变化（占空间最小、恢复要按链条逐个恢复）；差异=备份上次**全量**后的所有变化（折中）。常见组合：每周全量 + 每天增量。

**Q：监控应该监控哪些东西？告警为什么要分级？（★★）**
A：三层——**资源层**（CPU/内存/磁盘/IO/网络）、**服务层**（进程存活、端口、响应、状态码）、**业务层**（订单量、成功率、延迟）。分级是为了让 P0 打电话、P3 群里看，避免告警疲劳。

**Q：写一个日常巡检脚本，你会检查哪些项？（★★）**
A：负载与 CPU、内存和 swap、磁盘使用率与 inode、关键服务是否存活/端口是否监听、日志错误关键字、备份是否成功、证书到期时间；结果输出成报告或发到告警渠道。

**Q：线上的变更流程你是怎么理解的？（★）**
A：先评估影响和回滚方案 → 备份/快照 → 低峰期执行 → 灰度或分批 → 观察监控和日志 → 出问题按预案回滚 → 记录变更。**不能回滚的变更不上生产。**

**Q：线上出问题，怎么判断是代码问题还是环境问题？（★★）**
A：看时间点（发布前后）、范围（所有机器还是个别）、日志（应用异常栈 vs 系统报错）、资源曲线（突增还是平稳）、依赖（是不是下游先挂）。能快速回滚版本验证是最直接的办法。

## 十一、容器与自动化（★★）

**Q：容器和虚拟机有什么区别？（★★★）**
A：虚拟机有独立的 Guest OS，靠 Hypervisor 虚拟硬件，体量大（GB 级、启动分钟级）；容器共享宿主机内核，靠 **namespace 隔离 + cgroup 限制**，体量小（MB 级、启动秒级）。隔离性虚拟机更强。

**Q：容器是怎么实现隔离和资源限制的？（★★★）**
A：隔离靠 **namespace**（PID、NET、MNT、UTS、IPC、USER 六种），限制靠 **cgroup**（CPU、内存、IO、进程数）；文件系统靠镜像分层 + 联合挂载（overlayfs）。

**Q：为什么容器里 free 看到的是宿主机的内存？（★★）**
A：`free` 读的是宿主机的 `/proc/meminfo`，容器没有独立内核。要看自己的限制得用 `cat /sys/fs/cgroup/memory.max`（cgroup v2）或 `docker stats`。

**Q：镜像分层是什么？为什么能加速构建和分发？（★★）**
A：镜像由一层层只读层叠加而成，Dockerfile 的每条指令生成一层；没变的层可以复用缓存，多容器共享同一层只有一份存储，所以构建和拉取都快。

**Q：容器里的数据怎么持久化？（★★）**
A：用 volume（`-v 卷名:/path` 或 `--mount`）或绑宿主机目录（`-v /host/path:/container/path`）；**不要存在容器可写层**，容器重建数据就没了。

**Q：容器的重启策略有哪些？（★）**
A：`no`（默认不重启）、`on-failure`（异常退出才重启）、`always`、`unless-stopped`；生产更推荐交给 systemd 或 K8s 管理。

**Q：K8s 里 Pod、Deployment、Service 是什么关系？（★）**
A：Pod 是最小调度单位（一个或多个容器）；Deployment 管理 Pod 的副本数和滚动更新；Service 给一组 Pod 提供固定的访问入口和负载均衡。声明式配置，控制器负责把实际状态拉回期望状态。

## 十二、服务与中间件（结合你笔记里的项目）（★★）

**Q：Nginx 反向代理和负载均衡怎么配？怎么做到不断连接？（★★）**
A：`location / { proxy_pass http://backend; }`，`upstream backend { server 10.0.0.1:8080; server 10.0.0.2:8080; }`。改配置先 `nginx -t` 校验，再 **`systemctl reload nginx`**（或 `nginx -s reload`）——只让 master 重读配置、worker 平滑替换，不中断连接。

**Q：Nginx 报 502 怎么排查？（★★）**
A：看 error.log → 上游服务是否存活（`ss -tlnp`、`systemctl status`）→ 上游地址端口配置对不对、SELinux 是否拦了（`httpd_can_network_connect`）→ PHP-FPM/后端进程池是否耗尽 → 超时参数是否合理。

**Q：MySQL 慢查询怎么定位？（★★）**
A：开慢查询日志（`slow_query_log`、`long_query_time`），用 `mysqldumpslow`/`pt-query-digest` 分析；实时看 `SHOW PROCESSLIST`、`SHOW ENGINE INNODB STATUS`；再用 `EXPLAIN` 看执行计划（是否走索引、扫描行数）。

**Q：MySQL 主从复制的原理？主从延迟怎么查？（★★）**
A：主库写 binlog，从库的 IO 线程拉取写入 relay log，SQL 线程重放。查延迟用 `SHOW SLAVE STATUS\G` 看 `Seconds_Behind_Master` 和两个 `Yes`，或用 `pt-heartbeat` 更准确地测。

**Q：Redis 的 RDB 和 AOF 有什么区别？（★★）**
A：RDB 是定时快照，文件小、恢复快，但可能丢最后一次快照后的数据；AOF 是追加命令日志，丢数据少（`appendfsync everysec` 最多丢 1 秒），文件大、恢复慢。生产常两个都开。

**Q：Redis 内存满了怎么办？淘汰策略有哪些？（★★）**
A：先确认 `maxmemory` 和淘汰策略。常见策略：`noeviction`（不淘汰、写入报错）、`allkeys-lru`（所有 key 按最近最少使用淘汰）、`volatile-lru`（只淘汰设了过期时间的）、`allkeys-lfu`（按频率）、`volatile-ttl`。缓存场景一般用 `allkeys-lru`。

**Q：Redis 为什么建议把 vm.overcommit_memory 设为 1？（★★）**
A：Redis 做 RDB 时要 fork 子进程做写时复制，需要"超额分配"内存；如果内核不允许 overcommit，fork 可能失败或直接把 Redis 干掉，所以官方建议 `vm.overcommit_memory=1`。

**Q：Zabbix 的架构和告警链路是什么？（★★）**
A：Server 负责采集与计算，Agent 装在被监控机上，Proxy 用于大规模/跨网络场景，数据库存历史数据，Web 前端展示。告警链路：监控项采集 → 触发器判断（表达式/恢复表达式）→ 动作（Action）→ 媒介（邮件/脚本/Webhook）→ 收件人。
