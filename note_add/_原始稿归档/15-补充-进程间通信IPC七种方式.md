# 15 补充：Linux 七种进程间通信方式（面经第 11 题）

> **面经原题**：Linux 七种通信方式。（你写了"没了解过"）
> **七种背这句口诀**：**"管道、命名管道、信号、信号量、共享内存、消息队列、套接字"**。
> 追问一般是这三个：**哪个最快（共享内存）、哪个不能传数据（信号、信号量）、哪个能跨主机（套接字）。**

---

## 一、总览表（先看这张）

| # | 方式 | 一句话 | 传数据吗 | 能跨主机吗 | 速度 | 典型场景 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | **管道 pipe** | 匿名管道，只能父子/亲缘进程用 | ✅ | ❌ | 中 | `ps aux \| grep nginx` 里的那根竖线 |
| 2 | **命名管道 FIFO** | 有文件名的管道，无亲缘也能用 | ✅ | ❌ | 中 | `mkfifo` 做日志收集、shell 里跨进程传数据 |
| 3 | **信号 signal** | 异步通知，**只告诉你有事，不搬数据** | ❌（只带少量信息）| ❌ | 快 | `kill`、Ctrl+C、`nginx -s reload` |
| 4 | **信号量 semaphore** | 计数器，**管同步/互斥，不搬数据** | ❌ | ❌ | 快 | 多进程抢同一资源、保护共享内存 |
| 5 | **共享内存 shm** | 多进程映射同一块物理内存 | ✅ | ❌ | **最快** | 数据库/中间件的高频数据交换 |
| 6 | **消息队列 msg queue** | 内核维护的"消息链表"，可按类型收发 | ✅ | ❌ | 中 | 异步解耦、进程间排队传递结构化消息 |
| 7 | **套接字 socket** | 通信端点，**唯一能跨主机** | ✅ | ✅ | 中 | Nginx↔PHP-FPM（Unix socket）、Redis、一切网络服务 |

```text
速度排序（大概）：共享内存 > 信号/信号量 > 消息队列 ≈ 管道 ≈ socket（本机）> socket（跨网络）
原因：共享内存直接读写同一块物理内存，没有"用户态 ⇄ 内核态"的多次数据拷贝。
```

## 二、逐个说清（每个都准备一句"是什么 + 什么特点"）

### 2.1 管道 pipe（匿名管道）

```bash
ps aux | grep nginx        # 这里的 | 就是内核帮你建了一个管道
mkfifo /tmp/myfifo         # 下面是"命名管道"
```

| 特点 | 说明 |
| --- | --- |
| 半双工 | 同一时刻只能单向流动，要双向就开两个 |
| 只能亲缘进程用 | 因为管道没有名字，只能靠 fork 继承文件描述符 |
| 字节流 | 没有消息边界 |
| 随进程消失 | 进程一结束，管道就没了 |

### 2.2 命名管道 FIFO

```bash
mkfifo /tmp/pipe1
cat /tmp/pipe1 &            # 一个进程读
echo "hello" > /tmp/pipe1   # 另一个进程写（无亲缘也行）
ls -l /tmp/pipe1            # 类型位是 p
```

> **和匿名管道的区别只有一个：它有名字（存在于文件系统），所以任何进程都能打开它。**

### 2.3 信号 signal

```text
本质：软中断式的异步通知。进程收到信号后按"默认动作/捕获/忽略"处理。
关键点：信号本身不搬运数据（只传一个编号和少量附加信息）。
```

> 详见 `11-补充-信号与终端控制.md`。经典例子：`kill -TERM`、`Ctrl+C`、`nginx -s reload`（发 HUP）。

### 2.4 信号量 semaphore

```text
本质：一个内核维护的计数器，P/V 操作（减/加），值为 0 时申请者阻塞。
作用：同步与互斥，保护临界区 —— 它自己不传数据。
```

```bash
ipcs -s          # 看 System V 信号量
ipcrm -s <id>    # 删除（进程异常退出常留下"僵尸"信号量/共享内存）
```

> **经典组合**：**共享内存 + 信号量** —— 一个负责"传"，一个负责"别抢乱"。

### 2.5 共享内存 shared memory（★ 最快）

```text
多个进程把同一块物理内存映射到各自地址空间，读写它就像读写自己的变量。
优点：最快（没有数据拷贝）
缺点：没有内置同步机制，必须自己配信号量/互斥锁；且进程崩溃可能留下残留
```

```bash
ipcs -m              # 看共享内存段
df -h /dev/shm       # 基于 tmpfs 的共享内存（POSIX 共享内存常见位置，默认是内存的一半）
ls /dev/shm
```

> **三种实现**：System V 共享内存（`shmget`）、POSIX 共享内存（`shm_open`，落在 `/dev/shm`）、`mmap` 匿名共享映射。

### 2.6 消息队列 message queue

```text
内核维护的链表，写入方按"类型"投递消息，读取方可以按类型取，天然支持异步解耦。
优点：有边界（一条条消息）、可带优先级、异步
缺点：相比共享内存多一次拷贝；消息太多会占内核内存（有队列长度限制）
```

```bash
ipcs -q                        # 看 System V 消息队列
ipcs -l                        # 看内核限制（最大队列数、单条消息大小）
```

> **注意**：面试问的是"Linux 的进程间通信机制"（内核级）；如果是业务层的 MQ（Kafka、RabbitMQ、Redis 的 pub/sub），那是**分布式消息中间件**，别答混了 —— 可以补一句"业务上我们更多用消息中间件，内核级的消息队列用得少"。

### 2.7 套接字 socket（★ 唯一能跨主机）

| 类型 | 说明 | 例子 |
| --- | --- | --- |
| **AF_UNIX / Unix domain socket** | 本机不同进程之间，走文件系统路径，**比 TCP 更快**（不走协议栈）| `/run/docker.sock`、`/var/lib/mysql/mysql.sock`、Nginx ↔ PHP-FPM |
| AF_INET + TCP | 可靠、有连接、跨主机 | HTTP、MySQL 远程连接、Redis |
| AF_INET + UDP | 无连接、快、不保证可靠 | DNS、日志上报 |

```bash
ss -lntp        # TCP 监听
ss -lxnp        # Unix socket 监听（x = unix）
lsof -U         # 查看进程打开的 unix socket
```

> **实战记忆**：**MySQL 本地登录用 socket（快），远程用 TCP；Nginx 转发给 PHP-FPM 也用 Unix socket。** 面试说出这个例子，比背定义有效得多。

## 三、对比记忆（表格式记法）

```text
能不搬数据、只做"通知/同步"的：  信号、信号量
搬数据但只在同一台机器的：        管道、命名管道、共享内存、消息队列
唯一能跨主机的：                  套接字 socket
最快的：                          共享内存
最常用的（应用里最常见的）：      套接字 socket
必须自己配合同步机制的：          共享内存
```

## 四、面试可能这么问

**Q：Linux 有哪几种进程间通信方式？**
A：七种——管道、命名管道、信号、信号量、共享内存、消息队列、套接字。其中信号和信号量不传数据，只做通知和同步；共享内存最快；套接字是唯一能跨主机的。

**Q：共享内存为什么最快？**
A：因为它让多个进程映射同一块物理内存，读写不需要在用户态和内核态之间来回拷贝；代价是要自己加信号量/锁做同步。

**Q：管道和命名管道有什么区别？**
A：管道是匿名的，只能用于有亲缘关系的进程（靠继承 fd）；命名管道在文件系统里有名字（`mkfifo`），任意进程都能打开。两者都是半双工、字节流。

**Q：信号量和信号是什么关系？**
A：名字像，作用完全不同。信号是"事件通知"，信号量是"计数器，做互斥和同步"。共享内存通常配信号量一起用。

**Q：你怎么用 socket 的？**
A：本机进程间用 Unix domain socket（比 TCP 少走协议栈，Nginx 转发 PHP-FPM、MySQL 本地登录都是）；跨主机用 TCP socket。
