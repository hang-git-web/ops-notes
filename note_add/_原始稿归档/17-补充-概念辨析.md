# 17 补充：概念辨析（面经第 13 题 + 常被追问的几组）

> **面经原题**：并发和并行的区别？MB 和 Mb 的区别？
> 这类题属于"**答对不加太多分、答错非常掉分**"，所以要一次说准。
> 本篇把最容易被问混的几组概念放在一起：**并发/并行、MB/Mb、进程/线程/协程、缓冲/缓存、阻塞/非阻塞、用户态/内核态、五种 IO 模型与零拷贝**。

---

## 一、并发 vs 并行（★ 面经原题）

```text
并发（Concurrency）：同一时间段内"交替"处理多个任务 —— 宏观上像同时，微观上是轮流。
并行（Parallelism）：同一时刻"真正同时"执行多个任务 —— 必须有多个 CPU 核。
```

> **一句话答法**：**"并发是交替执行、看起来同时在处理；并行是真正同时执行，需要多核。并发是'结构'问题，并行是'执行'问题。"**

| | 并发 | 并行 |
| --- | --- | --- |
| 时间维度 | 一段时间内交替 | 同一时刻同时 |
| 需要多核吗 | 不需要（单核也能并发）| **必须多核/多机** |
| 典型例子 | 单核 CPU 上多进程轮流跑；Nginx 事件循环处理海量连接 | 4 核跑 4 个计算线程 |
| 关注点 | 吞吐、响应、任务调度 | 计算速度 |
| 类比 | 一个客服同时接待 10 个客户（来回切换）| 10 个客服各接待 1 个客户 |

> **加分补充**：
> - **"高并发"不等于"高性能"**：Redis 用单线程也能扛十万级 QPS，靠的是 IO 多路复用（并发处理连接），不是并行计算。
> - Go 的 goroutine、Python 的 asyncio 都是"用并发模型在少量线程上支撑大量任务"。

## 二、MB 和 Mb（★ 面经原题，单位陷阱）

```text
b = bit（位）      —— 网络带宽用
B = Byte（字节）   —— 文件大小、内存用
1 Byte = 8 bit
```

| 写法 | 含义 | 用在哪 |
| --- | --- | --- |
| **Mb / Mbps** | 兆**位**每秒 | **网络带宽、链路速率**（运营商说"100 兆宽带"）|
| **MB / MB/s** | 兆**字节**每秒 | **文件大小、下载速度、磁盘吞吐** |
| MiB / GiB | 2 的幂（1024 进制），严格说法 | 内存、`free -h` 的真实含义 |

### 2.1 三个必会换算（面试爱考）

```text
① 100 Mbps 的带宽 = 100 ÷ 8 = 12.5 MB/s  ← 下载速度的上限
② 1 Gbps = 1000 Mbps = 125 MB/s
③ 100 MB 的文件，在 100 Mbps 链路上理论最快 100/12.5 = 8 秒
```

### 2.2 1000 和 1024 的坑

```text
硬盘厂商用 10 进制：1 TB = 1000 GB = 1000^4 字节
操作系统用 2 进制：1 TiB = 1024 GiB
→ 所以买了 1TB 的盘，系统里显示 931 GiB（不是被坑了，是进制不同）
内存条是 2 进制：8 GiB 就显示 8 GiB
网络速率是 10 进制：1 Gbps = 1000 Mbps
```

### 2.3 顺带记住三个性能单位

| 单位 | 含义 | 场景 |
| --- | --- | --- |
| **IOPS** | 每秒 IO 次数 | 数据库小随机读写（SSD 几万到几十万）|
| **吞吐（MB/s）** | 每秒传输字节数 | 大文件顺序读写、带宽 |
| **延迟（ms/us）** | 一次操作耗时 | 磁盘 `await`、网络 RTT |
| PPS | 每秒包数 | 小包场景（防火墙/网卡瓶颈）|

## 三、进程 vs 线程 vs 协程（并发题的追问）

| 维度 | 进程 | 线程 | 协程 |
| --- | --- | --- | --- |
| 资源 | **独立地址空间**、独立 fd 表 | 共享进程的地址空间、堆、fd；**独享栈和寄存器** | 用户态调度，栈更小（KB 级）|
| 切换开销 | 大（要切换页表、TLB）| 中（同一地址空间，仍要陷入内核）| **极小（用户态切换，不陷入内核）** |
| 通信 | IPC（管道/共享内存/socket）| 直接读写共享变量（**要加锁**）| 共享变量/通道（channel）|
| 崩溃影响 | 只影响自己 | **一个线程崩了整个进程挂** | 同进程 |
| 数量级 | 几百~几千 | 几千~上万 | **几十万**（Go goroutine）|
| 谁调度 | 内核 | 内核 | 运行时/语言层 |

> **面试问"为什么线程切换比进程快"**：因为线程共享同一个地址空间，切换时**不用换页表和刷 TLB**，只需保存/恢复寄存器和栈。
> **面试问"线程越多越好吗"**：不是。线程多了上下文切换开销和锁竞争上升，`sy` 变高、性能反而下降（`vmstat` 的 `cs` 会飙升）。

## 四、缓冲 buffer 和缓存 cache（free 里合在一起，容易混）

| | buffer（缓冲）| cache（缓存）|
| --- | --- | --- |
| 目的 | **解决速度不匹配**：把零散的小写入攒起来 | **提高命中率**：把读过的数据留在内存 |
| 方向 | 偏"写" | 偏"读" |
| 例子 | 写磁盘前先在内存攒一批、管道缓冲、网卡发送缓冲 | 文件内容的 page cache、DNS 缓存、CPU cache |

> `free` 里显示成 `buff/cache`（合并一列），**它们都是可以回收的内存**，所以判断内存够不够要看 `available`（见 `05`）。

## 五、阻塞/非阻塞、同步/异步、五种 IO 模型

```text
阻塞 / 非阻塞：说的是"调用方要不要一直等"
同步 / 异步：  说的是"结果怎么通知你"（自己拿 vs 别人送上门）
```

| 模型 | 行为 | 现实例子 |
| --- | --- | --- |
| 阻塞 IO | `read()` 一直等到有数据 | 普通文件读写、简单 socket |
| 非阻塞 IO | 没数据立刻返回 `EAGAIN`，需要自己轮询 | 设置 `O_NONBLOCK` |
| **IO 多路复用** | 一个线程用 `select/poll/epoll` 同时盯上千个连接 | **Nginx、Redis、Netty** |
| 信号驱动 IO | 数据到了用信号通知 | 用得少 |
| **异步 IO** | 内核把活干完再通知你 | Linux `io_uring`、AIO |

> 前四种都算"同步 IO"（数据拷贝阶段你还是要等），只有最后一种是真正的异步 IO。

### 零拷贝（sendfile）

```text
普通读文件再发网络：磁盘 → 内核缓冲 → 用户缓冲 → socket 缓冲 → 网卡（4 次拷贝、4 次上下文切换）
sendfile：          磁盘 → 内核缓冲 → 网卡（省掉用户态那一趟）
→ Nginx 用 sendfile 传静态文件更快；类似的还有 mmap + write、splice
```

## 六、用户态 vs 内核态、系统调用

```text
CPU 有两种特权级：用户态（ring3，权限受限）和内核态（ring0，能操作硬件和所有内存）
应用程序想读文件、发网络包、创建进程，必须通过"系统调用（syscall）"陷入内核态。
→ 每次切换都有开销，这就是 top 里 sy 的来源。
```

```bash
strace -c ./程序        # 统计系统调用次数和耗时
strace -p <PID>        # 跟踪运行中的进程
ltrace                  # 跟踪库函数调用
```

> **串起来理解**：`us` 高 = 你写的代码在算；`sy` 高 = 系统调用/切换太多；容器通过 namespace 和 cgroup 限制的也是这些系统资源。

## 七、其它易混概念速查（一张表收尾）

| 概念对 | 区别要点 | 详见 |
| --- | --- | --- |
| 硬链接 / 软链接 | inode 是否相同、删源文件后是否可用 | `01b` |
| 管道 / socket | 能不能跨主机、有没有名字 | `15` |
| 块设备 / 字符设备 | 按块随机读写可挂载 / 按字符流不可挂载 | `12` |
| 虚拟内存 / 物理内存 | 进程看到的是虚拟地址，靠页表映射 | `14` |
| 缓冲 / 缓存 | 解决速度不匹配 / 提高读命中 | 本篇四 |
| 并发 / 并行 | 交替执行 / 真正同时（需多核）| 本篇一 |
| 大端 / 小端 | 多字节数据的字节序（网络字节序用大端）| 了解即可 |
| 冷备 / 热备 | 是否需要停机、数据是否实时同步 | `07` |
| RTO / RPO | 多久恢复 / 丢多少数据 | `07` |
| 蓝绿 / 灰度发布 | 整体切换 / 部分流量试探 | 了解即可 |

## 八、面试可能这么问

**Q：并发和并行有什么区别？**
A：并发是同一时间段内交替处理多个任务，单核也能做；并行是同一时刻真正同时执行，必须有多核。**并发关注"结构"，并行关注"执行速度"。** 比如 Nginx 用事件循环并发处理上千连接，但计算仍然是单线程的。

**Q：MB 和 Mb 有什么区别？**
A：B 是字节、b 是位，1 字节等于 8 位。MB 一般指兆字节（文件大小），Mb 指兆位（网络带宽）。所以 100 Mbps 带宽的理论下载速度是 12.5 MB/s。

**Q：为什么 1TB 硬盘显示只有 931G？**
A：厂商按 10 进制算（1TB = 1000^4 字节），系统按 2 进制算（1TiB = 1024^4 字节），换算是 1000^4 / 1024^3 ≈ 931。

**Q：线程和进程有什么区别？**
A：进程有独立地址空间，线程共享进程的地址空间、只独享栈和寄存器，所以线程切换更轻、通信更方便但需要加锁；一个线程崩溃会导致整个进程退出。

**Q：Redis/Nginx 为什么单线程/少量线程就能高并发？**
A：它们用 IO 多路复用（epoll）+ 事件驱动，单线程就能同时管理大量连接；高并发靠的是"并发模型"，不是靠多线程并行计算。
