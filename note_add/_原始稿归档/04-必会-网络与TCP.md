# 04 必会：网络基础、子网计算与 TCP

> **应届生级别的范围**：IP/掩码/网关/DNS 概念、会算子网、常用网络命令、三次握手、TIME_WAIT 和 CLOSE_WAIT。
> **不需要**：iptables 四表五链细节、TCP 拥塞控制（在 `进阶版/08`、`进阶版/10`）。

## 一、四个基础概念（**必须能说清**）

| 概念 | 作用 | 类比 |
| --- | --- | --- |
| **IP 地址** | 设备在网络里的唯一标识 | 详细地址 |
| **子网掩码** | 区分网络位和主机位（判断是否同网段）| 区分小区和门牌号 |
| **网关** | 通往外部网络的出口 | 小区门口的保安亭 |
| **DNS** | 把域名翻译成 IP | 查号台 |

### 一次访问的链路（能说清这个就够）

```text
访问 www.baidu.com
 ① DNS 解析：域名 → IP
 ② 判断是否同网段（用掩码算）
    · 同网段 → 直接通信（所以 ping 同网段不需要网关）
    · 不同网段 → 交给网关
 ③ 数据包交给网关 → 路由器逐跳转发 → 到达目标
 ④ 目标回包，原路返回
```

**排障口诀**：**先看本机 IP → 再看网关通不通 → 再看 DNS → 最后看端口**。

## 二、子网计算（★ 一定会考，必须会算）

### 2.1 三步法（万能公式）

**题目**：`192.168.1.100/26` 的网络地址、广播地址、可用主机数？

```text
第 1 步：算块大小
        块大小 = 256 − 掩码最后一段的值
        /26 的掩码是 255.255.255.192 → 256 − 192 = 64

第 2 步：分段，找目标落在哪一段
        0, 64, 128, 192, 256
        100 落在 64 ~ 127 → 网络地址 = 192.168.1.64

第 3 步：推导
        网络地址 = 192.168.1.64        （段起点）
        广播地址 = 192.168.1.127       （段终点）
        可用范围 = 192.168.1.65 ~ 192.168.1.126
        可用主机数 = 2^6 − 2 = 62
```

### 2.2 掩码对照表（背下来）

| CIDR | 掩码 | 块大小 | 可用主机数 |
| --- | --- | --- | --- |
| /24 | 255.255.255.0 | 256 | 254 |
| /25 | 255.255.255.128 | 128 | 126 |
| **/26** | **255.255.255.192** | **64** | **62** |
| /27 | 255.255.255.224 | 32 | 30 |
| /28 | 255.255.255.240 | 16 | 14 |
| /29 | 255.255.255.248 | 8 | 6 |
| /30 | 255.255.255.252 | 4 | 2 |

**速记**：后面三段的掩码值是 `128 192 224 240 248 252 254 255`（每组相差 128 64 32 16 8 4 2 1）。

### 2.3 练习题（自己算一遍）

**题 1**：`10.0.0.200/28` 的网络地址、广播地址、可用主机数？

```text
块大小 = 256 − 240 = 16
分段：0,16,32,...,192,208,224,240
200 落在 192~207
→ 网络地址 10.0.0.192
→ 广播地址 10.0.0.207
→ 可用 10.0.0.193 ~ 10.0.0.206
→ 主机数 2^4 − 2 = 14
```

**题 2**：`192.168.1.0/24` 要分给 4 个部门，每个部门至少 50 台机器，怎么分？

```text
需要 50 台 → 主机位要 6 位（2^6−2=62 ≥ 50）→ 掩码 /26
部门A：192.168.1.0/26      可用 .1 ~ .62
部门B：192.168.1.64/26     可用 .65 ~ .126
部门C：192.168.1.128/26    可用 .129 ~ .190
部门D：192.168.1.192/26    可用 .193 ~ .254
```

**题 3**（易错）：`192.168.1.10/24` 和 `192.168.1.200/24` 同网段吗？`/25` 呢？

```text
/24：两个的网络地址都是 192.168.1.0 → 同网段 ✓
/25：块大小 128
     10  → 落在 0~127   → 网络地址 192.168.1.0
     200 → 落在 128~255 → 网络地址 192.168.1.128
     → 不同网段 ✗
```

> **记住这句话**：**"同网段 ≠ 前三段一样"，必须结合掩码算网络地址。**

### 2.4 私有地址（知道就行）

另外：169.254.x.x 是"没拿到 DHCP 地址"的标志

## 三、常用网络命令

| 命令 | 用途 |
| --- | --- |
| `ip addr` / `ip a` | 查看本机 IP |
| `ip route` | 查看路由表（看默认网关）|
| `ping IP` | 测试网络连通性 |
| **`telnet IP 端口`** / `nc -vz IP 端口` | **测试端口通不通（比 ping 更准）** |
| **`ss -tlnp`** | **查看监听端口和对应进程（替代 netstat）** |
| `curl -I http://IP` | 测试 HTTP 接口（看状态码）|
| `nslookup 域名` | 测试 DNS 解析 |

### `ss` 参数逐个拆解（★ 另一份面经的原题）

```text
ss -lntp
   l = listening   只看处于 LISTEN 状态的（正在监听、等待连接的）
   n = numeric     不做名称解析，直接显示 IP 和端口数字（不查 DNS / 服务名，更快更准）
   t = tcp         只看 TCP 协议（u = UDP，x = Unix socket，a = 所有状态）
   p = processes   显示占用端口的进程名和 PID（★ 需要 root 或 sudo 才看得全）
```

| 写法 | 看什么 |
| --- | --- |
| **`ss -lntp`** | **本机在监听哪些 TCP 端口、分别是哪个进程**（排障最常用）|
| `ss -lunp` | 监听的 UDP 端口 |
| `ss -ant` | **所有 TCP 连接**（含 ESTABLISHED、TIME_WAIT、CLOSE_WAIT 等状态）|
| `ss -antp` | 上面再加进程信息 |
| `ss -lxnp` | Unix socket（本机进程间通信）|
| `ss -s` | 汇总统计（各类状态各有多少条）|
| `ss -tn state established` | 只看已建立的连接 |
| `ss -tn '( sport = :80 )'` | **只看 80 端口的连接**（sport = 源端口）|
| `ss -tnp dst 10.0.0.5` | 按对端地址过滤 |

> **老命令 `netstat -lntp` 参数含义完全一样**（l / n / t / p 一一对应），只是 `ss` 更快；新系统默认可能没装 netstat。

### 怎么查 80 端口的连接（★ 另一份面经第 6 题）

这题有三种理解，**面试时先说"你是问哪一种"再答**，比闷头报命令得分高：

```text
理解 A：谁在"监听"80 端口（服务起没起、监听在哪个地址）
  ss -lntp | grep :80
  lsof -i :80
  ★ 重点看是 0.0.0.0:80、*:80 还是 127.0.0.1:80 —— 后者外部访问不了

理解 B：当前有哪些连接连到 80 端口（连接数、来源、状态）
  ss -tn state established '( dport = :80 )' | head
  ss -tn | grep ':80' | wc -l                       # 连接数
  ss -tn 'sport = :80' | awk '{print $5}' | cut -d: -f1 | sort | uniq -c | sort -rn | head
                                                    # 按来源 IP 统计连接数（找异常来源）
  lsof -i :80                                       # 哪个进程占着 80

理解 C：怎么让程序"监听"80 端口
  ① 服务配置里绑定：nginx 里 listen 80;
  ② 1024 以下的端口默认需要特权 → 用 root 启动，或给二进制 CAP_NET_BIND_SERVICE 能力
  ③ 只给本机用就绑 127.0.0.1:80，对外服务绑 0.0.0.0:80
  ④ 临时测端口能不能通：nc -l 80（占住端口）→ 另一头 telnet IP 80
```

**80 端口连不上时的排查顺序**（和下面"高频场景"配套记）：

```text
① ss -lntp | grep :80     服务到底有没有在监听
② 监听地址对不对          127.0.0.1 vs 0.0.0.0
③ 防火墙放没放            firewall-cmd --list-all / iptables -L -n
④ 客户端实测              telnet IP 80 / curl -I http://IP
⑤ 还不行就抓包            tcpdump -i any -nn port 80 -c 20（看包到底有没有到网卡）
```

### 高频场景：服务本机能访问、外部访问不了

```text
① ss -tlnp | grep 端口   先看监听地址是 0.0.0.0 还是 127.0.0.1
                          （是 127.0.0.1 就说明只能本机访问，要改配置）
② 看防火墙是否放行：firewall-cmd --list-all
③ 看 SELinux 是否拦截：getenforce
④ 从客户端 telnet 端口，确认是网络不通还是应用拒绝
```

> **`ping` 通不代表服务可用** —— 判断服务要用 `telnet 端口` 或 `curl`。

## 四、TCP 三次握手与四次挥手（**背下来**）

### 4.1 三次握手（建立连接）

```text
客户端                          服务端
  │  ① SYN                        │
  │ ─────────────────────────────▶ │
  │  ② SYN + ACK                   │
  │ ◀───────────────────────────── │
  │  ③ ACK                         │
  │ ─────────────────────────────▶ │
  │         连接建立               │
```

**为什么是三次？** 让服务端确认"**客户端确实收到了我的回复，而且它还在线**"。两次的话服务端不知道客户端有没有收到，可能白白建立一个连接。

### 4.2 四次挥手（关闭连接）

```text
主动关闭方                        被动关闭方
  │  ① FIN                         │
  │ ─────────────────────────────▶ │  ← 被动方进入 CLOSE_WAIT
  │  ② ACK                         │
  │ ◀───────────────────────────── │
  │  ③ FIN                         │
  │ ◀───────────────────────────── │
  │  ④ ACK                         │
  │ ─────────────────────────────▶ │
  │  主动方进入 TIME_WAIT           │
  │  等 2MSL（60 秒）后关闭          │
```

### 4.3 TIME_WAIT 和 CLOSE_WAIT（★ 高频，能答出这个就领先）

| | **TIME_WAIT** | **CLOSE_WAIT** |
| --- | --- | --- |
| 谁会出现 | **主动关闭连接的一方** | **被动关闭的一方** |
| 含义 | 等 2MSL，确保最后的 ACK 能到达 | **对方关了，但我还没调用 close()** |
| 性质 | **正常状态**，连接正常关闭必经的阶段 | **异常状态**，说明应用没关连接 |
| 怎么解决 | 用长连接/连接池减少连接数；调内核参数缓解 | **只能改代码**（调参数没用）|

> **标准答法**：
> **"TIME_WAIT 是主动关闭连接的一方进入的正常状态，等 2MSL（Linux 上是 60 秒）才释放，作用是保证最后那个 ACK 能到达、让残留报文消散。它多了会占用本地端口，解决思路是减少短连接——用长连接或连接池。**
> **CLOSE_WAIT 就不一样了：它表示对方已经关闭连接，但我这边的应用还没调用 close()，本质是应用的 bug，调内核参数没用，只能改代码。"**

### 4.4 怎么看连接状态

```bash
ss -s                                        # 看总体统计（estab / timewait 数量）
ss -ant                                      # 看所有 TCP 连接
ss -ant | awk '{print $1}' | sort | uniq -c  # 按状态统计各有多少条

# 老写法
netstat -n | awk '/^tcp/ {++S[$NF]} END {for (a in S) print a, S[a]}'
```
