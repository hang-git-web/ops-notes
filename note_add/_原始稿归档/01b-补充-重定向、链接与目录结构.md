## 一、重定向与管道（★ 基础必考）

### 1.1 三个标准流

```text
0 = 标准输入（键盘）
1 = 标准输出（屏幕上的正常结果）
2 = 标准错误（屏幕上的报错信息）
```

### 1.2 常用写法（背下来）

| 写法 | 含义 | 典型用法 |
| --- | --- | --- |
| **`>`** | **覆盖**输出到文件 | `echo hello > a.txt` |
| **`>>`** | **追加**输出到文件 | `echo hello >> a.txt` |
| `2>` | 只把**错误**输出到文件 | `命令 2> err.log` |
| `&>` | 正确 + 错误都到文件 | `命令 &> all.log` |
| **`> f 2>&1`** | 同上（老写法，兼容性好）| `命令 > f 2>&1` |
| `2>/dev/null` | **丢弃错误**（不显示报错）| `find / -name a 2>/dev/null` |
| **`\|`（管道）** | 前一个命令的输出，当作后一个命令的输入 | `ps aux \| grep nginx` |
| `tee` | 同时输出到屏幕**和**文件 | `命令 \| tee -a log.txt` |

### 1.3 最需要记住的一句话

> **`>` 是覆盖，`>>` 是追加** —— **写日志必须用 `>>`**，用错 `>` 会把已有内容清空。

**两个高频场景**：

```bash
# ① 把命令的输出和错误都记到日志（cron 里最常用）
/shell/backup.sh >> /var/log/backup.log 2>&1

# ② 屏蔽一堆无用的权限报错
find / -name "*.conf" 2>/dev/null
```

### 1.4 管道有什么用

**把多个命令串起来**：

```bash
ps aux | grep nginx                     # 在进程列表里搜 nginx
cat app.log | grep "ERROR" | wc -l      # 统计错误行数
df -h | awk 'NR>1 {print $5, $6}'       # 只看使用率和挂载点
```

> **面试问**：**"`>` 和 `>>` 有什么区别？"** → `>` 覆盖原内容，`>>` 追加。**写日志一定要用 `>>`。**

## 二、软链接与硬链接（★ 高频）

```bash
ln  a.txt  hard.txt      # 硬链接
ln -s a.txt soft.txt     # 软链接（-s = symbol）
ls -li a.txt hard.txt soft.txt    # -i 看 inode 编号
```

| 对比 | 硬链接 | 软链接 |
| --- | --- | --- |
| 本质 | **同一个文件的另一个名字** | **存放路径的快捷方式** |
| inode 编号 | **相同** | 不同 |
| **删除源文件后** | **还能用**（数据还在）| **失效**（指向的路径没了）|
| 能否跨分区 | 不能 | 能 |
| 能否指向目录 | 通常不能 | **能** |
| 类比 | 同一个人有两个户口本 | 桌面上的快捷方式 |

**怎么判断是哪种链接**：

```bash
ls -l soft.txt
# lrwxrwxrwx ... soft.txt -> a.txt    ← 开头是 l，且有 -> 箭头，就是软链接
```

> **标准答法**：**"硬链接和源文件指向同一个 inode，相当于给文件起了个新名字，删掉源文件数据还在；软链接存的是路径，是一个快捷方式，删掉源文件就失效了。软链接可以跨分区、可以指向目录，硬链接不行。"**

### 2.1 被追问时补这 5 个细节（★ 另一份面经问过"什么是软链接"）

| 追问 | 怎么答 |
| --- | --- |
| 软链接的权限位有意义吗 | **没有**。软链接永远是 `lrwxrwxrwx`，能不能访问看**目标文件**的权限 |
| 软链接写成相对路径会怎样 | 相对路径是相对**链接文件所在目录**解析的；把链接文件挪到别处就断了（所以跨目录的链接一般写绝对路径）|
| 什么是断链（dangling link）| 目标被删或移走后：`ls -l` 里一般显示成红色，`file` 报 `broken symbolic link`；此时 `test -L` 为真、`test -e` 为假 |
| 怎么覆盖已有的链接 | `ln -sf 目标 链接名`（`-f` = 覆盖）；不加 `-f` 会报 `File exists` |
| 怎么知道它指向哪 | `ls -l` 看 `->` 箭头；`readlink 链接` 看路径；`readlink -f 链接` 解析成最终绝对路径 |

| 顺带硬链接的追问 | 怎么答 |
| --- | --- |
| 目录能做硬链接吗 | ❌ 不能（`.` 和 `..` 除外），否则目录树会出现环路 |
| 怎么看出还有几个名字 | `ls -l` 的**第二列就是链接计数**，减到 0 数据才真正释放 |

> **实战场景**（说出来比背定义有用）：版本发布常用软链接切流——`/opt/app/current -> /opt/app/v1.2`，回滚就是把链接指向 v1.1；Nginx 的 `sites-enabled` 也是指向 `sites-available` 的软链接。

## 三、环境变量与 PATH（了解）

```bash
echo $PATH                  # 查看 PATH（决定敲命令时去哪些目录找）
export MY_VAR=hello         # 定义环境变量（当前会话有效）
echo $MY_VAR
env                         # 查看所有环境变量
```

**永久生效**：写进 `~/.bashrc`（当前用户）或 `/etc/profile`（所有用户），再 `source ~/.bashrc`。

### 为什么"命令找不到"（command not found）

**因为装软件的目录不在 PATH 里**。两种解决方式：

```bash
# ① 加进 PATH（永久）
echo 'export PATH=$PATH:/usr/local/mysql/bin' >> /etc/profile
source /etc/profile

# ② 或直接用绝对路径调用
/usr/local/mysql/bin/mysql -uroot -p
```

> **典型场景**：源码编译装的 MySQL，敲 `mysql` 提示找不到——因为它装在 `/usr/local/mysql/bin/`，不在 PATH 里。
> **加分点**：**"写脚本或用 cron 的时候要用绝对路径，因为 cron 的环境变量很干净，PATH 可能不包含你要的目录。"**

## 四、目录结构（FHS，了解）

Linux 只有一棵树，根是 `/`。**记住这几个就够**：

| 目录 | 放什么 |
| --- | --- |
| **`/etc`** | **配置文件**（nginx.conf、my.cnf 都在这）|
| **`/var`** | **可变数据**：日志（`/var/log`）、缓存、网站 |
| `/usr` | 系统软件和库 |
| `/home` | 普通用户的家目录 |
| `/root` | root 的家目录 |
| `/tmp` | 临时文件（**重启会清空**）|
| **`/proc`** | **虚拟文件系统**，反映内核实时状态（`cat /proc/cpuinfo`、`/proc/meminfo`）|
| `/dev` | 设备文件（如 `/dev/sda`）|
| `/boot` | 内核和引导文件（别乱动）|

> **面试可能问**：**"配置文件一般放在哪个目录？"** → `/etc`。**"日志放在哪？"** → `/var/log`。

## 五、前后台任务（了解）

```bash
命令 &                  # 把命令丢到后台运行
jobs                    # 查看当前终端的后台任务
fg %1                   # 把 1 号任务调回前台
bg %1                   # 把任务放到后台继续跑
Ctrl + Z                # 把正在跑的前台任务挂起（暂停）
Ctrl + C                # 结束正在跑的前台任务
nohup ./run.sh &        # 退出终端也不中断地跑
```

| 概念 | 说明 |
| --- | --- |
| `&` | 后台运行，**但退出终端可能被挂断** |
| **`nohup`** | **退出终端也不中断**（no hang up），配合 `&` 用 |
| `Ctrl+C` vs `Ctrl+Z` | 前者**结束**进程；后者只是**暂停**（挂到后台）|

> **面试问**：**"怎么让程序在退出终端后继续跑？"** → `nohup ./run.sh &`；生产环境更推荐写成 systemd 服务。
