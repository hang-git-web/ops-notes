# 00 答题方法与四道场景题

> **本章考什么**：不是知识点，是**答题的框架**。
> 应届生面试里，「会不会」只占一半分，另一半是「**说得清不清楚、有没有结构**」。
> 这一章包含：AI 面的评分逻辑 → 两种答题模板 → **四道必背场景题**。
> **这一章不背完，后面全部白背。**

---

## 一、先搞清：AI 面对应届生到底考什么

```text
70%  基础命令 + 基础概念 + 你的项目经历      ← 决定你过不过
25%  简单场景题（"CPU 高怎么查"这类）        ← 决定你排名靠前还是靠后
 5%  底层原理细节                            ← 应届生基本不会被问到底
```

**AI 面的评分特点**：

```text
① 逐项打分 —— 一个知识点清单里少说一项，这一项就是 0 分（不是扣一点，是没分）
② 顺着你的回答追问 —— 你提什么，它问什么，所以要准备"第二层"
③ 看重关键词 —— 说出 `partprobe`、`available`、`2MSL` 这类词，分数立刻不一样
```

> **推论**：把基础题答得**利索、有结构、有术语**，比把难题答得含糊，得分高得多。
> **所以今天的目标不是"学更多"，是"把已经会的说清楚"。**

## 二、两种答题模板（直接套，不要临场想）

### 模板 A：概念题 → 四句话

```text
① 定义    它是什么（一句话 + 一个类比）
② 本质    背后机制是什么、为什么需要它
③ 怎么用  命令 / 参数 / 一个真实例子
④ 注意点  坑、上限、最容易混的那个东西
```

**用「什么是软链接」示范**：
> ① 它是存目标路径的「快捷方式」文件。
> ② 它和目标文件是两个不同的 inode，内核访问时按存的路径重新解析 —— 所以能跨文件系统、能指向目录，但目标删了它就变成断链。
> ③ `ln -s /opt/app/v1.2 /opt/app/current`，发布切版本、回滚都靠它。
> ④ 它自己的权限位没意义（永远 `lrwxrwxrwx`，看的是目标文件权限）；覆盖已有链接要用 `ln -sf`；用相对路径创建时是相对**链接所在目录**解析，移动链接会断。

> 按这个模板答，任何概念题都能撑满 **40 秒**，而且面试官想追问的点你**已经提前堵住了**。

### 模板 B：场景题 → 五步

```text
① 分层定位  先判断是哪一类资源的问题（服务 / CPU / 内存 / 磁盘 / 网络）
② 看指标    top / free / df / vmstat / iostat / ss —— 各看哪个字段
③ 定进程    ps、top -H、lsof —— 缩小到具体进程或线程
④ 处理      扩容 / 回滚 / 修配置 / 清日志 / 杀异常进程
⑤ 验证留痕  再看指标确认回落；处理前先留一份现场
```

> **第 ⑤ 步是加分项，也是应届生最容易漏的一步**：说一句「我会先留一份现场（`top`/`vmstat`/`iostat` 输出），避免处理完查不到原因」，可信度立刻不同。

## 三、四道场景题（★★★ 今天必须背下来）

> 这四题是应届生面试的**送分区**，也是原稿 `05` 里最重要的内容。
> 每题都按「**先定位是哪类资源 → 再看指标 → 再定位进程 → 最后处理**」来说。

---

### 场景题 1：服务器 CPU 使用率 100%，你怎么查？

> **面试官会这么问**：线上有台机器 CPU 一直 100%，你远程上去怎么查？
> **考察点**：性能排查方法论 · top 字段含义 · 分层定位能力
> **变体**：四核机器从 20% 飙到 100%，怎么查？（面经①第 15 题，见 09-Q7 的完整版）

```text
① 先用 top 找出是哪个进程（按 P 键按 CPU 排序），记下 PID
② 看是什么原因导致的：
   · us 高 → 应用自己在算（死循环、复杂正则、频繁 GC）
   · sy 高 → 系统调用 / 上下文切换太多
   · wa 高 → 其实是在等磁盘 IO，不是 CPU 的问题（加 CPU 没用）
   · hi/si 高 → 网络（大流量、小包、被攻击）
   · st 高 → 宿主机超卖（云主机），你自己无能为力
③ 深入到进程内部：
   · 通用 → top -H -p <pid> 看是哪个线程在占 CPU
   · Java → jstack <pid> 看线程栈；jstat -gcutil 看 GC
④ 最后处理：业务高峰就扩容；代码 bug 就回滚或修；不该跑的进程就杀掉
⑤ 处理前后各留一份现场（top / vmstat / iostat 输出）
```

**必说的一个点**：**四核机器上单线程死循环最多只能吃 25%**（一个核），所以必须用 `top -H -p` 看到线程级，才能定位到具体线程。

---

### 场景题 2：内存不够（内存快满了）怎么查？

> **面试官会这么问**：监控告警说内存使用率 95%，你怎么处理？
> **考察点**：free 各字段 · available vs buff/cache · 换页判断
> **变体**：free 里 buff/cache 占了 8G，是内存不足吗？（这题几乎必问）

```text
① free -h —— 重点看 available（不是看 free，也不是看 used）
② 如果 buff/cache 很大 —— 那是缓存，不是内存不足（应用需要时会自动回收）
③ vmstat 1 —— 看 si/so（换入换出），持续非 0 才说明真的缺内存
④ ps aux --sort=-%mem | head —— 找出占内存最大的进程
⑤ dmesg | grep -i oom —— 看有没有进程被 OOM Killer 杀掉过
```

**一句话结论**（面试直接这么说）：
> 「`free` 里 `buff/cache` 大是正常的，那是**缓存**；判断内存够不够要看 **`available`** —— 它才是应用真正还能拿到的内存。只有 `vmstat` 里 `si/so` 持续不为 0，才说明内存真的紧张。」

### 场景题 3：磁盘满了怎么查？

> **面试官会这么问**：告警说磁盘使用率 100%，服务写不了日志了，你怎么查？
> **考察点**：df vs du · 磁盘排查步骤 · inode / deleted file 两个特例

```text
① df -h —— 先确认是哪个分区满了
② du -sh /* | sort -h —— 在该分区里逐层往下找大目录
③ 找到大文件后判断是日志、备份还是垃圾，再清理或转移
④ 如果是日志 → 清理并配置 logrotate 自动轮转（治本）
⑤ 特例：df 显示有空间但写不进 → df -i 查 inode 是否用满
⑥ 特例：删了文件空间没释放 → lsof | grep deleted，重启对应进程释放
```

**加分点**：第 ⑤⑥ 条能说出来，说明你**真踩过坑**，不是背的。

---

### 场景题 4：服务起不来 / 端口访问不通，怎么查？

> **面试官会这么问**：nginx 起不来了 / 网站访问不了，你怎么排查？
> **考察点**：systemd 排障 · 端口监听 · 权限与磁盘这类"容易忽略的一环"

```text
① systemctl status 服务        —— 看状态和错误提示
② journalctl -u 服务 -n 50     —— 看完整日志
③ ss -tlnp | grep 端口         —— 端口有没有被占用、服务有没有在监听
④ 检查配置文件语法（如 nginx -t）
⑤ 检查目录权限和属主（数据目录、日志目录）
⑥ 检查磁盘是否满（df -h）      —— ★ 最容易忽略的一条
⑦ 如果是"本机能访问、外部不能"：
   · 先看监听地址是 0.0.0.0 还是 127.0.0.1（后者外部访问不了）
   · 再看防火墙（firewall-cmd --list-all / ufw status）
   · 再看 SELinux（getenforce）
   · 最后从客户端 `telnet IP 端口` 实测，还不行就抓包
```

## 四、四个「万能补一句」（临场救场用）

```text
① 被问不会的题：
   "这块我目前掌握到 X 层，我的理解是……（说出你会的部分），更深的机制我还在学。"
   —— 比沉默或硬编好得多。

② 被问"你做过吗"：
   一定要落到具体命令 + 一个具体现象，例如"我遇到过一次 df 有空间但写不进，df -i 一看 inode 满了"。

③ 被追问"为什么"：
   往"机制"两个字上靠：进程/内核/内存/磁盘 IO，讲哪一层在干什么。

④ 面试收尾必问"你有什么想问的"：
   问「这个岗位日常最常处理的故障类型是什么」比问「加不加班」加分得多。
```

## 五、本章追问链（AI 面试的真实套路）

```text
CPU 100%  →  你怎么知道是应用还是系统？（us vs sy）
          →  wa 高说明什么？怎么办？
          →  单线程死循环在四核上占多少？（25%）
          →  怎么看线程？（top -H -p / ps -L）

内存快满  →  buff/cache 是不是内存不足？
          →  判断够不够看哪个字段？（available）
          →  什么信号说明真的缺内存？（si/so 持续非 0）
          →  被 OOM 杀了怎么看？（dmesg | grep -i oom）

磁盘满    →  df 和 du 区别？
          →  du 找不到大文件怎么办？（inode / deleted file）
          →  日志怎么防止写满？（logrotate）

服务起不来 →  端口在听但访问不了，先查什么？（监听地址 0.0.0.0 vs 127.0.0.1）
          →  都正常还不行？（防火墙 / SELinux / 抓包）
```
