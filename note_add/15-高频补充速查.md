# 15 高频补充速查

> **本章定位**：那些**零散但会突然被问到**的东西 —— 记结论就行，不用背原理。
> **包含**：系统信息命令、时间同步、内核参数（sysctl）、Shell 文本处理三件套（grep/awk/sed）、日志统计、日常巡检脚本。

## 一、系统信息（面试可能随口问）

### Q1 面试官：怎么查看系统版本、内核版本、CPU 核数、内存大小？

> **考察点**：基础信息命令 · 别说混

| 想看什么 | 命令 |
| --- | --- |
| 发行版 | `cat /etc/os-release`（RHEL 系也可 `cat /etc/redhat-release`） |
| **内核版本** | **`uname -r`**（`uname -a` 看全部） |
| **CPU 核数** | **`nproc`** 或 `lscpu`（`lscpu` 能看到物理核 / 逻辑核、频率、架构） |
| 内存大小 | `free -h`；硬件细节用 `dmidecode -t memory` |
| 主机名 | `hostname` / `hostnamectl` |
| 运行时长 + 负载 | `uptime`（`uptime -s` 看开机时间点） |
| 磁盘 | `df -h` / `lsblk` |
| 在线用户 / 登录历史 | `who` / `w` / `last` |
| 硬件总览 | `dmidecode`（需要 root） |

> **★ 最容易混的一对**：**`uname -r` 是内核版本，`cat /etc/redhat-release`（或 `/etc/os-release`）是发行版版本** —— 面试问"你的系统是什么版本"，两个都要能报出来。

### Q2 面试官：服务器时间不对会有什么影响？怎么同步时间？

> **考察点**：时间同步 · 集群一致性的意识

**时间不对的影响（★ 按这几条说）**：

```text
1) 日志时间错乱 → 排查故障时对不上时间线
2) 证书校验失败（HTTPS、集群通信都依赖时间）
3) 集群 / 主从数据不一致（依赖时间戳的逻辑会出问题）
4) 定时任务跑错时间（cron 按系统时间触发）
5) 分布式系统的日志追踪、事务顺序错乱
```

**怎么同步**：

```bash
timedatectl                       # 看当前时间、时区、NTP 是否开启
timedatectl set-timezone Asia/Shanghai
timedatectl set-ntp true          # 开启自动同步

# chrony（CentOS 7+ / RHEL 8+ 默认）
chronyc sources -v                # 看时间源
chronyc tracking                  # 看偏差（System time 那行）
systemctl status chronyd

# 老工具（CentOS 6 / 简单场景）
ntpdate ntp1.aliyun.com           # 一次性同步（不能与 ntpd 同时跑）
```

> **加分**：**「生产上我会用 `chronyd` 而不是 `ntpdate` —— `ntpdate` 是跳变时间，会打断依赖时间连续性的服务；`chronyd` 是渐进调整。另外集群里最好指同一批时间源。」**

## 二、内核参数（sysctl）

### Q3 面试官：内核参数怎么改？临时和永久有什么区别？你改过哪些？

> **考察点**：sysctl · **能报出几个真实参数就是加分**

```bash
# 临时改（重启失效）
sysctl -w vm.swappiness=10
echo 10 > /proc/sys/vm/swappiness

# 永久改（推荐写独立的 conf 文件，别直接改 /etc/sysctl.conf）
echo 'vm.swappiness=10' > /etc/sysctl.d/99-tunning.conf
sysctl -p /etc/sysctl.d/99-tunning.conf     # 重新加载
sysctl -a | grep swappiness                 # 确认生效
```

**常改的参数（★ 背 4~5 个，面试能报出来就很稳）**：

| 参数 | 作用 | 什么时候调 |
| --- | --- | --- |
| `net.ipv4.ip_forward` | 是否开启 IP 转发 | 做网关 / 容器 / VPN 时开 1 |
| `net.core.somaxconn` | **监听队列最大长度** | 高并发时调大（配合应用 backlog） |
| `net.ipv4.tcp_max_syn_backlog` | SYN 队列长度 | 抗 SYN Flood / 高并发 |
| `fs.file-max` | 系统级最大文件句柄数 | 句柄不够时调大 |
| `net.ipv4.tcp_tw_reuse` | 复用 TIME_WAIT 端口 | TIME_WAIT 太多时（只影响主动发起方） |
| `vm.swappiness` | 换出匿名页的倾向 | 数据库调 1~10 |
| `vm.overcommit_memory` | 是否允许内存超额分配 | Redis 官方建议设 1 |
| `net.ipv4.tcp_fin_timeout` | FIN_WAIT2 超时 | 缩短连接释放时间 |
| `kernel.pid_max` | 最大 PID 数 | 进程数非常多时 |

> **注意**：`tcp_tw_recycle` 在新内核已被**移除**（NAT 环境下会误杀连接），别再提它。

## 三、Shell 文本处理三件套

### Q4 面试官：`grep`、`awk`、`sed` 分别适合做什么？各举一个例子。

> **考察点**：Shell 数据处理能力 · **面试常出"统计日志"这种题**

| 工具 | 定位 | 例子 |
| --- | --- | --- |
| **`grep`** | **按行筛选**（找内容） | `grep -n "ERROR" app.log` |
| **`awk`** | **按列处理 / 统计 / 格式化** | `df -h 管道符 awk 'NR>1 {print $5, $6}'` |
| **`sed`** | **按行编辑 / 替换** | `sed -i 's/old/new/g' a.conf` |

> **一句话记忆**：**`grep` 是"挑行"，`awk` 是"挑列"，`sed` 是"改行"。**

**其它常用文本工具**：

```bash
cut -d: -f1 /etc/passwd        # 按分隔符取列（取用户名）
sort -rn                        # 按数字倒序
uniq -c                         # 去重并计数（必须先 sort）
wc -l / wc -c                   # 统计行数 / 字节数
tr 'a-z' 'A-Z'                  # 字符转换
xargs                           # 把前一个命令的输出变成后一个命令的参数
```

---

### Q5 面试官：怎么统计日志里访问次数最多的 IP 或状态码？（★ 经典题）

> **考察点**：管道组合能力 · **这题几乎是 Shell 面试的标配**

```bash
# 访问次数最多的 10 个 IP（Nginx access.log 里第 1 列是 IP）
awk '{print $1}' access.log | sort | uniq -c | sort -rn | head

# 状态码分布（第 9 列是状态码）
awk '{print $9}' access.log | sort | uniq -c | sort -rn

# 只看 5xx 并统计来源
awk '$9 ~ /^5/ {print $1}' access.log | sort | uniq -c | sort -rn | head

# 统计某个时间段（14:00-15:00）
awk '$4 ~ /14:[0-9]{2}:[0-9]{2}/ {c++} END {print c}' access.log
```

> **★ 背下这个"万能管道"**：
> `awk '{print $N}' file | sort | uniq -c | sort -rn | head`
> —— 统计任何"某一列出现次数排行"都是这个套路。`uniq -c` **必须跟在 `sort` 后面**（uniq 只能合并相邻的重复行）。

### Q6 面试官：怎么批量替换一批文件里的内容？怎么在大目录里快速搜关键字？

> **考察点**：批量操作 · 有没有踩过"改动前先备份"

```bash
# 批量替换（先看改哪些，再改）
grep -rl 'old' /etc/nginx/ --include='*.conf'                 # 先列出要改的文件
grep -rl 'old' /etc/nginx/ --include='*.conf' | xargs sed -i 's/old/new/g'

# 大目录搜关键字
grep -rn --include='*.log' 'ERROR' /var/log
rg 'ERROR' /var/log            # ripgrep，比 grep 快很多（装了就用）

# find + exec（比 xargs 更稳，能处理带空格的文件名）
find /data -name "*.conf" -exec sed -i 's/old/new/g' {} +
```

> **★ 安全意识（说出来加分）**：**「批量替换前我会先 `grep -rl` 列出要改的文件、先备份、并且用 `sed -i.bak` 留一份原文件，确认没问题再清理备份。」**

### Q7 面试官：写 shell 脚本有哪些必须注意的点？

> **考察点**：脚本规范 · 生产意识

```text
1) 首行写 #!/bin/bash
2) 开头加 set -euo pipefail
   e = 出错就退出     u = 用未定义变量报错     pipefail = 管道任一环失败也算失败
3) 变量加双引号：rm -rf "$DIR"/    ← 不加引号时 $DIR 为空就变成 rm -rf /
4) 命令用绝对路径（cron 里尤其重要，见 03-Q8）
5) 重要操作先做检查再执行（判断目录存在、判断参数个数）
6) 日志重定向：>> /var/log/xxx.log 2>&1
7) 调试用 bash -x script.sh（看每一步执行了什么）
```

> **★ 面试必答的一条**：**「变量引用一定要加双引号。`rm -rf $DIR/` 当 `$DIR` 为空时就等于 `rm -rf /`；`"$DIR"` 则安全。这是最经典的 Shell 事故。」**

## 四、日常巡检脚本

### Q8 面试官：写一个日常巡检脚本，你会检查哪些项？

> **考察点**：运维体系 · **能不能把前面的知识串成一个脚本**

**先说检查项（★ 按分类说，显得成体系）**：

```text
资源：负载与 CPU、内存和 swap、磁盘使用率【和 inode】
服务：关键服务是否存活、端口是否监听
日志：错误关键字统计、登录失败次数
数据：备份是否成功、备份文件大小是否正常、证书到期时间
输出：结果输出成报告，或发到告警渠道
```

**一个可用的骨架**：

```bash
#!/bin/bash
# 日常巡检脚本：资源 + 服务 + 端口
set -uo pipefail

REPORT=/tmp/check_$(date +%F).log

{
  echo "========== 巡检时间: $(date '+%F %T') 主机: $(hostname) =========="

  echo "--- 1. 负载与 CPU ---"
  uptime
  echo "核数: $(nproc)"

  echo "--- 2. 内存与 swap ---"
  free -h

  echo "--- 3. 磁盘使用率（>80% 告警）---"
  df -hP | awk 'NR>1 && int($5)>80 {print "  [警告] " $5, $6}'
  df -hP | awk 'NR==1 || int($5)>80'
  echo "inode 使用率:"
  df -iP | awk 'NR>1 && int($5)>80 {print "  [警告] " $5, $6}'

  echo "--- 4. 关键服务 ---"
  for svc in nginx mysql sshd; do
    printf "  %-10s %s\n" "$svc" "$(systemctl is-active "$svc" 2>/dev/null)"
  done

  echo "--- 5. 监听端口 ---"
  ss -lntp | awk 'NR>1 {print "  " $4}'

  echo "--- 6. 登录失败次数（今日）---"
  grep "$(date '+%b %e')" /var/log/secure 2>/dev/null | grep -c "Failed password"
} >> "$REPORT" 2>&1

echo "巡检完成，报告: $REPORT"

# 挂到 crontab：每天早上 8 点
# 0 8 * * * /shell/daily_check.sh
```

> **★ 加分**：**「脚本只是"能看见"，真正的运维还要有"能告警"—— 所以巡检结果我会再推给监控/告警渠道（邮件、钉钉、企业微信 Webhook），而不是只写进一个没人看的文件。」**
