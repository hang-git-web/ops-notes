# 11 日志、定时任务与安全

> **本章考什么**：会不会看日志、会不会配定时任务、出问题会不会往"权限/安全"方向查。
> **关键词**：`/var/log` 各文件、tail -f / grep -C / journalctl、logrotate、cron 五颗星、`*/5` vs `5`、防火墙、SELinux、SSH 加固。

## 一、日志

### Q1 面试官：Linux 的日志都在哪？各记什么？

> **考察点**：日志文件位置 · CentOS 和 Ubuntu 的差异
> **来源**：面经①押题方向（"会不会看日志"是运维基本功）

**系统日志统一放在 `/var/log/` 下**：

| 文件 | 内容 |
| --- | --- |
| `/var/log/messages` | **系统主日志**（服务运行、系统消息）**← CentOS/RHEL** |
| `/var/log/syslog` | 同上 **← Ubuntu/Debian** |
| `/var/log/secure` | **安全日志**（登录、sudo）← CentOS |
| `/var/log/auth.log` | 同上 ← Ubuntu |
| `/var/log/cron` | **定时任务执行记录** |
| `/var/log/dmesg` | 内核 / 硬件日志 |
| `/var/log/nginx/access.log` | 应用日志（在应用自己的目录下） |

> **加分**：**「CentOS 和 Ubuntu 的日志文件名不一样 —— CentOS 是 `messages` + `secure`，Ubuntu 是 `syslog` + `auth.log`。这个区别面试官很爱用来判断你是不是只在一种系统上做过。」**

---

### Q2 面试官：怎么看日志？怎么在日志里找报错？

> **考察点**：日志查看命令 · 会不会过滤

```bash
cat /var/log/messages            # 小文件直接看
less /var/log/messages           # 大文件用 less（可上下翻、/ 搜索、q 退出）
tail -n 50 /var/log/messages     # 看最后 50 行
tail -f /var/log/nginx/access.log    # ★ 实时跟踪（最常用）
tail -F app.log                      # -F：文件被轮转后还能跟住新文件

# 过滤
grep -n "ERROR" app.log              # 找错误，带行号
grep -C 3 "ERROR" app.log            # 显示错误前后各 3 行（排障很有用）
tail -f app.log | grep "ERROR"       # 实时只看错误
grep "Failed password" /var/log/secure | wc -l   # 统计登录失败次数（安全排查）

# 看服务自己的日志（systemd 托管）
journalctl -u nginx -n 50            # 该服务最近 50 行
journalctl -u nginx -f               # 实时跟踪
```

**`journalctl` 常用参数（★ 面经爱问）**：

| 参数 | 作用 |
| --- | --- |
| `-u 服务` | 按服务过滤 |
| `-f` | 实时跟踪 |
| `--since "1 hour ago"` | 时间范围（也支持 `--since today`） |
| `-p err` | 只看错误级别及以上 |
| `-b` | 本次开机（`-b -1` 上次开机） |
| `-k` | 只看内核日志（等价 `dmesg`） |
| `--disk-usage` | 看 journal 占了多少磁盘 |

> **journalctl 的坑**：`/var/log/journal` 不做限制的话会无限增长。要改 `/etc/systemd/journald.conf` 里的 `SystemMaxUse=`，或者定期 `journalctl --vacuum-size=500M`。

### Q3 面试官：日志文件太大怎么办？（★ 会被问）

> **考察点**：logrotate · 日志把磁盘写满这个经典事故

**问题**：日志会一直增长，不管它，迟早把磁盘写满，**业务就挂了**。

**logrotate 就是解决这个的**：自动完成 **切割 → 压缩 → 删除旧日志 → 通知服务重开日志**。

```bash
# 配置文件放这里（每个服务一个文件）
/etc/logrotate.d/nginx

# 一个典型配置
/var/log/nginx/*.log {
    daily                  # 每天轮转
    rotate 7               # 保留 7 份，更旧的自动删除
    compress               # 压缩旧日志
    missingok              # 文件不存在也不报错
    notifempty             # 空文件不轮转
    create 644 nginx adm   # 轮转后重建日志文件并设权限
    postrotate
        kill -USR1 $(cat /var/run/nginx.pid)   # 通知 nginx 重新打开日志文件
    endscript
}
```

**测试命令（★ 说出来显得真配过）**：

```bash
logrotate -d /etc/logrotate.d/nginx    # 只检查不执行（debug，看它打算怎么切）
logrotate -f /etc/logrotate.d/nginx    # 强制立刻轮转一次（验证配置对不对）
```

> **面试标准答法**：
> **Q：日志文件太大怎么办？**
> A：「配置 **logrotate** 做日志轮转 —— 按天或按大小切割、压缩旧日志、只保留最近 N 份。另外要加 `postrotate` 通知服务重新打开日志文件，否则服务会继续往改名后的旧文件里写。」

---

### Q4 面试官：为什么日志轮转后要给服务发信号？（★ 追问）

> **考察点**：文件句柄 · 理解"进程持有的是 fd 不是文件名"

> **答**：**因为进程还开着原来那个文件句柄**。logrotate 只是把 `app.log` **改名**成 `app.log.1`，进程手里的句柄还指向那个 inode，于是会**继续往旧文件里写** —— 结果新日志文件是空的，旧文件还在涨。
> 所以要用 `postrotate` 发信号（Nginx 是 `USR1`、其它服务常是 `HUP`），**让进程重新打开一个新的日志文件**。

> **这个原理和"删了文件空间没释放"是同一件事**（`08-Q2`）—— 都是"进程持有 fd，文件名消失了但 inode 还在"。能把这两处串起来讲，面试官会觉得你理解得深。

## 二、定时任务（cron）

### Q5 面试官：cron 的语法是什么？`*/5 * * * *` 和 `5 * * * *` 有什么区别？

> **考察点**：crontab 五颗星 · **最高频的一个坑**

```bash
crontab -e      # 编辑当前用户的定时任务
crontab -l      # 查看
crontab -r      # 删除所有（★ 没有确认，慎用）
```

**语法：五颗星**：

```text
分   时   日   月   周    命令
*    *    *    *    *    /path/to/script.sh

取值范围：
分 0-59   时 0-23   日 1-31   月 1-12   周 0-7（0 和 7 都是周日）
```

**常用示例**：

```bash
0 3 * * *      /shell/backup.sh      # 每天凌晨 3 点
*/5 * * * *    /shell/check.sh       # 每 5 分钟
0 9 * * 1-5    /shell/work.sh        # 周一到周五 9 点
@reboot        /shell/start.sh       # 开机执行
```

**★ 最高频的坑**：

```text
*/5 * * * *   每 5 分钟执行一次（一天 288 次）    ← 想要"每5分钟"用这个
5 * * * *     每小时的第 5 分钟执行（一天 24 次）  ← 容易写错
```

---

### Q6 面试官：cron 任务不执行，你怎么排查？（★ 会被问）

> **考察点**：cron 环境 · **90% 是三个原因**

```text
1) systemctl status crond        服务有没有在跑
2) crontab -l                    表达式对不对（★ 重点看 */5 还是 5）
3) tail -f /var/log/cron         有没有执行记录
4) 脚本里用绝对路径                cron 的环境变量极简，找不到命令（见 03-Q8）
5) 脚本有执行权限                 chmod +x，以及首行有没有 #!/bin/bash
6) % 要转义成 \%                  cron 里 % 表示换行，是特殊字符
7) 手动 bash -x 跑一遍            定位到底是脚本本身的问题还是 cron 的问题
```

> **★ 加分点**：**「cron 不执行，90% 是三个原因：**表达式写错、脚本里用了非绝对路径、脚本没有执行权限**。」**

> **cron 的另一个坑**：**命令的输出默认会以邮件形式发给用户**（系统没配 MTA 会报错）。所以脚本末尾要自己重定向：`/shell/backup.sh >> /var/log/backup.log 2>&1`。

---

### Q7 面试官：写一个"每天备份 + 每周清理旧备份"的脚本，你的思路？

> **考察点**：脚本规范 · 安全意识 · 有没有真写过

```bash
#!/bin/bash
set -euo pipefail

BACKUP_DIR=/backup
SRC_DIR=/data
DATE=$(date +%F)

# 1) 归档
tar -czf "${BACKUP_DIR}/db_${DATE}.tar.gz" "${SRC_DIR}"

# 2) 校验（★ 这一步最能体现"备份意识"）
tar -tzf "${BACKUP_DIR}/db_${DATE}.tar.gz" > /dev/null && echo "verify ok"

# 3) 清理 30 天前的旧备份
find "${BACKUP_DIR}" -name "*.tar.gz" -mtime +30 -delete
```

```bash
# 挂到 crontab
0 3 * * *   /shell/backup.sh >> /var/log/backup.log 2>&1
```

> **思路要点（面试就按这四步说）**：**归档 → 校验 → 清理 → 挂计划任务 + 日志重定向**。
> **再加一句加分**：「重要备份我会再用 `rsync` 推到远端，并且**定期做恢复演练** —— 没验证过的备份不算备份。」

## 三、防火墙

### Q8 面试官：怎么放行一个端口？firewalld 和 iptables 是什么关系？

> **考察点**：firewalld/iptables/ufw · 端口放行了还是不通

```bash
# CentOS（firewalld）
firewall-cmd --list-all                                   # 查看当前规则
firewall-cmd --add-port=80/tcp --permanent                # 永久放行 80
firewall-cmd --reload                                     # 重载生效

# Ubuntu（ufw）
ufw status
ufw allow 80

# 直接看 iptables 规则
iptables -L -n
```

| 问题 | 答案 |
| --- | --- |
| firewalld 和 iptables 什么关系 | **firewalld 是管理工具（前端），底层还是用 iptables/nftables**。两者**不能同时用** |
| 放行了端口但还是不通 | ① 看**监听地址**（`ss -tlnp`，是 `0.0.0.0` 还是 `127.0.0.1`）② 看云平台**安全组** ③ 看 SELinux ④ 看服务是不是真的起来了 |

> **`--permanent` 的坑**：不加 `--permanent` 只是**临时**生效，重启就没了；加了之后**必须 `--reload`** 才生效。这两个是 firewalld 最常见的坑。

## 四、SELinux

### Q9 面试官：SELinux 是什么？有哪三种模式？被它拦了怎么查？

> **考察点**：强制访问控制 · **"改了权限还是 Permission denied"的排查方向**

**一句话理解**：

> SELinux 是 Linux 的**强制访问控制**机制：除了传统的 rwx 权限，它还检查「**这个进程能不能访问这个文件**」，**即使你是 root 也可能被拦。**

**三种模式（★ 记住这三个词）**：

| 模式 | 行为 |
| --- | --- |
| **enforcing** | 强制（拒绝违规访问并记录）← **生产应该是这个** |
| **permissive** | 宽容（不拒绝，但记录）← **排障时临时用** |
| **disabled** | 关闭 |

```bash
getenforce            # 查看当前模式
setenforce 0          # 临时切到 permissive（重启失效）
setenforce 1          # 切回 enforcing
ls -Z /var/www/html   # 看文件的安全上下文（可以对比正常文件的标签）
```

**被拦了怎么查（★ 记住这个流程）**：

```text
1) getenforce                   确认 SELinux 是否开启
2) setenforce 0                 临时切成 permissive，再试一次
                                → 如果成功了，就说明是 SELinux 的问题
3) ausearch -m avc -ts recent   查看具体的拒绝记录（AVC 日志）
                                也可以看 /var/log/audit/audit.log
4) 修复：
   · restorecon -Rv 目录          恢复文件默认的标签
   · setsebool -P 开关 on         开启对应的策略开关
     （★典型场景：Nginx 做反向代理时报 502，就是 httpd_can_network_connect 没开）
5) setenforce 1                 记得切回去
```

> **★ 标准答法（背这一段）**：
> 「如果改了权限还是 **Permission denied**，我会怀疑 SELinux。判断方法很简单：`setenforce 0` 临时关掉再试一次，如果通过了就是 SELinux 的问题；然后用 `ausearch -m avc` 看具体的拒绝记录，用 `restorecon` 或 `setsebool` **精确放行**，而**不是直接关掉 SELinux**。」

> **为什么强调"不要直接关"**：生产关 SELinux 等于放弃一层防护，而且关掉要改配置 + 重启。**能精确放行才是运维水平。**

## 五、SSH 加固与安全排查

### Q10 面试官：SSH 你会做哪些安全加固？

> **考察点**：安全基线 · 有没有安全意识的加分项

| 加固项 | 做法 |
| --- | --- |
| **禁用 root 直接登录** | `/etc/ssh/sshd_config` 里 `PermitRootLogin no` |
| **只用密钥认证** | `PasswordAuthentication no` + 分发公钥 |
| 改默认端口 | `Port 2222`（降低扫描命中率，但**不是安全措施，只是减少噪音**） |
| 限制来源 IP | 防火墙只放行跳板机/办公网；或用 `AllowUsers`、`Match` 块 |
| **失败次数限制** | `fail2ban`，多次失败自动封 IP |
| 保持版本更新 | 定期打补丁（OpenSSH 漏洞不少） |
| 会话超时 | `ClientAliveInterval` + `ClientAliveCountMax` |

```bash
sshd -t                # 改完先测语法（★ 改 sshd 前千万别重启失败，会把自己关在门外）
systemctl reload sshd  # 用 reload 而不是 restart 更稳
```

> **★ 面试能加的实战细节**：「改 `sshd_config` **一定先 `sshd -t` 测语法**，而且**保留一个已经登录的会话别关**，确认新会话能连上再退出 —— 否则配置写错就再也连不进去了。」这句话能证明你真改过。

**安全排查常用命令**：

```bash
last -n 20                                  # 最近登录历史（看有没有异常来源）
grep "Failed password" /var/log/secure | awk '{print $(NF-3)}' | sort | uniq -c | sort -rn | head
                                            # 统计暴力破解来源 IP
who / w                                     # 当前在线用户
find / -perm -4000 -type f 2>/dev/null      # 找出所有 SUID 文件（排查后门）
find / -mtime -1 -type f 2>/dev/null        # 最近一天被改过的文件
rpm -Vf /usr/bin/xxx                        # 校验包文件有没有被改
```
