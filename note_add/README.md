## 五、答题模板（直接套）

### 模板 A：概念题 —— 四句话

```text
① 定义   它是什么（一句话 + 一个类比）
② 本质   背后机制是什么、为什么需要它
③ 怎么用 命令 / 参数 / 一个真实例子
④ 注意点 坑、上限、最容易混的那个东西
```

**示范（什么是软链接）**：
> ① 它是存目标路径的「快捷方式」文件；② 和目标是两个不同的 inode，内核按存的路径重新解析，所以能跨文件系统、能指向目录，但目标删了就断链；③ `ln -s /opt/app/v1.2 /opt/app/current`，发布切版本和回滚都靠它；④ 它自己的权限位没意义（永远 `lrwxrwxrwx`，看目标文件），覆盖已有链接要用 `ln -sf`。

### 模板 B：场景题 —— 五步

```text
① 分层定位：先判断是哪一类资源的问题（服务 / CPU / 内存 / 磁盘 / 网络）
② 看指标  ：top / free / df / vmstat / iostat / ss，各看哪个字段
③ 定进程  ：ps、top -H、lsof，缩小到具体进程或线程
④ 处理    ：扩容 / 回滚 / 修配置 / 清日志 / 杀异常进程
⑤ 验证与留痕：再看一遍指标确认回落；处理前先留一份现场（面试加分）
```

**反面例子**（不要这样答）：
> 「就 top 看一下，然后看看日志……」（没结构、没术语）

**正面例子**：
> 「我会先**分层定位**：`top` 看整体是哪类资源紧张 —— `wa` 高说明是磁盘 IO，`us` 高说明是应用在算；然后按 CPU 排序定位到具体进程，再用 `top -H -p` 看到线程；Java 应用用 `jstack` 看线程栈；最后按原因处理 —— 高峰扩容、代码问题回滚、异常进程清理，处理前后各留一份现场。」

## 六、复盘：为什么「答了」还被追问（原稿 08 / 18 的精华）

原稿里有两份「对照表 + 拷打点复盘」，核心结论就四句：

```text
① 只报名词、不解释本质   →  「b 是块设备」不够，要补「按块随机读写、可挂载、有内核缓冲，例如 /dev/sda」
② 步骤题漏关键字         →  新盘初始化漏说「分区」或「partprobe」，等于没做过
③ 只会一种工具、一种说法  →  每个命令准备「一个主用 + 一个替代 + 一个过滤条件」
④ 边界场景答不出         →  bash/source 都会，题目加个 exec 就懵了
```

**每个命令准备三件套**（原稿面经②第 5 题的教训）：

```bash
ss -lntp                     # 主用：谁在监听
netstat -lntp / lsof -i :80  # 替代：老写法 / 直接看是哪个进程占用
ss -tn '( dport = :80 )'     # 过滤：只看连到 80 的连接
```

**一句话记住 exec**：
> **「source 是借你的壳干活，bash 是另开一个壳干活，exec 是把你的壳直接换掉。」**
