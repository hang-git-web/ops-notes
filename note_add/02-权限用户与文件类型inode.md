# 02 权限、用户、文件类型与 inode

> **本章考什么**：你能不能看懂 `ls -l` 那一长串、能不能说清「谁能动这个文件」。
> **关键词**：rwx 对文件 vs 对目录、chmod 两种写法、SUID、wheel/sudo、7 种文件类型、inode、`df -i`、三个时间戳。
> **应届生范围**：会改权限、知道特殊权限的名字和例子、知道 inode 是什么。
> **不需要**：ACL、SELinux 上下文细节（在 `11`）。

## 一、`ls -l` 那一行长什么样（先看懂再说）

> **面试官会这么问**：这一行每个字段是什么意思？
> **考察点**：权限位 · 链接计数 · 属主属组

```text
-rw-r--r--  1 root root  1234 Aug 26 10:00 a.txt
 │└┬┘└┬┘└┬┘  │  │    │
 │ │  │  │   │  │    └── 所属组（group）
 │ │  │  │   │  └─────── 文件所有者（user）
 │ │  │  │   └────────── 链接计数（硬链接数，见 Q6）
 │ │  │  └────────────── 其他人（others）
 │ │  └───────────────── 所属组权限
 │ └──────────────────── 所有者权限
 └────────────────────── 类型：- 文件、d 目录、l 链接、b 块设备、c 字符设备
```

## 二、权限：rwx 对文件和目录含义完全不同（★★★ 最高频）

### Q2 面试官：rwx 分别代表什么？对文件和目录一样吗？

> **考察点**：权限模型 · 目录权限的特殊性

| 权限 | 对**文件** | 对**目录** |
| --- | --- | --- |
| `r` | 读文件内容 | **列出目录里的文件名**（`ls`） |
| `w` | 改文件内容 | **在目录里创建 / 删除 / 改名文件** |
| `x` | 执行文件 | **进入目录**（`cd`） |

> **一句话**：**文件的 rwx 管「内容」，目录的 rwx 管「名单和进出」。**

**两个常考的推论**（能说出来就是加分）：

1. **能不能删一个文件，看的是「目录的 w 权限」，不是文件自己的权限**（删除是"从目录里移除一个名字"）。
2. **目录有 r 没 x**：能 `ls` 看到文件名，但 `cd` 不进去。

---

### Q3 面试官：chmod 怎么用？755、644、600 分别用在哪？

> **考察点**：权限设置 · 数字法 · 生产规范意识
> **来源**：面经①第 8 题（已会，但这题常被追问"为什么"）

```bash
# 字母法
chmod u+x a.sh          # 给所有者加执行权限
chmod o-r a.txt         # 去掉其他人的读权限
chmod a+r a.txt         # 所有人都能读

# 数字法（r=4 w=2 x=1，三位分别对应 所有者 / 组 / 其他人）
chmod 755 a.sh          # rwxr-xr-x  ← 目录、可执行脚本
chmod 644 a.txt         # rw-r--r--  ← 普通文件、配置文件
chmod 600 key.pem       # rw-------  ← 私钥、密码文件
chmod 777 a.txt         # 谁都能读写执行 ← 生产禁止
```

| 数字 | 权限 | 用在哪 |
| --- | --- | --- |
| **755** | rwxr-xr-x | 目录、脚本 |
| **644** | rw-r--r-- | 普通文件、配置 |
| 600 | rw------- | 私钥、口令文件 |
| 777 | rwxrwxrwx | 生产禁止（面试时主动说"生产不会用 777"是加分） |

**为什么是 4-2-1？**：`r`=4、`w`=2、`x`=1，三位相加就是 0~7，所以三组权限刚好用一个八进制数表示。

### Q4 面试官：chown、chgrp、umask 是干什么的？

> **考察点**：属主属组 · 默认权限

```bash
chown tom a.txt              # 改所有者
chown tom:dev a.txt          # 同时改所有者和组
chown -R www:www /data/www   # 递归改（部署网站后常用）
chgrp dev a.txt              # 只改所属组
```

**umask（新建文件的默认权限）**：

```text
新建文件/目录的权限 = 最大权限 − umask
· 目录最大 777，文件最大 666（文件默认不给 x）
· umask = 022 时：目录 777−022 = 755，文件 666−022 = 644
```

`umask` 查看当前值，`umask 027` 临时修改。

### Q5 面试官：SUID / SGID / Sticky 是什么？举个例子。

> **考察点**：特殊权限 · 有没有真的理解 passwd 这个例子

| 权限 | 一句话 | 例子 |
| --- | --- | --- |
| **SUID** | 执行时**临时获得文件所有者的权限** | `/usr/bin/passwd` —— 普通用户也能改自己的密码 |
| **SGID** | 执行时获得**组**权限；用在目录上则新建文件**继承目录的组** | 部门共享目录 |
| **Sticky** | 目录内的文件**只有属主能删** | `/tmp`（人人可写但不能删别人的，权限位是 `1777`） |

**必考的一个追问**：

> **Q：为什么普通用户执行 `passwd` 能改 `/etc/shadow`？**
> **A**：因为 `passwd` 带 **SUID** 权限，执行的那一瞬间**进程以 root 身份运行**，所以能写 shadow；改完立即恢复成普通用户。

## 三、用户与用户组

### Q6 面试官：怎么新建用户、怎么给他 sudo 权限？四个关键文件是什么？

> **考察点**：用户管理 · wheel/sudo 组 · 敏感文件位置

```bash
useradd -m -s /bin/bash tom      # 建用户（-m 建家目录）
passwd tom                        # 设置密码
usermod -aG dev tom               # 追加到 dev 组（★ 少写 -a 会覆盖原有组）
id tom                            # 查看用户的 UID/GID 和所属组
userdel -r tom                    # 删除用户（-r 连家目录一起删）
```

**sudo 与 wheel 组**：

```bash
usermod -aG wheel tom             # CentOS：加入 wheel 组后 tom 才能用 sudo
# Ubuntu 上加的是 sudo 组
```

**四个关键文件**：

| 文件 | 内容 |
| --- | --- |
| `/etc/passwd` | 用户信息（所有人可读） |
| `/etc/shadow` | **密码密文**（只有 root 能读） |
| `/etc/group` | 组信息 |
| `/etc/sudoers` | sudo 授权规则（改完用 `visudo` 校验，别直接 vim） |

> **加分**：最小权限的做法是 `visudo` 编辑 `/etc/sudoers.d/xxx`，**只放开需要的具体命令**，而不是给 `ALL=(ALL) NOPASSWD: ALL`。

## 四、inode 与文件类型

### Q7 面试官：inode 是什么？为什么硬链接不能跨文件系统？

> **考察点**：文件系统底层 · 硬链接题的根
> **来源**：面经①第 7 题追问 / 面经②第 3 题

**一句话**：

```text
inode（索引节点）= 文件的"元数据 + 数据块地址表"，不包含文件名。
存放：权限、属主/属组、大小、三个时间、指向数据块的指针、链接计数。

文件名和 inode 的关系：
   目录项（文件名） → inode 号 → 数据块
   所以"文件名"只是目录里的一条记录，删掉文件名不等于删掉 inode。
```

```bash
ls -li a.txt hard.txt soft.txt
#  1234567 -rw-r--r-- 2 root root ... a.txt      ← 链接计数 2
#  1234567 -rw-r--r-- 2 root root ... hard.txt   ← ★ inode 相同 = 硬链接
#  1234570 lrwxrwxrwx 1 root root ... soft.txt -> a.txt  ← inode 不同 = 软链接
stat a.txt        # 直接看 inode 号、链接计数、三个时间
```

**四个必记推论**：

| 推论 | 原因 |
| --- | --- |
| **硬链接的 inode 相同** | 它们是同一个文件的不同名字 |
| **删除一个硬链接，文件还在** | 只看**链接计数**减到 0 才真正释放数据 |
| **硬链接不能跨文件系统** | **inode 编号只在单个文件系统内唯一**，跨分区找不到对应 inode |
| **软链接可以跨分区、可以指向目录** | 它只存路径字符串，靠内核重新解析 |

**inode 用尽：空间没满却写不进（★ 高频故障）**：

```bash
df -h /            # 空间看起来还有
df -i /            # ★ inode 已经 100% → 创建新文件报 "No space left on device"
```

> **原因**：inode 数量在 `mkfs` 时就固定了（每个文件至少占一个 inode）。
> **场景**：`/var/spool/postfix` 堆积大量小邮件、session 文件、缓存小文件。
> **处理**：找出小文件多的目录清掉；长期方案是重建文件系统时调大 inode 数，或换 xfs（动态分配 inode）。

### Q8 面试官：怎么查看一个文件的类型？都有哪些类型？

> **考察点**：`file` 命令 · `ls -l` 首字符 · 块设备 vs 字符设备
> **来源**：面经②第 3 题 —— **原稿完全空白，这题被追问过两次**

> **完整答法（30 秒版）**：「两种方式：`file 文件名` 直接看类型，它**读文件头判断、不受扩展名影响**；或者 `ls -l` 看第一个字符 —— `-` 普通文件、`d` 目录、`l` 软链接、`b` 块设备、`c` 字符设备、`s` socket、`p` 命名管道。」

```bash
file /etc/passwd          # ASCII text
file /bin/ls              # ELF 64-bit LSB executable...
file -i 图片.png          # image/png（MIME 类型）
file -b /dev/sda          # block special（不显示文件名，脚本里好用）

ls -l /etc/passwd         # 看第一个字符
stat /etc/passwd          # 文件系统层面的详细信息（含 inode 号、三个时间）
```

**`ls -l` 第一个字符的 7 种类型（★ 背下来）**：

| 字符 | 类型 | 例子 | 说明 |
| --- | --- | --- | --- |
| `-` | **普通文件** | 文本、二进制、配置 | 最常见 |
| `d` | **目录** | `/etc` | 目录本质也是文件（存的是"名字 → inode"的映射） |
| `l` | **符号链接** | `ls -l` 里带 `->` | 软链接 |
| `b` | **块设备** | `/dev/sda`、`/dev/sdb1` | 按块随机读写，**可挂载** |
| `c` | **字符设备** | `/dev/tty`、`/dev/null` | 按字符流读写，**不可挂载** |
| `s` | **套接字 socket** | `/run/docker.sock` | 进程间通信的端点 |
| `p` | **命名管道 FIFO** | `mkfifo /tmp/pipe` | 管道文件 |

**为什么 `file` 不看扩展名**：

```text
Linux 不靠扩展名判断文件类型，靠的是文件内容（头部 magic number）和权限位。
所以把 a.jpg 改名成 a.txt，file 依然会说它是 JPEG 图片。
```

**小技巧**：`ls -lF` 会在名字后面加标记：目录 `/`、可执行 `*`、软链 `@`、socket `=`、FIFO `|` —— 一眼就能看出来。

## 五、文件系统与时间戳（顺带补，面试常混）

### Q9 面试官：常见文件系统有哪些？ext4 和 xfs 有什么区别？

> **考察点**：文件系统常识 · 扩容/缩容的前提

| 文件系统 | 特点 | 常见于 |
| --- | --- | --- |
| **ext4** | 稳定、经典，**可缩容** | CentOS 6/7、Ubuntu |
| **xfs** | 大文件、高并发强，**只能扩不能缩** | CentOS 7+ 默认、RHEL 系 |
| tmpfs | 内存里的文件系统，重启即失 | `/dev/shm`、`/run` |
| overlayfs | 分层联合挂载 | **Docker 镜像层** |
| nfs / cifs | 网络文件系统 | 共享存储 |

```bash
df -T              # 显示文件系统类型
mount | column -t  # 看当前挂载和类型
```

> **面试问到扩容就会带到这一条**：**XFS 只能扩、不能缩**（要缩容只能备份 → 重建 → 恢复）；ext4 可以缩，但必须先卸载。详见 `08-Q6`。

---

### Q10 面试官：mtime、ctime、atime 有什么区别？

> **考察点**：时间戳 · `find` 按时间找文件

| 时间 | 含义 | 什么时候变 |
| --- | --- | --- |
| **mtime** | 内容修改时间 | 改内容时（**最常用**） |
| **ctime** | 元数据变更时间（权限、属主、链接数） | `chmod` / `chown` 时 |
| **atime** | 访问时间 | 读文件时（现代系统常用 `relatime` 减少写入） |

```bash
find /var/log -name "*.log" -mtime +7      # 7 天前修改过的
find /data -size +100M -mtime -1           # 一天内、大于 100M 的文件
```

---

### Q11 面试官：`/dev/sda` 和 `/dev/sda1` 有什么区别？

> **考察点**：磁盘与分区的命名 · 扩盘题的基础

| 名字 | 含义 |
| --- | --- |
| `/dev/sda` / `/dev/sdb` | 第一块 / 第二块 SCSI/SATA 盘（虚拟机的虚拟盘也常这样命名） |
| `/dev/sda1`、`/dev/sdb1` | 磁盘上的**分区** |
| `/dev/vda` | KVM/QEMU 的 virtio 盘 |
| `/dev/nvme0n1`、`/dev/nvme0n1p1` | NVMe 盘及其分区 |
| `/dev/sr0` | 光驱 |

> **记住**：**盘是 `/dev/sdb`，分区是 `/dev/sdb1`**；`mkfs` 要作用在**分区**上，`fdisk -l` / `lsblk` 用来确认到底识别到了什么。
