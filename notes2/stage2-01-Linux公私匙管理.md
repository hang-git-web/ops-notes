# SSH 密钥对与免密登录

## 1. 密钥对概念

| 名词 | 比喻 | 存放位置 |
| --- | --- | --- |
| 公钥 | 相当于**锁** | 放到服务器上（可公开） |
| 私钥 | 相当于**钥匙** | 留在自己电脑上（必须保密） |

- 一把钥匙只能开配套的锁：**公钥和私钥必须配对**
- 公钥可以随便分发（锁多配几把没关系），私钥泄露 = 钥匙被人捡走，风险很大

## 2. 密钥对工作原理

```text
① 你本地生成一对钥匙（公钥 + 私钥）
② 把公钥（锁）安装到服务器的 ~/.ssh/authorized_keys
③ 登录时：客户端出示私钥"开锁"
④ 服务器用 authorized_keys 里的公钥验证私钥是否配对
⑤ 验证通过 → 免密登录成功
```

比喻：你把**锁（公钥）装在服务器的大门上**，钥匙（私钥）自己留着；每次进门，用钥匙开锁，不用再报密码。

## 3. 创建密钥对

在自己电脑（客户端）上执行：

```bash
ssh-keygen -t ed25519 -C "yuanhang"
# 或传统 RSA：ssh-keygen -t rsa -b 4096 -C "备注"
```

一路回车（可设置 passphrase，也可留空），生成在 `~/.ssh/` 下：

```text
~/.ssh/id_ed25519        # 私钥（钥匙，绝不给别人）
~/.ssh/id_ed25519.pub    # 公钥（锁，可以分发）
```

**私钥权限必须为 600：**

```bash
chmod 600 ~/.ssh/id_ed25519
```

## 4. 通过 ssh-copy-id 传公钥实现免密登录

```bash
ssh-copy-id -i ~/.ssh/id_ed25519.pub 用户名@服务器IP
```

示例：

```bash
ssh-copy-id -i ~/.ssh/id_ed25519.pub root@192.168.232.131    
```

- 首次会要求输入一次密码（用于把公钥装到服务器上）
- 装好后，以后 `ssh root@192.168.232.131` 直接登录，**不再问密码**
- 首次是一次性ssh加密通道传输公钥，以后才是公私钥认证，免密登录

没有 ssh-copy-id 时手动装：

```bash
cat ~/.ssh/id_ed25519.pub | ssh 用户名@服务器IP "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys"
```

## 5. 权限要求（最容易踩的坑）

| 文件/目录 | 必须权限 | 命令 |
| --- | --- | --- |
| `~/.ssh` 目录 | 700 | `chmod 700 ~/.ssh` |
| `authorized_keys` | 600 | `chmod 600 ~/.ssh/authorized_keys` |
| 私钥 `id_ed25519` | 600 | `chmod 600 ~/.ssh/id_ed25519` |

> 权限过宽会报 `Permissions too open`，SSH 会**拒绝使用密钥**。改完权限即可。

## 6. 验证

```bash
ssh 用户名@服务器IP           # 直接登录成功 = 免密生效
ssh -v 用户名@服务器IP        # 加 -v 看详细认证过程（排错用）
```

## 7. 常见问题排查

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| `Permissions too open` | 权限过宽 | 按第 5 节 chmod 修正 |
| 还是问密码 | 公钥没装对 | 重新 `ssh-copy-id`，检查 authorized_keys 内容 |
| 连接无响应 | 服务器 sshd 没开/防火墙 | `systemctl status sshd`、放行 22 端口 |
| 提示 No such file | 私钥路径不对 | 检查 `~/.ssh/` 下文件名，或 `-i` 指定路径 |

## 8. 一句话总结

**公钥是锁、私钥是钥匙**：锁装服务器，钥匙留本地；`ssh-keygen` 造锁配钥匙，`ssh-copy-id` 把锁装上，权限 700/600 别越界，从此免密登录。
