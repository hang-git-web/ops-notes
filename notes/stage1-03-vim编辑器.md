# 阶段一 第3课：vim 编辑器

## 1. 核心概念：三种模式（vim 难学但强大的根源）

| 模式 | 按键盘的效果 | 怎么进入 |
| --- | --- | --- |
| **普通模式**（Normal） | 按的是**命令**（删除、复制、移动光标） | 打开 vim 就在这里；任何时候按 `Esc` 回来 |
| **插入模式**（Insert） | 按的是**文字**（正常打字） | 按 `i` 进入 |
| **命令行模式**（Command） | 输入保存/退出等命令 | 在普通模式按 `:` |

**记忆钥匙**：`i` = insert（插入），进入打字；`Esc` = escape（逃跑），逃回普通模式。

## 2. 三种退出方式（救命命令）

| 命令 | 含义 | 什么时候用 |
| --- | --- | --- |
| `:wq` | 保存并退出 | 改完了，正常走 |
| `:q!` | 不保存强制退出 | 改坏了，不想要了 |
| `:q` | 直接退出 | 没改东西，想走 |
| `:w` | 只保存不退出 | 想边改边存 |

**心理建设**：卡住了先按 `Esc`，再 `:q!` 回车，永远能逃出来。

## 3. 常用操作：10 个日常按键

| 操作 | 按键 | 说明 |
| --- | --- | --- |
| 进入插入模式 | `i` | 在光标前开始打字 |
| 回到普通模式 | `Esc` | 万能逃回键 |
| 保存 | `:w` 回车 | write |
| 保存退出 | `:wq` 回车 | write + quit |
| 强制退出不保存 | `:q!` 回车 | quit 不保存 |
| 删除当前行 | `dd` | delete line |
| 撤销 | `u` | undo，后悔药 |
| 搜索 | `/关键词` + 回车，`n` 下一个 | 配合第 2 课 grep 思路 |
| 跳到文件头/尾 | `gg` / `G` | 文件很大时定位 |
| 查看当前在哪 | 普通模式 `Ctrl+G` | 显示行号信息 |

**理解记忆**：这些字母全是英文缩写——`i`nsert、`w`rite、`q`uit、`d`elete、`u`ndo、`g`o。理解了缩写，比死记快十倍。

**注意**：删除、撤销、移动光标这类操作，都要在**普通模式**下进行——先按 `Esc` 确认回到普通模式，再按 `dd`/`u`/方向键。

## 4. 实战：给 nginx.conf 写入第一份配置

1. 打开配置文件：`vim ~/projects/demo/conf/nginx.conf`
2. 按 `i` 进入插入模式，输入内容：

```
server {
    listen 80;
    server_name demo.example.com;
    root /var/www/demo;
}
```

3. 按 `Esc` → 输入 `:wq` 回车，保存退出
4. 验证：`cat ~/projects/demo/conf/nginx.conf` → 看到 5 行内容 = 第一次服务器端文件编辑成功
5. 三遍肌肉记忆：
    - 打开文件，`/` 搜 `server_name`，`n` 跳下一个，`:q!` 退出
    - 光标移到 `listen` 行按 `dd` 删除，按 `u` 撤销，`:wq` 保存
    - 故意乱按体验“卡住”，`Esc` + `:q!` 逃出

## 5. 踩坑记录

**tail -f 没跟到日志**（第 2 课与第 3 课衔接时）：

- 现象：`tail -f /var/log/dpkg.log` 等了半天没有新内容
- 原因：`sudo apt install -y vim` 显示 “vim is already the newest version”，vim 早就装好了，apt **没有安装任何东西**，dpkg.log 自然没有新记录
- 结论：tail -f 工作正常，是“没有新日志可跟”——前提条件（安装会产生新日志）不成立
- 教训：排障第一原则，先确认“前提条件成立”，再怀疑命令坏了

## 6. 复盘

- vim 三模式的核心是“先想清楚我要打字还是要发命令”，i/Esc 两个键来回切
- 以后改任何配置文件（Nginx、MySQL、网络配置）都用 vim
