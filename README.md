# ops-notes · Linux 运维学习笔记

> 从 Linux 零基础，到能独立部署服务、排查故障、做监控告警的完整记录。
> **五个阶段**的系统笔记 + 每个阶段对应的**真实操作与排错截图** + 沉淀下来的**脚本**。

---

## 一、这是什么

一份按**学习阶段**组织的运维知识库。不是零散的资料收集，而是"学完一个主题 → 动手做一遍 → 截图留痕 → 复盘写清单"的闭环记录。

仓库由四块内容组成：

| 目录 | 定位 | 说明 |
| --- | --- | --- |
| `notes1` ~ `notes5` | **笔记区** | 五个阶段的系统笔记，按 `stageN-XX-主题.md` 命名 |
| `images1` ~ `images5` | **实操留痕** | 每个阶段真实操作与排错的截图，与笔记目录**一一对应** |
| `scripts` | **脚本沉淀** | 独立的脚本文件（大多数脚本直接内嵌在对应笔记里） |
| `notes` + `images` | **散乱学习区** | 阶段零环境复盘、Shell 案例、专题对比等，暂不纳入阶段主线 |

## 三、学习路线

五个阶段层层递进，每一阶段都建立在前一阶段的能力之上：

```text
阶段一  Linux 基础与系统管理
        │  会用系统、看得懂系统：文件、用户、进程、网络、磁盘、日志、计划任务
        ▼
阶段二  自动化与容器
        │  从"手工一台台做"到"批量、标准化交付"：SSH 免密、LVM、Ansible、Docker、K8s
        ▼
阶段三  数据库与缓存
        │  数据怎么存、怎么备、怎么不丢：MySQL 安装与备份、主从、Redis 高可用
        ▼
阶段四  Web 服务与站点运维
        │  业务怎么跑起来、出问题怎么查：Nginx、Tomcat、HTTPS、LNMP、故障排查方法论
        ▼
阶段五  企业级监控
           怎么第一时间发现故障：Zabbix 全流程实战、Prometheus + Grafana
```

## 五、单篇笔记的结构

每篇笔记尽量保持同一套骨架，便于复习和快速定位：

```text
知识点    → 这个概念是什么、为什么需要它
实操      → 每一步的命令与配置（可直接照着复现）
检验      → 每步做完怎么确认成功
闭环自检  → 一张清单，逐项打勾才算完成
常见问题  → 实际踩过的坑与排错思路
复盘      → 这一节学完的理解与疑问
```

**图片引用约定**：笔记里统一用相对路径，例如

```markdown
![ip addr 输出](../images1/3.png)
```

即 `notesN/xxx.md` 引用 `imagesN/N.png`，保证在 GitHub 网页端和本地编辑器里都能正常显示。

## 九、使用说明

- **按阶段顺序读**：阶段一没打牢，后面排障会很吃力。
- **笔记不是读一遍就完**：每篇末尾的「闭环自检清单」建议逐项动手验证过。
- **截图要连报错一起留**：`imagesN/` 里存的多数是真实报错现场，回看时比结论更有价值。
- **可以只取其中一部分**：比如只准备面试，可以重点看阶段三（备份/主从）、阶段四（故障排查案例）、阶段五（监控告警链路）。

## 十、安全提醒

- 笔记里的密码、授权码目前都是**示例占位符**（如 `Mysql@123`、`StrongPass!2026`），请保持这个习惯，**不要把自己真实环境的密码、SMTP 授权码、密钥贴进仓库**。
- 实验环境里常见的"关防火墙、开 `bind 0.0.0.0`、`protected-mode no`"是为了方便演示，**生产环境必须按最小暴露原则放行端口**。
- 内网 IP 建议统一使用示例网段（如 `192.168.x.x`），避免把自己环境的网络结构公开。
